# FreeRTOS：显式静态内核适配

本目录将锁定的官方 FreeRTOS 内核及精确 CPU 端口连接到 Nexus 等待、任务、队列
和通知合同。普通调用使用 `os/include/nexus/os/` 的公共头，装配通过
`nexus/os/storage.h` 定义本后端精确布局。`freertos.h` 只保留直接通知槽、IRQ
检查等明确扩展。普通实现为 `freertos.c`，`task_runtime.c` 维护显式引导与延时；
`CMakeLists.txt` 选择内核和端口，`lowpower.c` 处理可选无节拍
空闲，`hooks.c` 提供保留资源责任的故障停机路径。

## 构建与资源

CPU 事实决定真实 M0／M3／M4F／M7／v8-M 端口及 FP／MVE／安全态 ABI，不能统一
套用 CM4F。普通配置启用静态分配，关闭动态分配和软件定时器后台任务，不链接
`heap_*.c`。调用者提供任务控制对象、栈、队列有效数据和明确容量。普通配置的
Idle 可以使用内核提供的静态存储；MPU／分域安全配置要求应用提供对应 Idle
TCB／栈。默认不创建产品工作线程。
所有控制对象首次清零，栈容量以 B 传入，后端校验真实 word 换算、初始帧和对齐。
公共对象大小随后端和配置变化，不保留最大 union 或固定 TCB 字节池。单个可执行
文件只链接一个共同接口实现，普通业务头不包含原生内核类型。

`nx_platform_start()` 不启动调度器。应用在合法冷态中显式进入真实内核，
负责任务拓扑、执行进度、公平性和停机。普通运行 API 要求特权线程模式，且
PRIMASK、BASEPRI、FAULTMASK 清零；启动前规范屏蔽状态是独立例外，详见
[OS 总览](../README.md)。内核 ISR 唤醒还核对真实异常范围、优先级分组和系统
调用上限。
通过公共 `nx_os_run` 调用应用 bootstrap 后启动真实 scheduler，成功不返回；任务
在允许阶段可能先于 start 返回执行。逻辑优先级高数值更高，不改变实际可用等级。

## 请求与任务退出

通知只提示重查判定条件。可返回任务发布完成后挂起，唯一外部退出会合者完成
真实删除，再回收控制对象、栈和上下文。退出等待超时保留存储，不得凭完成提示
提前复用。永久任务和直接通知是独立可选路径；只有不需要退出等待的任务才能
选择相应较小控制对象。
公共 `nx_task_join_until` 成功前不能回收；自 join 返回 `CONTEXT`。`nx_os_now_us`
使用 Core 单调时钟，有限 `sleep_until` 保持同一绝对预算，`yield` 不承诺公平。

普通 queue 没有关闭广播。可关闭 channel 另带调用者控制对象和每操作独占等待者，
检查最大并发操作数。关闭后拒绝新发送，允许旧数据
排空。关闭准入后继续推进服务，结清请求，等待生产者和资源责任者退出，撤销
全部 IRQ 发布者，最后销毁通知、队列及保护区。复制队列成本随单项大小增长，
关闭广播随等待者数增长。
完整 payload 容量必须足够、与控制对象不重叠且不回绕，不能仅检查有效 item 字节。
deadline 零表示 try，关闭后的发送和排空后的接收返回 `CANCELLED`。运行内核继续
保留 clock／Tick；对象销毁不隐式停止 scheduler。

## 可选配置与证据

[MPU](mpu/README.md)和 [Secure companion](secure/README.md)是显式独立配置，
不会使普通 I/O 自动可从非特权或另一安全域调用。无节拍空闲必须绑定完整定时器
端口及连续时钟，不代表任意 SoC 已具备深睡眠接入。

[FIG-08：等待、唤醒与退出](../../docs/assets/diagrams/wait-wake-shutdown.svg)
说明公共流程，[OS 总览](../README.md)列出精确 CPU／后端差异，
[OS 交付](../../docs/reference/contracts/os/execution.md)保留实际执行范围。真实宿主内核、寄存器模型
和 ARM 链接各自建立不同证据；FP／MVE 切换、栈峰值、IRQ 延迟和睡眠时序仍须
实板 HIL。
本分支公共接口的实现不自动建立最终软件候选或硬件资格，实际命令与报告分别验收。
