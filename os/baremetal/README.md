# 裸机等待适配

本目录为没有调度器的工程提供 `nx_baremetal_notify_t`。它只保存通知序列、
调用者提供的单调时钟函数和上下文；公开声明在
`../include/nexus/os/baremetal.h`，生产实现为 `notify.c`。

## 架构和执行责任

应用主循环是执行者：推进设备或资源责任者的服务，再检查请求完成判定条件。
`nx_wait_port_t` 连接公共等待流程，不创建任务、队列、隐藏循环或隐式 WFI。
通知序列以 release 内存序进行原子更新，等待方以 acquire 观察变化；唤醒只提示
重新检查权威判定条件，不代表请求已经 SETTLED。

等待函数检查原始绝对截止时间和序列，返回成功、超时或 BUSY。BUSY 表示应用
应继续调度，不能在只读判定条件中偷偷推进共享硬件。若工程需要浅睡眠，应显式
选择 Arch／SoC 的合法睡眠端口，并负责定时唤醒和时间域连续性。

## 存储和退出

通知对象、时钟上下文和等待接口存储由调用者持有，须活到全部发布者和等待者
退出。关闭新准入后仍保持推进服务和排空；只有全部借用结清、IRQ 发布源撤销且
相关使用者退出后，才回收通知及依赖。超时不解除请求或缓冲区借用。
