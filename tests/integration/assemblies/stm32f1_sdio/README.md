# STM32F103ZE SD 卡软件参考

STM32F103ZET6 使用 HSI8、轮询和 SD v2 高容量卡。单线接线为 PC8 D0、
PC12 CK、PD2 CMD 和 PC13 低有效卡检测。软件参考假定独立 3.3 V 供电、
CMD／DAT 外部上拉和已消抖的卡检测。实际 PCB、电气和卡兼容性待实板验证。

Platform 启动取得引脚。调用者通过 typed factory 获得端口后用 `activate` 识别
卡片。读取一次最多一个 512 字节扇区。引脚和主机在 `stop` 确认撤回后释放。
板级所有者确认拔卡后通过 `media_removed` 报告，再停止和重新识别。

`ze-1bit.toml` 默认只读。`ze-1bit-write.toml` 显式选择 `sdio-poll-write`，
仅在卡片 CSD 声明支持 512 字节写入、容量属于 SDHC 且未写保护时开放单扇区
`CMD24`。确认进度要求正向数据 CRC 状态和卡片以 `CMD13` 回到传输就绪状态。
失败时当前扇区可能已改变，调用方通过同步或停止确认当前状态。主机时钟固定在
约 364 kHz，符合 ES0340 Rev17 §2.13.6 的单线发送约束。固件示例只提交越界
写请求验证拦截，然后读取第一扇区。成功写路径由 Native 模型验证，实卡写入待测。

`ze-4bit.toml` 选择独立的软件参考插座和 `sdio-poll-4bit`。在单线接线上追加
PC9 D1、PC10 D2 和 PC11 D3，CMD 和 DAT0–3 均外部上拉。该装配只读 SDHC，
每次读取一个 512 字节扇区，仍使用约 364 kHz 的内核分频。四条并行数据线提高
每个时钟周期携带的位数，实际吞吐量取决于卡片和板级电气条件。

识别在单线完成。卡片选中并处于传输就绪后，驱动确认 `CMD55` 的 APP_CMD，
发出 `ACMD6(2)`，随后切换主机 WIDBUS 并回读。双方确认前 API 不公布几何。
发生不确定响应时，`stop` 在卡仍在位的情况下重试 `ACMD6(0)`、恢复主机单线，
再取消选卡。卡检测确认拔出后可只撤回主机。PC9／PC10 的输出互斥、
关闭硬件流控和选择正向时钟仍遵守 ES0340，保留 CMD17 的计数和数据 CRC 检查。

依据为 DS5792 Rev13 表 5、RM0008 Rev21 §22.4.9／§22.9.2 和
[SD Physical Layer Simplified Specification v9.10](https://www.sdcard.org/downloads/pls/)
§4.3.1／§5.3.3／表 5-21。规范要求 SD 存储卡同时提供 1 位与 4 位模式。

`ze-4bit-write.toml` 显式启用四线 SDHC 的单扇区 `CMD24`，适用于没有机械写保护
开关的外接 microSD 插座。卡片 CSD 必须允许 512 字节写入且未写保护。8 MHz
的 APB2 和 SDIOCLK 加上除以 22 的时钟配置，使 ES0340 §2.13.6 的六个父时钟周期
为 0.75 μs，四线传输一个 32 位字需 22 μs。驱动关闭硬件流控，必须收到完整传输
和正向 CRC 证据，并等到卡片以 `CMD13` 确认传输就绪，才确认一个扇区。
失败返回零个已确认扇区，当前扇区内容可能已改变，由调用方核对。
停止先撤回传输，再等待卡片就绪、切回单线并取消选卡。集成固件使用越界写请求
验证拦截，正常写入、欠载及超时由主机模型验证。实卡写入待硬件验证。

`ze-4bit-rx-dma.toml` 使用四线 SDHC，只读取单个 512 字节扇区。RM0008 表 79 将
SDIO 固定到 DMA2 通道 4。本装配轮询 DMA 和 SDIO 状态，通道的中断使能位保持清零，
与通道 5 共享的向量保持原状。仅清本通道各自的完成／错误标志，遵守 ES0340 §2.4.1。

DMA 写入 512 字节驱动私有缓冲。全扇区计数、DMA 完成、SDIO 块 CRC、通道撤回及
卡片就绪均确认后，CPU 才复制给调用者。超时或错误时调用者可立即复用缓冲区；
若通道无法撤回，驱动保留私有缓冲和硬件所有权，`stop` 可重试。写入仍使用独立
PIO 装配。接线、电气和 DMA 时序待实板验证。
