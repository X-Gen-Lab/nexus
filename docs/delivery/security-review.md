# 安全扫描与生命周期边界

静态扫描分析当前工具、F4 生产实现和实际 host 构建；扫描执行与诊断审查分别记录。
历史扫描结果不能代替本次源码执行。配置、证据与打包代码仍在检查范围，不能通过
移除所有权或路径检查消除诊断。

## 必须审查的合同

| 地址保存位置 | 必要退出条件 |
| --- | --- |
| F4 IRQ／callback 状态 | 正常 stop 解绑真实发布者；失败保留责任 |
| request 与 buffer | provider 最后访问后 release-publish SETTLED，调用者 acquire-observe |
| task 的 stack／TCB／context | 外部成功 join 后才可复用，不能由当前任务销毁自己 |
| owner slot | executor 结清、slot detach、发布者和观察者均退出 |
| 已启独立 watchdog | 作用不可逆，静态 owner 持续到复位 |

异步借用保存调用者地址是必要机制。诊断必须核对真实寿命，不能换成隐式 heap、删除
IRQ 表或屏障以绕过。失败的 Flash relock、DMA drain 和硬件撤回必须保留隔离与恢复
责任，后到成功观察不自动清除锁存故障。模型验证软件合同，不能证明实际电气与复位。

工具临时目录、进程组、路径身份与失败退出必须有真实回归。厂商导入保留原字节和许可；
未选 vendor 不建立生产支持。普通静态扫描不证明无漏洞，也不替代 IRQ、掉电、时序、
长期负载或产品安全资格。当前物理 HIL 为 `not_executed`；候选由同一源码的实际门禁建立。
