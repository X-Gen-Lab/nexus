# Nexus 架构决策记录

以下决策指导工业控制与设备联网首期建设。状态为“采用”的方向可以用于本地增量开发；状态为“待收敛”的事项依赖参考板、测量或产品要求。所有条目描述目标与迁移，不表示相应功能已实现。

## ADR 001 增量维护 C 接口

状态：采用。

保留 C11 公共 API、能力接口、工厂入口和 Native 测试资产。先统一错误、生命周期、资源所有权和执行上下文，再拆分实现。公共结构体变更必须评估源码及 ABI 影响；若应用静态链接，也必须明确配置和编译器导致的布局变化。新模块优先使用不透明句柄与版本化参数，已有接口通过薄适配层迁移并声明弃用窗口。

选择增量迁移的原因是现有驱动和测试可继续验证每次变更，能较早交付一个板卡闭环。整体重写或全面换语言会同时扩大适配、验证和团队学习成本。Rust 可用于独立边界清晰的服务实验，暂不作为修复现有接口问题的前提。

## ADR 002 分离架构 SoC 板卡与产品

状态：采用。

通用能力契约位于 HAL/OSAL；架构端口负责临界区、原子、屏障、cache 和时间源；SoC 驱动负责控制器及厂商 SDK；板卡负责时钟、引脚、外设连接和存储分区；产品负责控制策略、功能选择和业务安全状态。通用层不得包含厂商头文件，产品不得绕过接口依赖寄存器。

迁移首先提取临界区端口和 board 描述，保持旧 `platforms/stm32` 入口可用；随后逐个驱动搬迁。目录变化必须伴随依赖检查和相同契约测试，不能只移动文件。

## ADR 003 配置作为每个构建的输入

状态：采用，首批仅修复 preset 选择，完整生成链路待实施。

产品 profile、板卡默认值和用户 overlay 合成一份有效配置，输出到独立构建目录；头文件、CMake 变量、链接分区和能力清单都从同一有效配置派生。preset 选择工具链和 profile，不能再被源码目录中的个人 `.config` 静默覆盖。非法符号、矛盾选项和生成失败应阻断，不能继续使用旧头文件或回退默认值并声称成功。

每个构建保存有效配置 hash，重配时清理失效缓存。宿主与目标可以并行构建；同一配置应在干净目录和重配目录产生一致结果。保留用户显式 `NEXUS_CONFIG_FILE` 作为过渡入口，但需要验证它与目标和工具链一致。

## ADR 004 先定义实时接口契约

状态：采用。

每个 API 明确任务或 ISR 上下文、是否阻塞、timeout 起点、缓冲区所有权、取消行为、回调上下文以及失败后的状态。有限超时应覆盖锁等待和设备操作；DMA 超时返回前必须停止 DMA，或者通过显式异步所有权继续持有缓冲区。完成、错误、取消竞态只交付一次终态。

Native 验证同一语义，真实板验证中断优先级、DMA/cache、总线和调度。临界区不应由编译器名字猜测 CPU；OSAL 端口必须定义嵌套、SMP 与 ISR 行为。控制路径需要静态分配或有界池，其他服务可按 profile 选择堆。

## ADR 005 模块化工业设备服务

状态：采用。

以参考产品需要的采集控制、参数、诊断和工业通信建立最小闭环；协议、网络、TLS、OTA、文件系统和 TinyML 均按需启用。驱动与服务以稳定端口相连，避免 HAL 直接依赖网络或云 SDK。控制域与管理域分离优先级、队列、内存预算和故障处理，是否需要 MPU 或双核隔离由风险和硬件能力决定。

Modbus、CANopen、MQTT、TLS、bootloader 等优先评估维护良好、许可证适用的组件，经过适配和验证后纳入依赖清单；不自行实现密码原语。选型需记录资源成本、版本维护、可移植性与安全更新路径。

## ADR 006 发布来自同一组已验证产物

状态：采用，首批形成候选发布保护。

构建、测试和打包成功后才能创建候选 Release；正式发布复用该工件，不再次构建产生不同镜像。工件身份包含 source、board/product、有效配置、toolchain 和第三方依赖，摘要与报告随工件存储。签名服务与普通构建隔离。

首批候选仅有主机构建测试、配置和工件摘要，不代表 HIL、SBOM、签名或 LTS 完成。正式企业发布仍需明确的产品门禁。空测试、空包、配置与 Release 构建类型不匹配均应拒绝。

## ADR 007 持久化与升级先保证可恢复

状态：采用；具体 Flash 格式、bootloader 与密码库待收敛。

配置记录、schema 迁移、密钥迁移和升级状态均以断电可恢复为前提。先定义存储 program/erase 粒度和坏页行为，再设计日志记录、提交标记与回收；Flash 模拟模型用于故障注入，实际板断电测试用于验证模型。不能用 RAM 后端代替掉电证明。

OTA 的空间、回退与防降级策略同时设计；新镜像的健康确认与安全计数推进必须保留合法恢复路径。MCUboot 是候选而非已选实现；必须依据分区容量、硬件保护和更新方式决定。AEAD 的 nonce 生命周期和设备身份必须有实际熵源、key id 与失败传播。

## 需要产品信息收敛的决策

团队输入已确定为约 10 人、3–6 个月。首发板与芯片容量、控制周期和允许抖动、RS485/CAN/Ethernet 优先级、断电保持策略、OTA 空间、量产身份注入方式、外部 Flash/Secure Element、支持年限以及成员技能与 HIL 预算仍待实际产品定义。相关任务可先定义接口与测试模型；硬件依赖实现和正式支持承诺应在这些输入确定后冻结。
