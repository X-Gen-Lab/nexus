# Nexus 首批维护迭代记录

本批维护以 `7a203266082ad1f655b6686713b2b7950ba31ec6` 为源码基线。用户确定工业控制与设备联网、约 10 人、STM32/GD32 和 3–6 个月周期。工作结果包含可持续维护的架构与企业流程方案，以及范围有限的本地候选补丁。没有推送远端、修改仓库设置或创建实际 Release。

## 分析和规划交付

形成目标架构、企业研发工作流、质量安全、实施路线、架构决策、支持矩阵和 38 项依赖明确的 backlog。补充 `AGENTS.md` 作为后续维护约束，强调接口契约、有效配置、验证证据和工业资源边界。具体型号与板卡、控制预算及 HIL 仪器仍需在第一个迭代收敛。

主要证据包括工作流结果与源码契约：Native 配置被 STM32 覆盖、预设引用漂移、平台 CMake 模块/函数漂移、SPI 的 OSAL/生命周期接口与 DMA 超时风险、配置加密和持久化缺口、发布顺序和扫描门禁不足。静态风险与实际运行结果分别记录，不把接口存在或工作流配置当作成功验证。

## 本地代码和文档修复

| 范围 | 改变 | 目的 |
|---|---|---|
| `CMakePresets.json` | Native 显式选择 Native defconfig；STM32 显式配置入口；多重继承将目标放在宿主默认值前 | 消除已识别的目标选择冲突；完整有效配置统一仍是后续任务 |
| `build-matrix.yml` | ARM 引用真实 preset；sanitizer 显式选择 Native defconfig；主机、coverage 和 sanitizer 拒绝零测试 | 不让配置或测试遗漏形成假成功 |
| `ci.yml` 和 CI helper | 补齐触发路径；手动全门禁；聚合 changes/build/quality/docs；执行辅助套件 | 拒绝失败、取消、缺失与异常跳过；合法跳过按事件和变更判断 |
| `release.yml` 和 package helper | 校验 tag/source，构建和测试后打包，校验完整矩阵后创建 draft；附实际配置和摘要 | 阻断空包、身份漂移、错误配置、缺失/漂移子模块及未提交源码变动 |
| `README.md` 与 `README_CN.md` | 更正仓库/preset/GPIO 示例，说明当前支持与测试证据，链接维护方案 | 让入门内容对应当前 API，降低错误支持承诺 |

发布辅助逻辑的细节见 [发布迭代记录](first-iteration-release.md)。辅助套件使用临时 Git 仓库、文件和二进制格式夹具；它们检验门禁和打包规则，不代表 Nexus 固件已编译通过。最终执行数量与静态检查结果保存在交付包的 `verification.json`。

## 已执行验证

- 解析预设并核对继承与矩阵引用；27 个具体预设选择正确的配置入口，8 个构建矩阵引用存在。
- 执行 CI 与 release 的 Python 单元套件，覆盖事件真值表、错误状态、CLI、Git 标签/commit、空包、配置、路径安全、子模块和摘要篡改；独立复核发现的身份校验缺口在本批补充修复并回归。
- 从双语 README 提取 GPIO 代码，用 GCC 14.2 执行 C11 语法及当前头文件 API 检查，通过；没有完成链接或运行验证。
- 对原始 `nx_mutex.c` 作单文件编译对照：默认线程安全关闭可编译；通过 `-DNX_CONFIG_HAL_THREAD_SAFE=1` 启用后，x86 GCC 报告不支持 `mrs primask/cpsid/msr primask`。该缺陷未在本批驱动代码中修复。
- 校验 backlog 的唯一 ID、引用及无循环依赖，支持矩阵引用与文档结构；原始文本快照用 Git blob SHA 校验。

## 下一批必须关闭的阻塞

`BAS-002/003/004`：头文件仍生成到源码目录，Kconfig 与 preset 的构建类型/工具链可冲突；未设置项与旧缓存处理、生成失败回退需要修复；平台仍有缺失模块和旧函数引用。完整构建生成链路必须在安装 CMake 的环境和真实 checkout 中验证。

`HAL-002/003/004/005`：临界区架构端口、SPI 接口编译与设备隔离、DMA 停止/取消/错误传播和缓冲所有权。先恢复契约和编译，再使用真实板测试 IRQ、超时及取消竞态。

`CFG-001/002` 和 `SEC-001`：真实持久化、未完成轮换的明确失败、可恢复格式、熵源和认证加密。不能把 RAM 模拟或确定性 PRNG 用作企业安全与掉电保障。

首批候选发布采用严格拒绝策略；当前生成已跟踪头文件会被 dirty-source 检查拒绝，ARM `.config` 的 Debug/armclang 冲突也会阻止候选。它保护错误交付，但不表示完整发布链路已恢复。扫描工具内部仍有允许失败的步骤，聚合 job 成功不等于每项静态分析已达标。

## 工作区和交付边界

本地网络代理不可连接，源码通过 GitHub connector 按固定提交取得。工作区包含 708 个源码、构建、测试和关键文档文件的文本快照，以及本批新增文件；不是完整 Git checkout，厂商/RTOS/GoogleTest 子模块未初始化，部分既有文档未下载。快照范围见根目录 `.nexus-source-snapshot.json`。

环境有 Python、GCC 和 Git，没有 CMake、kconfiglib 和 ARM 工具链，因此本批没有执行完整 Native/ARM/FreeRTOS 构建、CTest、GitHub Actions 或 HIL。正式采用补丁前应在固定基线的完整仓库执行对应验证，不应把本批 Python 测试报告当作全部固件验证。

交付包包含候选补丁、修改文件、维护方案和验证记录。补丁可在干净基线使用 `git apply --check` 先检查，再由正常分支/PR 流程接入。仅创建本地方案与补丁，不自动发布网站、发送外部消息或改变远端权限。
