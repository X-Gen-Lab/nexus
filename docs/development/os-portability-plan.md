# OS 可移植接口交付与验收清单

本清单记录公共接口、后端和消费者迁移的交付内容及验收条件。接口范围与取舍见
[OS 现行架构](../explanation/os-portability.md)；本文保留 32 个稳定任务 ID、
优先级和依赖，不复制第二份 API 合同。

**状态：公共实现与阶段验收已交付，最终集成验收进行中。** OSU-22／23 根据
实际需求盘点明确不纳入本批；HIL 继续暂缓，保持 `not_executed`。
阶段结果不能提前关闭最终集成、ARM、资源和 SDK 验收。当前调用要求与生命周期以
[OS 执行合同](../reference/contracts/os/execution.md)为准。
软件实施覆盖 FreeRTOS、ThreadX、Native 的已维护范围，裸机保留非阻塞能力。
不因此新增 CPU、SoC、Board、安全配置或实板资格。

本轮开发阶段已有 32 项新公共接口测试、18 个保留的旧 GoogleTest／CTest 模块和
9 项外部示例检查通过。它们分别验证三后端实际生产 C、既有故障合同和示例消费，
不是最终完整集成或所有硬件配置的通过声明；最终关闭需匹配相关源码、配置及报告。

## 范围、复用与完成口径

| 已有机制 | 本轮处理 | 保留的边界 |
| --- | --- | --- |
| 公共 wait、单等待者通知和绝对 deadline | 复用生产 C 与合同，补统一类型入口 | wake 是提示，真实 predicate 才决定完成 |
| 三后端任务和外部 join | 迁入统一源码接口，复用已有退出算法 | 成功 join 才能回收任务存储 |
| 静态队列与可关闭队列 | 保留不同成本档位，统一选定语义 | 不让普通队列默认承担广播和 waiter 成本 |
| CPU port、ISR 准入与掩码保护 | 沿用精确端口和上下文检查 | 不把主机通过推广成 MCU IRQ 资格 |
| TOML、typed IR、CMake 与 Source SDK | 保留硬件装配链，增加选定目标的软件能力校验 | 不引入第二份配置权威或源码图 |
| GoogleTest／GoogleMock、资源夹具和门禁 | 补缺失合同，按实现类别复用 | 不重建测试、台账或证据框架 |

静态存储使用所选后端的真实大小和对齐，不使用全部后端的最大联合体。
统一源码 API 不承诺统一二进制布局；切换后端需要重新编译、配置存储和评估调度。
不增加运行时后端选择、隐藏 worker、默认 timer daemon 或对象池。

优先级 P0 表示冻结后续工作依赖的合同或集成阻塞；P1 表示完成可移植消费链所需
实现；P2 表示由真实消费者决定的可选扩展。依赖栏中的编号均指本页稳定任务 ID。
任务在相关代码、测试、文档及验证一起满足退出条件后才能关闭，不能仅以提交数
或新增接口数量判定完成。

## WP1：冻结合同与真实消费者

合同与真实消费路径已经落入公共头和维护夹具。下面保留各项退出条件，后续改动
继续从具体消费者出发，不为凑齐原生 API 名称增加没有使用者的功能。

| 任务 | 优先级／依赖 | 改动与产物 | 退出条件 |
| --- | --- | --- | --- |
| OSU-01 | P0／无 | 盘点 OS 头、组件及外部示例调用，区分业务、装配与原生扩展 | 每个现有公开后端入口有保留、内部化或删除决定，无悬空消费者 |
| OSU-02 | P0／01 | 冻结单位、错误、Task／IRQ、优先级、join、关闭和存储合同 | 三后端语义差异逐项有实现策略或显式拒绝，不以同名函数代替语义 |
| OSU-03 | P0／02 | 选定已有 owner 及生产者／消费者流程，记录等价原生基线 | 同一业务源码覆盖正常、超时、关闭和退出；输入、负载和容量固定 |
| OSU-04 | P0／02、03 | 为首个统一接口增加 C 头编译及实际行为 RED，记录实施交接 | RED 确因待实现合同失败；并行实现者收到原始命令和源码快照后开始 |

合同冻结同时列出不纳入项：强制杀任务、通用 scheduler shutdown、运行时换内核、
透明裸机阻塞线程和未维护的 MPU／TrustZone 组合。后续新增需求先说明消费者，
再修改现行架构和对应合同。

## WP2：类型、静态存储与构建选择

本包把后端布局限制在装配及私有实现。普通业务只接收公共类型，不包含内核头，
不根据后端设置预处理分支。

| 任务 | 优先级／依赖 | 改动与产物 | 退出条件 |
| --- | --- | --- | --- |
| OSU-05 | P0／02 | 定义公共对象引用、初始化参数及选定后端存储声明边界 | 公共业务头可单独按 C11 编译，未泄露 TCB、原生 handle 或 tick 类型 |
| OSU-06 | P0／05 | 实现精确存储类型及容量、对齐、跨度和生命周期检查 | 不足、溢出、重叠及错误配置在产生效果前拒绝，无最大池和非法类型别名 |
| OSU-07 | P0／05、06 | 用现有 CMake 目标选定存储布局和后端，覆盖 Platform／Runtime | 一幅镜像只有一套任务实现，混合后端身份在生成时拒绝；未选内核不进入该镜像 |
| OSU-08 | P1／02、07 | 通过选定目标的能力元数据校验软件需求，保留裸机轻路径 | 缺能力在配置或编译期拒绝，helper 不隐式链接；新增同 CPU MCU 不需重写 OS 工具 |

不为对象尺寸另建独立清单或手写 magic number。生成连接与 C 类型定义共用现有
权威来源；配置器不实现内核行为。对象布局随后端变化时，消费者完整重编译。
独立 Host 夹具可以在同一构建图生成不同后端的可执行文件，每幅镜像分别校验身份。
公共 `storage.h` 不根据整仓 Native 配置误选 RTOS 夹具布局。

## WP3：任务、引导与真实退出

复用各后端已经存在的生命周期算法。统一的是任务入口与成功退出后的资源保证，
不要求三个内核具有相同的创建时机。

| 任务 | 优先级／依赖 | 改动与产物 | 退出条件 |
| --- | --- | --- | --- |
| OSU-09 | P1／04、06、07 | 接入可返回任务与永久任务，保留静态 TCB、栈、唯一 lifecycle owner | 返回、创建失败、自 join 和真实删除路径正确；永久任务不承担完成对象成本 |
| OSU-10 | P1／02、09 | 提供统一产品引导入口，封装 FreeRTOS／ThreadX／Native 创建阶段 | 回调范围、可调用操作、首任务执行时机及失败责任明确；Platform 不启动 scheduler |
| OSU-11 | P1／09、10 | 完成 Native 有限 deadline join，保留真实 pthread 会合 | 超时不 detach、不取消、不释放存储；成功确认无内核引用，不用无界 join 冒充有限等待 |
| OSU-12 | P1／02、08、10 | 映射公共逻辑优先级，定义 host 执行及调度能力边界 | MCU 顺序映射无反转；Native 无 RT 能力时明确拒绝硬保证，不静默钳位 |

ThreadX 的引导回调、FreeRTOS 启动前对象创建和 Native 线程立即执行需要在适配器
内部协调。实际内核启动只能由外部工程显式调用，入口返回不能被当成可回收证明。
不增加统一的强制终止接口来掩盖合作式停止依赖。

## WP4：通知、等待与发布者撤回

本包保持现有 ready／arm／ready／wait 协议，消除消费方显式选择内核通知对象的
需要。单端口仍只有一个等待者。

| 任务 | 优先级／依赖 | 改动与产物 | 退出条件 |
| --- | --- | --- | --- |
| OSU-13 | P1／02、05；运行接入另依赖 07、09、10 | 统一 wait／select 及 task-only sleep_until／yield，不复制 deadline 工具 | 公共等待可先完成；延时／yield 在后端与任务上下文稳定后验收，覆盖过期、量化与非法上下文 |
| OSU-14 | P1／06、09、13 | 连接各后端通知；直接任务通知作为明确选择的后端优化 | 同一消费者不含后端分支；优化不隐占通知槽，不扩大单等待者合同 |
| OSU-15 | P1／08、14 | 分开 Task 与允许的 ISR 唤醒入口，复用 IRQ ceiling／掩码检查 | 非法优先级、异常、权限或屏蔽状态在对象变更前拒绝，合法路径保留原掩码 |
| OSU-16 | P1／11、14、15 | 在实际 owner 消费链落实发布者停止、会合及通知销毁 | SETTLED 后仍在执行的发布者不能访问已回收存储；无隐藏退出线程 |

`nx_sleep_until` 使用同域绝对 deadline，拒绝 `NX_DEADLINE_NEVER`，不承诺微秒
调度精度、不隐建 timer。`nx_task_yield` 只提出调度提示，不是公平性或等待完成证明。
TIMEOUT 只表示本次等待预算结束，不能撤销已接受 I/O 的借用。取消、排空失败及
QUARANTINED 的责任继续沿用 Core 和 provider 合同；不把通知销毁当成取消设备。
运行中的内核继续保留 platform clock／Tick；仅在全部消费者静默且所选内核生命周期
允许时撤回，不承诺通用 scheduler shutdown，不在内核运行期间直接关闭它们。

## WP5：普通队列与可关闭 channel

复用已有字节队列和关闭协议。原始队列与可关闭通信通道保留分开的类型或明确
配置，使固定常驻关系可以选择更小的对象。

| 任务 | 优先级／依赖 | 改动与产物 | 退出条件 |
| --- | --- | --- | --- |
| OSU-17 | P1／02、06、07 | 统一有界字节复制队列、try 与绝对 deadline 操作 | 单位、立即就绪优先、输出保持及缓冲区所有权一致，执行真实内核队列路径 |
| OSU-18 | P1／14、17 | 接入可关闭 channel、调用者 waiter 和 drain 协议 | close 拒绝新发送、唤醒阻塞者、保留旧数据；drained 且 users 退出后才能销毁 |
| OSU-19 | P1／15、17、18 | 固定 queue／channel transfer 的运行态 Task-only 范围 | deadline 0 也不能在 bootstrap 传输；本批无 ISR transfer，IRQ 使用受审通知入口 |
| OSU-20 | P1／03、16、18 | 迁移真实生产消费流程，固定满队列、停止、迟到 wake 行为 | 执行 owner 在排空期间继续运行；大 payload 使用稳定引用时有独立借用闭环 |

等待者数量和 payload 大小分别决定广播与复制成本。配置明确最大并发 waiter，
不创建全局池；性能报告分开记录调度暂停与 IRQ 屏蔽，不能混成一次主机耗时。

## WP6：同步原语需求与范围决定

OSU-21 已盘点生产组件：同步通过窄端口注入，未直接依赖公共跨 OS mutex 或计数
semaphore。当前任务与通信消费链不需要新增这两类原语，因此 OSU-22／23 明确不
纳入本批，没有新增 `mutex.h`／`semaphore.h` 或占位实现。原生内核具备相应能力，
不表示 Nexus 已提供公共支持。下表保留未来真正选入时必须满足的合同。

| 任务 | 优先级／依赖 | 改动与产物 | 退出条件 |
| --- | --- | --- | --- |
| OSU-21 | P1／01、02、20 | 列出确需跨后端互斥或计数同步的消费者及最小合同 | 每种新增原语有真实用例；无消费者的选项有排除理由，不进入默认镜像 |
| OSU-22 | P2／06、12、21 | 公共 mutex 本批不纳入；后续选入须明确 owner、递归及优先级继承 | 排除依据为 OSU-21；未来实现仍须覆盖非 owner 释放、自锁及不支持协议，不降级硬要求 |
| OSU-23 | P2／06、15、21 | 公共 semaphore 本批不纳入；后续选入须明确饱和与 ISR 范围 | 排除依据为 OSU-21；未来实现仍须覆盖计数上界、超限、超时及销毁前置条件 |
| OSU-24 | P1／17、21 | 统一所选阻塞操作的 deadline、错误和输出语义 | 不新增相对超时换算器；不把不支持原生能力映射成成功或无限等待 |

普通业务不能用 semaphore 替代带所有权的 mutex。受限用户任务、跨安全域同步和
内核专属抢占控制仍属扩展范围，未完成准入不能放进公共默认能力。

## WP7：迁移消费者与交付入口

采用一次性源码迁移，不保留旧 API shim、别名或兼容门面。先保证目标消费者能
完成同一流程，再删除旧公开入口，避免留下两套竞争的维护路径。

| 任务 | 优先级／依赖 | 改动与产物 | 退出条件 |
| --- | --- | --- | --- |
| OSU-25 | P1／09、14、17、24 | 迁移平台消费点，删除退役公开头、声明及重复连接 | 旧入口无生产引用；原生类型仅留后端布局、实现及明确扩展，允许装配依赖布局头，业务头不泄漏 |
| OSU-26 | P1／16、20、25 | 审核组件、I/O 和 SoC 依赖，维持窄端口注入 | 设备日常 I/O 不强制经过 OS；公共组件无内核条件分支或隐藏 worker |
| OSU-27 | P1／10、12、20、25 | 在独立 nexus-examples 仓迁移任务装配、配置、锁和示例 | 同一业务源码在选定 RTOS 运行；两仓提交分别绑定，不把应用移入平台 |
| OSU-28 | P1／07、25、27 | 更新 Source SDK 导出与外部 Platform／CPU Runtime 消费者 | 搬迁后的 SDK 可独立配置、链接及运行适用消费者，无 checkout 私有路径泄漏 |

常规应用只使用公共合同；主动采用 MPU、TrustZone、直接通知槽或特有调度机制的
适配留在产品基础设施层。业务源码可移植不等于原生扩展、存储预算和实时参数
无需重新评估，也不承诺跨工具链、ABI 的二进制兼容。

记录，不能把前者冒充全部行为的运行期 RED。纯文档修改不新增镜像实现测试。

| 任务 | 优先级／依赖 | 改动与产物 | 退出条件 |
| --- | --- | --- | --- |
| OSU-29 | P1／04、20、24、26 | 合并 GoogleTest／GoogleMock 合同与真实内核探针，审查重复覆盖 | 测试生产 C；保留超时、迟到发布、join、关闭和实例隔离负例；不只验证 mock 次数 |

OSU-30 对 OSU-22／23 的依赖由 OSU-21 的明确排除决定满足；两类原语不标为
已实现或已支持。通用算法按实现类别验证一次，编译变体保留其独有 ABI、掩码、FP／MVE、
MPU 或安全合同；不展开所有 CPU、板卡、后端、优化和功能的笛卡尔积。

## 顺序、并行与效率

1. 公共头和存储合同冻结后，三个后端按各自目录并行；消费方使用相同 C11 公共
   业务源，后端测试 runner 分别维护，不在业务中添加内核条件分支。
2. 每个并行任务有明确文件范围；同一维护构建目录通过显式交接串行使用。
   汇总已发现的合同修正后执行所需完整门禁，不为每项任务重复全仓工具测试。
3. 普通后端公开入口完成一次性迁移，专有扩展保留明确命名，不增加兼容门面。
   生产组件与应用分仓，示例锁定和 SDK 消费需分别绑定实际平台提交。
4. 日常反馈使用维护的相关目标；最终运行范围沿用现有工具选择，不加过滤来冒充
   完整验收，不缓存成功报告，不绕过提交门禁。

## 软件交付与后续 HIL

软件退出需要：公共合同有真实消费者；三后端在明确范围内保持同一业务源码；
失败及退出路径完成；选定存储与源码可裁剪；外部示例、Source SDK 和 CPU Runtime
完成各自验证；当前合同、中英文说明和实际行为一致。不能以本页发布代替这些条件。

物理 IRQ 到唤醒延迟、调度抖动、真实栈峰值、低功耗时间连续性、FP／MVE 切换和
安全隔离保持独立 HIL 验收，当前按用户安排暂缓，状态保留 `not_executed`。
它们不阻塞已明确边界的软件交付，也不能被 Native、模型或 ARM 链接结果标成通过。
不设无测量依据的绝对性能门槛；发现资源回归先解释对应能力与对等基线，再决定取舍。
