# 当前派生能力矩阵

本表由维护工具读取当前 SoC 事实、受审路线、Board 包、实际软件装配和生成
face 对应的生产 ops 定义生成。它不是另一份配置输入，也不建立编译、执行或实板
资格。声明模式、允许 route 和本次选择分别核对，空列表示没有该类关联。

生产聚合包含解析后 scope 为 `production` 的 STM32F4 和 STM32F1。
Native 属于显式 host-test fixture，不计入生产 SoC 支持；`scope=reference` 的软件
参考必须显式启用 test support，也不进入生产聚合。其他保留的 vendor SDK 不进入
本表。精确限制见[支持](support.md)。

```sh
python tools/maintenance/capabilities.py --write
python tools/maintenance/capabilities.py --check
python tools/dev/dev.py support --assembly tools/configure/assemblies/qiming-baremetal-uart-dma.toml
```

从完整仓库根执行，工具按同一原始事实重建表；`--check` 拒绝陈旧内容。修改能力应
先改真实实现、事实与合同回归，再生成此投影，不手工编辑表格行。

## 查询与证据

选择查询报告精确型号、Board、模式、资源、预算和输入身份，并通过
`provider_package` 记录真实 package 的 ID、family 和 scope。事实与 CMake 输入
使用同一快照身份；工具不从家族 Python 注册表或固定文件名猜来源。查询不运行
新的编译、测试、烧录或测量。默认软件阶段保留 `not_assessed`，不表示历史上从未
执行，也不表示失败。显式查询 reference 包仍保留其参考 scope 和未评估的物理状态，
不能升级为生产支持或实板资格。

任何验证关联都必须匹配真实源码、配置、模式、产物和执行scope；不匹配或缺失时保持`not_assessed`。

物理 HIL 当前为 `not_executed`，查询不会改变 `physical_qualified=false`。
PCB、供电、跳线、波形、吞吐与时序需要真实 station 原件，软件模型和预算不提供
这些物理结论。资格规则见[验收边界](qualification.md)。
