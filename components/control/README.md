# 显式执行的电机与轴控制

本目录提供可选 C11 控制组件。调用者拥有每个实例的参数、历史、时间和执行者；
组件不创建任务、堆、设备注册表或全局时钟，也不直接操作厂商 SDK。

[控制架构与 FIG-35](../../docs/explanation/motor-control.md)区分算法决策、应用桥、
唯一硬件 owner 及最终退出；公共头保持各字段的权威合同。

| 入口 | 责任 | 调用者仍负责 |
| --- | --- | --- |
| `Nexus::MotorControl` | 有感电流计算、独立电压决策、固定调制入口、校准候选及算法故障 | 真实测量、选定调制与采样计划、硬件提交和完整退出 |
| `Nexus::AxisControl` | 命令准入、速度／位置级联、参考采用与参数切换 | 执行节拍、机械侧换算、授权与设备恢复 |
| `Nexus::CurrentControl` | 标定身份、电流换算、观测检查和拓扑重构 | 来源、零电流依据、采样偏差和周期关联 |
| `Nexus::ModulationControl` | 整载波脉冲、采样窗口和最终量化电压 | 完整硬件映射、模拟建立与实际执行预算 |
| `Nexus::DriveControl` | 有界参考、连续反馈分频、独立 inhibit 和共母线预算计算 | 队列存储、执行者、参数身份、限幅实施和硬件保护 |

算法决策、输出暂存、硬件采用和机械结果分别观察。控制组件的成功返回不证明
功率级已经采用输出，也不证明机构已经停止。底层请求和 callback 的借用仍以
provider 的最终退出为准；不能通过清零算法状态解除它们。

`nx_motor_voltage_step` 不生成 duty，适合将电压交给选定的联合调制／采样规划。
`nx_motor_step` 保留固定共模调制入口。每周期选择其中一条路径，最终量化电压
只对匹配周期 tracking 一次；提交失败后关闭准入并沿真实 provider 完成退出。

Current 保留实测与重构来源，双相重构后的零和不充当独立诊断。Modulation
联合输出脉宽、起点与采样计划；provider 必须完整映射或拒绝。纯 C 规划支持
某种拓扑、中心对齐或相移，不代表所选 MCU mapper 和功率板已具备该模式。

任务与 IRQ 不得同时逐字段修改同一个实例。跨上下文交接由应用已有的有界
queue／guard 或具有独立同步合同的对象负责。参数按完整 revision 切换，停机、
清故障和重新使能分别执行。

Drive 提供类型明确的 caller-backed SPSC，不创建任务或分配队列。参考接纳与
快环采用分别记录；连续反馈保留真实时间区间及快环覆盖，溢出锁存故障。遥测
另用可丢对象。共母线消费／回生预算只是限幅计算，不替代实际保护或机械策略。

通用数学继续复用 `../algorithms`；PWM、ADC、角度源、门极与 IRQ 由唯一硬件
provider 管理。底盘协调、升降承重、机械抱闸和整机动作属于外部应用。完整示例
保存在 `X-Gen-Lab/nexus-examples`，物理 HIL 与实时性能仍需精确设备执行。

本轮硬件接入限于 STM32F4；GD32F470 与其他非 F4 provider 延后。公共组件不加入
厂商分支，但只有实际第二实现与消费者通过后，才声明跨厂商复用已经验证。
