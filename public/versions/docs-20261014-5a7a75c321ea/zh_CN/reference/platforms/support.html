理解精确平台支持¶

支持分为五个独立维度：芯片事实、维护的 provider/mode、复核 Board route、实际软件执行范围和物理 station 范围。派生能力矩阵拥有 mode/route/fixture/source 关联。支持记录拥有当前详细限制；本页说明如何选择。

平台

维护选择与关键边界

Native

独立 host 模型、POSIX 行为和实际选定 RTOS host 测试；不建立 MCU 资格

F407ZG 启明 / F407VE 天空星

精确 M4F 料号和各自 Board 事实；明确选择广泛 F407 模式、baremetal/FreeRTOS 与复核 ThreadX M4 子集

F470ZG 梁山派

精确 GD32 M4F provider 与 Board；明确选择广泛模式、baremetal/FreeRTOS 与复核 ThreadX M4 子集

G474RE 来源参考

GPIO/LPUART 基线及 selected EXTI；不继承 F407 DMA 或全外设支持

H743ZI NUCLEO 参考

精确固定 HSI32/HSI64 与 Cache off/on profile、GPIO/IRQ UART 和有限 USART3 TX DMA；无 RX DMA 或运行态交接

U575ZI-Q 默认参考

外部预先建立 TZEN=0/SWAP_BANK=0、MSIS4、GPIO/IRQ UART；默认无 DMA 或双域 factory

U575 独立双域参考

TZEN=1、无 OS、同步复制 GPIO gateway；无通用异步跨域 transport

CPU-only Runtime

M0/M0+/M3/M4/M7/M23/M33/M55/M85 Core/Arch 及选定 baremetal/FreeRTOS 软件 profile；不生成 SoC/Board/factory

ThreadX 当前维护 Native Linux GNU 与 M4 GNU profile；不继承 FreeRTOS Cortex-M、MPU、split-security 或 tickless 矩阵。平台启动不进入任何 kernel。应用拥有 scheduler 启动。

FIG-13 分开 CPU 软件覆盖、精确 SoC 接入和物理验收。FPU、DSP、Cache、MVE、SAU 和 IRQ width 必须作为明确事实；CPU 名称绝不自动启用可选能力。

使用前核对选择¶

  1. 确认精确完整料号与 Board package，包括未知物理事实。

  2. 在能力矩阵核对选定 controller route 与 mode。

  3. 解析实际完整 assembly；不支持模式和冲突会拒绝。

  4. 核对精确 source/configuration 的软件证据，不能使用近似 tuple。

  5. 声明物理行为前核对实际 station record。

当前记录中所有维护 MCU 的物理 HIL 仍未执行。默认 Board binding 不涵盖全部 connector、transceiver 或外部器件。有限 block 模式存在 rearm 间隙。连续模式需要显式 replacement 存储和 service 预算，不能承诺任意负载下无损。Flash geometry 是物理机制，产品分区和升级策略属于外部工程。

FIG-14 仅适用其声明的 TZEN=1 同步参考。不改变默认 TZEN=0 Platform 配置，也不建立物理隔离。把软件结果视为发布前先阅读资格。
