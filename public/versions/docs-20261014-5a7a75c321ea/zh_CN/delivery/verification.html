当前证据与验收边界¶

本次九核 CPU/Arch/Core/OS runtime 与平台迭代必须重新执行验证。旧版本候选、 历史测试数量和开发目录不能继承为新 HEAD 的资格。实施台账的 implemented 表示源码和工具已落地；验收状态必须读取对应 HEAD 的执行报告。最终执行保存在外部 nexus-delivery/<HEAD>/；每份报告绑定源码、配置、依赖、工具、命令返回码和产物。

HIL

工装已准备；未连接设备，所有物理结果 not_executed

本轮 SoC 的 canonical commit、实际完整门禁、离线候选与剩余验收范围见 SoC 扩展执行记录； 早期基线记录 保留原版本证据。 版本化 datasheet／manual／errata 索引只建立来源；实际 silicon revision 和各 mode 的 workaround 适用性单独验收。 soc_costs.py 保存真实 ELF／反汇编／工具调用与可比 profile，不将不同 backend、 route 或容量的大小差解释为同配置优化，也不把指令数量当作测得 cycles。

tools/hil/soc_acceptance.py 对 SOC-37–55 提供十九项 plan/capture/validate 合同。plan 只产生 prepared_unbound；参考 G474/H743/U575 即使改名或重新计算 metadata hash，也不能跳过 reference-only admission。真实 station 与工具输入、 协议、仪器、连续非空 samples 和 reviewed limits 一起决定结果。物理 Flash 掉电还需外部产品提供擦除对齐且避开全部 firmware LOAD 的显式测试布局。

开发执行目录 build/controller-routes-factory/ 与 build/minimal-factory-resources/ 保留独立 attempt 和原始命令，不覆盖旧运行。资源 数字只描述对应 ELF；源码变化后重新执行。MSP 显式预留，heap=0；未使用的内存域 不因芯片具有该区域就自动驻留。汇编和 ELF 字节不能替代实际 cycles／IRQ latency。

本轮 CPU/runtime 开发执行目录为 /workspace/nexus-all-cortex-evidence，保存 CPU 事实/schema、原子 publication/RMW、九核寄存器模型、可选 feature 编译与 真实 kernel context 审计各自的原始报告。公开报告记录实际命令、退出码、工具 与 hash；通过数和 feature 范围由执行结果读取，不继承此前数字或一种组合。 Source/installed Runtime consumer 与完整平台 consumer 分开建立证据，前者 没有具体 startup、SoC、Board 或 factory，不能替代后者或 candidate 封存。

RED 日志保存在 tools/testing/evidence/，GREEN 为真实框架执行。既有正确合同的 迁移明确标识，不为了制造 RED 而修改生产行为。commit hook 开始和结束检查暂存 快照及 index tree，拒绝执行期间发生的行为变更；失败不发布新的成功摘要。

正式软件资格要求 clean source/dependency、准确工具环境与配置、非零 fresh tests、 同一 ELF／BIN／map、当前预算、源码 SDK 独立消费与离线双构建。支持范围以 精确支持矩阵 为准，不把软件夹具的 connector 继承到参考 Board。

所有物理时序、精度、波形、reset、掉电和长期负载项目尚未执行。FP/MVE context 切换、IRQ latency、cache/DMA coherence、MPU/SAU 和安全世界协作也未进行实板 验收；可选 restricted MPU task 和 split runtime 的软件执行不能建立实板隔离 资格。实际 HIL 必须 记录 PCB、chip UID、probe／serial／power、station、预算和同一候选 image。
