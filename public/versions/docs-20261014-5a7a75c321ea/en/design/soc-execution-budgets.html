SoC execution budgets¶

The authored assembly and immutable resolved IR select exact controller modes, capacities and clock profiles. This document explains how to review their execution costs; it is not another capability registry or configuration input. The derived capability matrix owns the maintained selection projection. Product scheduling and overload policy stay external.

Work, time and completion¶

A finite work count is not a measured time bound. Bootstrap loops use explicit poll limits because the monotonic clock may not yet exist. Runtime absolute deadlines belong to the current boot clock domain. IRQ delay, DMA arbitration, bus stalls, notification latency and service intervals require measurements for the exact firmware and hardware under load.

Each selected mode must document its maximum IRQ work, task service work, critical-section scope, caller storage and terminal predicate. A drain deadline limits the period before quarantine; it never authorizes releasing borrowed memory. The executor must keep calling service/recovery until hardware, IRQ, queues and observers actually withdraw their references.

The exact implementations and configured limits remain authoritative:

  • UART: soc/*/drivers/uart*.c; G474, H743 and U575 are IRQ bytes only. The F407, G474, H743 and U575 wire-drain allowance is 20000000 / baud + 100 microseconds. GD IRQ uses its reviewed reset-abort protocol; it is not assigned the ST wire-drain formula.

  • SPI: soc/*/drivers/spi*.c; the finite DMA drain allowance is 200 microseconds.

  • I2C: soc/common/i2c_v1_async.c and the SoC wrappers; V1 async drain allowance is 1,000 microseconds. Polling STOP has separate finite work.

  • ADC/EXTI/timer: selected SoC driver and private state; scan, queue and channel limits come from resolved inputs or explicit caller storage.

  • CAN/USB/Ethernet: io/src/can_controller.c, usb_device_controller.c and eth_mac.c; poll/drain limits and selected capacities are validated at cold admission. IRQ notification remains a hint, never a replacement for predicates.

Cost review and evidence¶

Keep the exact resolved configuration, compiler identity, flags, linked ELF/map, resource budget and retention outputs together. Compare equivalent CPU/ABI, backend, clock, memory layout and capacities. A source instruction count, object-file size or different-capacity image cannot establish an equivalent whole-image saving. Report Flash, static RAM, reservations and caller storage separately. Disassembly is real tool output, not a cycle measurement.

tools/measurement/soc_costs.py observes actual linked functions and ELF resource costs with complete raw command receipts and input/tool hashes. Its comparison rejects changed routes, bindings, claims, backend or capacity profiles rather than silently attributing their cost to an implementation improvement. The empty versus selected and baremetal versus FreeRTOS dimensions remain useful selection-cost reports, but are not same-profile regression comparisons. The SoC execution record identifies the source scope of completed observations and pending final baselines.

For changed interrupt/concurrency behavior, GoogleTest/GoogleMock calls the real production source with external register/CPU ports modeled. Record actual RED, then GREEN; retain admission, loss ordering, cancel, quarantine, wake and instance isolation regressions. ARM budget/retention verifies actual linking. Software checks do not certify physical IRQ latency or DMA throughput.

No numerical maximum service interval is asserted without the selected producer rate, storage, hardware and interference budget. External products must qualify that interval and the resulting overload policy. A missed service deadline cannot revoke an accepted request or block loan. Current physical measurements remain not executed until an actual station records them.
