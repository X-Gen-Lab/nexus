如何取得与核对旧证据¶

  1. 先打开对应结果索引，确认 canonical code commit、配置和记录 scope。

  2. 使用索引中的归档定位，核对归档 SHA-256 和 bytes；记录失败尝试的原身份。

  3. 根据 archive_relative_path、archive_member_relative_path 等原字段定位 member， 继续核对该 member 的 hash 和 bytes。字段名因原 schema 而不同，按该索引解释。

  4. 查看实际执行记录、原始日志和同一产物。软件模型、链接、独立消费和两次断网 重建分别证明自己的范围，某一类成功不替代另一类。

  5. 物理记录按 HIL 状态另行判断。

原 /workspace/...、/dev/shm/... 是执行主机定位，离开该主机不能当作公开下载。 构建系统索引的 evidence_navigation 明确候选归档、candidate document、ELF／BIN／map 和全部 member 清单的定位方式。归档当前是原记录的本地留存；没有发布的远程证据 不能伪造下载 URL。文档包包含原 JSON 以便核对，并不复制大型原始归档或重签历史字节。
