以太网帧借用与 MAC 硬件时钟¶

可选的 eth_frames 接口提供完整的分散聚集帧、一个带内 VLAN C-tag 和 MAC硬件事件时间戳。它选择独立的 provider 状态、八字描述符和调用方存储。现有 eth 接口保留连续无标签帧契约、四字描述符及原有操作表。选择其中一个接口不会扩大另一个接口的能力。

首批面向硬件的实现是采用已维护 168 MHz、200 MHz HCLK 配置的精确STM32F407、GD32F470 RMII provider。Native 提供显式的 C 硬件模型。已执行的主机验证覆盖公共契约、共享引擎、精确系列 provider、Native 和普通装配／工厂组合。两个规范 ARM 固件配置也已编译和链接通过。这些属于软件检查；物理 RMII、PHY 行为、外部总线时序、时间戳准确度和工位 HIL 仍为not_executed。

装配与硬件所有权¶

已维护的普通装配契约使用 authored eth_frames.mac 控制器选择rmii-vlan-sg-ptp、已审核 RMII 路由、MAC 地址、精确 TX／RX 环大小、RX缓冲大小、IRQ 策略以及有限初始化／排空预算。工厂契约通过nx_factory_eth_frames(NX_ETH_FRAMES_ID_MAC) 返回已有的静态nx_eth_frames_port_t。查找不得访问硬件、分配或初始化。配对的 MDIO 接口通过独立公共类型访问同一物理所有者。位于cmake/package/verification/io_evolution/ 的两个规范示例配置f407zg-eth-frames.toml 和 gd470-eth-frames.toml 验证了这一完整组合。

Platform 拥有 System 时钟租约、引脚、RMII 选择及 MAC／TX／RX／PTP 时钟门。provider 在该租约内管理 MAC、DMA、PTP 计数器和 IRQ。旧 raw Ethernet 与增强帧不能同时拥有同一 MAC。产品在本仓库之外提供 PHY 复位、地址、电源、自协商／链路观测、网络栈、报文分类和关闭策略。

启动先建立实际 HSE8／PLL168 或 HXTAL25／PLL200，再访问 MAC。系列 provider检查最新的振荡器／PLL 就绪、实际时钟源状态、PLL 参数、AHB／APB 分频、RMII选择及独立 PTP 时钟门。仅请求切换到 PLL 或声明配置频率，不能授权 16 MHz回退或其他实际分频。两份手册都要求 Ethernet AHB 至少 25 MHz。外部 50 MHzRMII REF_CLK 不能证明 HCLK 或 PTP 输入时钟。

provider 在复位前拒绝外部／活动描述符表。描述符和报文存储必须处于精确的主SRAM DMA 域；排除 F407 CCM 和 GD470 TCM。软件元数据可使用其他 CPU 可访问存储。硬件描述符步长为 32 字节；ST HAL 描述符类型还含软件备份字，不能以其大小作为硬件步长。官方头文件提供经过审核的布局／掩码定义；不选择厂商 C运行时、描述符池、可变全局游标或 HAL tick 初始化。

完整帧与 VLAN 处理¶

TX 请求包含不可变 nx_eth_fragment_t 视图。准备阶段在改变请求存储前检查全部长度、指针溢出及跨片段的完整 L2 首部，拒绝空片段。允许一个 EtherType0x8100 C-tag；TCI 保留在载荷中。拒绝嵌套标签、0x88A8 和采用长度字段的802.3 帧。无标签帧包含 14..1514 个调用方字节；带标签帧包含 18..1518 个，均不含前导码、硬件填充和硬件 FCS。

所选模式不插入或剥离标签。PCP／DEI／VID、access／trunk 端口策略及 VLAN成员关系属于产品。保持硬件填充／FCS 开启，校验和卸载关闭。

准入先检查全部片段、DMA 范围及空闲描述符。拒绝时请求与 OWN 状态不变。接受后，provider 记录 PREPARING 预留，在不屏蔽 IRQ 的情况下准备可变数量的描述符，待后续所有描述符就绪后才发布首个 OWN。IRQ 不能把 CPU 所有的PREPARING 描述符解释为已完成流量。每次 IRQ 最多推进一个 TX 和一个 RX描述符。中间 TX 回写不能证明整帧线上完成；实际末描述符提供最终状态及可选捕获。

RX 获取产生一个 nx_eth_frames_rx_loan_t 和调用方提供的片段视图。视图不足返回 OVERFLOW，不将帧出队或改变输出。即使 FCS 占据整个尾描述符，视图仍排除 FCS。令牌持有全部硬件描述符，直到精确释放。复制令牌不增加借用。过期、外部、语义字段被改变或重复的释放均拒绝。结构体填充字节不属于令牌身份。

借用、取消与恢复¶

接受 TX 后，完整请求、片段数组及全部载荷一直被借用，直到以 acquire 语义观测到 SETTLED。单个描述符归还 OWN 不会独立释放片段。完整帧借用被持有时，RX 字节保持不可变。视图数组本身只是未保留的输出，可在获取后复用。provider 的输出存储必须与其状态、环、控制对象及全部活动请求／载荷借用分离。

MAC 仅提供控制器范围的 TX 撤离。取消一个待处理请求会关闭 TX 准入并排空其他待处理 TX，不虚构逐帧中止能力。实际完成的发送可以优先于取消。超时、取消和排空失败都不会撤销借用。无法证明引擎／MAC／FIFO 静止时，请求保留为QUARANTINED，载荷地址继续保留。

STM32 ES0182 控制写规避措施依据租用的 HCLK，执行有限次 volatile Device读取。该间隔超过最慢所支持 10 Mbit/s 下的四个内部 TX／RX 时钟周期，包含RMII 内部 REF_CLK／20 分频。四次 HCLK 回读或最快情况下的 80 ns 下界都不足。该间隔用于受影响的控制写，不用于报文 poll／W1C 写。GD32 共享机制采用同样的保守顺序，但不将 ST 的硅勘误归于 GD32。发出 FTF 前必须观测 FIFO 已空；刷新非空 FIFO 不能制造取消完成的证明。

Stop 关闭新准入／获取，在释放存储前证明 MAC／DMA／IRQ 引用撤离。被持有的RX 或已捕获的 wake 发布者返回 BUSY。可选 wake 接收器一直被借用到发布者退出；通知只是提示，不是完成谓词。调用方在回收各自存储前，还须分别停止并join 外部生产者、消费者、等待者与观测者。

显式恢复属于 MAC 的排他所有者。它在发出复位前拒绝被持有的 RX 或活动发布者。只有复位被实际确认后，才能撤离未完成 TX 并以已锁定失败原因结算。复位超时继续保留所有权，不自动复位、重试或重放。成功复位记录 RX 缺口并递增 MAC时钟 epoch。Stop／start 保留 RX 令牌代次和时钟 epoch 计数，防止旧身份再次有效。

时间戳含义¶

所有时间事实都使用已有 nx_io_timestamp_t。装配契约从实际计数器的统一命名空间分配一个非零 32 位 domain；应用不能通过赋予相同本地设备 ID，就使互不相关的计数器具备可比较性。

所选时钟使用数字纳秒回卷、20 ns 子秒增量和精细更新。累加器输入为 HCLK，168 MHz 时 addend 为 1278264076，200 MHz 时为 1073741824。上述数值和声明单位不代表量测的振荡器准确度。该计数器不是 UTC、TAI 或已同步网络时钟。

验证与剩余物理工作¶

已维护的外部 MMIO 模型区分可见寄存器回读与内部锁存，分别建模 W1C 和只读DMA 进程状态，并在故障控制要求时拒绝引擎撤离／复位。Native 收发是显式的完整帧事件，不会自动 service 或结算 provider。各模型实例具有独立计数器与 DMA 身份。

Native 源在与 provider 结算相同的排他域中验证活动借用。确定性的最终访问回归让真实 provider 结算已接受请求，随后让消费者合法保护已回收页；旧的未受保护读取会触发故障。这仅证明该软件边界，不代替物理 DMA 或完整并发系统资格。

已执行的主机验证包含 108 个公共／共享引擎／系列／Native 用例，加上每个规范装配各六个工厂用例，全部无失败、无跳过。工厂用例针对同一共享时钟／定时器oracle 和实际 DMA 可达地址，执行真实 System／GPIO／provider 代码。两个规范ARM 配置均使用所选源码编译和链接通过。工位证据保持独立：在实板验证 PHY 时钟／复位、路由与电平、两种链路速率、负载下DMA 流量、控制写间隔、VLAN 保留、错误／排空／复位、PTP 捕获行为及量测的时钟准确度。

已知 GD32 ENET 帧间隔限制仍是物理资格约束；本软件模式不能凭主机模型声明IEEE 时序符合性。协议栈、PHY／PCB 策略、时间同步及应用产品仍是外部平台消费者。
