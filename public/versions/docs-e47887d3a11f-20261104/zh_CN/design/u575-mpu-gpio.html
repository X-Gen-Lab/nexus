U575 MPU-v2 scalar GPIO WRITE authority¶

本实施参考选择 STM32U575ZIT6Q TZEN0、MSIS4、单一 security world、FreeRTOS MPU-wrapper-v2 及实际 Cortex-M33 八 region port。一个受保护 task 可通过一个不可变 grant WRITE GPIOC PC7。软件证据现包括真实 C host 模型、normal M33 reset 链接，以及经过维护静态 ELF gate 的单个搬移 development-SDK consumer。未执行 runtime MPU 异常行为及电气 HIL。它不建立 M7 MPU 支持或通用 user-device gateway。

通过维护的装配 链接所选 Nexus::U575MpuGpio target。普通 profile 保留锁定的 70 项 syscall 编号及 delay/tick 服务。仅 user_io="gpio-write" 选择 71 项派生、新 slot70 及受保护 task 的 pin/epoch 字段。资源结论仅适用于实际测量的编译上下文和镜像；源码绑定证据 明确区分 selected/default 范围与历史阶段。

图合同 区分实际调用、受保护 authority、保存掩码后的排除边界及生命周期责任。任何箭头均不创建 worker、动态 handle registry、user MMIO 映射或异步 request 协议。

五个显式内存域¶

维护的 normal memory generator 接受五个显式、非空、32 B 对齐的预留区。其 Flash 和 RAM 总量可小于物理容量；余下尾部保持未分配，不成为 user memory。溢出、重叠、非法大小及不足的 privileged MSP/static 预算在生成前被拒绝。这些是软件参考预留，不是产品分区政策。

绑定唯一可信 authority¶

声明以 authority 头文件、protected task 头文件 及 user entry 头文件 为准。在 privileged Flash 定义恰好一个不可变 nx_freertos_mpu_gpio_binding。它指定互不重叠的 privileged-RAM task/control 及只读 grant。grant 指定只读生成的 nx_binding_led pointer slot、逻辑 LED device 及 mask 0x80；绝不接受 user pointer 作为 authority。

读取嵌套字段前，实现核验完整对象范围、对齐和五个 linked range：binding、grant、pointer slot、face 及 ops 必须完整位于 privileged Flash；task、control 和完整具体 provider context 必须位于互不重叠的 privileged RAM。SoC validator 要求实际已初始化的 GPIOC PC7 output provider 及精确 ops 身份。仅元数据范围不能证明每条指令的 MPU 权限：最终 normal ELF 还须将完整 helper/provider 函数范围置于 privileged Flash。

一个 privileged lifecycle owner 串行执行 task start/delete 及 authority open/close/join。binding、grant、task metadata、control 和 provider 在 linked image 整个寿命内有效；从 open 到 join 还禁止 GPIO stop 或重配置。仅 cold startup 对元数据清零。task 的单调 epoch 在删除后保留；join 只清除所捕获的 task epoch。task epoch 溢出即拒绝，不重用代次。NMI、HardFault、DMA 及另一个 security world 绝不写这些对象。

通过真实 protected port 进入¶

启动静态提供的 restricted task，然后在允许 user 调用前 open 固定 authority。open 核验实际 live task handle 等于选定 static TCB，快照其 task epoch，并 pin 住删除。没有调用方提供的 principal、查找表或借用 pointer 参数。

user 调用 nx_freertos_user_gpio_write(device, set, reset)。其真实 veneer 经锁定的 protected call stack/origin 核验进入 SVC70。dispatcher 在进入保存掩码的边界前取得实际 xTaskGetCurrentTaskHandle()，再于单次真实 nx_gpio_port_write() 效果期间复核 open phase、live TCB/epoch、device 和 grant。所选 provider 恰好执行一次有界 BSRR 写入。该效果边界内不调用 kernel API、等待、分配或产品 callback；scalar 结果在 R0 返回。

未知 device、错误 current task 或 0x80 之外的位返回 PERMISSION。合并 mask 为零或 set/reset 重叠返回 INVALID；closed/陈旧代次返回 STATE；非法 privileged 元数据返回 INVALID；不支持的上下文返回 CONTEXT。这些拒绝均不产生 GPIO 效果。READ、toggle、任意 pointer、user MMIO、DMA、IRQ 及 copied/异步 I/O 均不属于本 API。delay 与 tick-read 仍是独立服务 6 和 13；最终 ELF 须证明全部三个 Nexus user 入口及其实际 veneer 位于允许执行的 region。

生命周期控制要求 privileged Thread，scheduler 为 running 或尚未启动，绝不能 suspended。FAULTMASK 和 BASEPRI 必须为零，仅 scheduler 启动前允许所选 port 的规范 bootstrap BASEPRI。service 要求 scheduler running 且 BASEPRI 为零。incoming PRIMASK 被保存和恢复。该单核排除不能约束未建模的 writer；产品须保持精确 single-owner 前提。

显式 close、join 和 delete¶

close 撤回新效果但保留 task pin。join 要求 closed 状态和同一 live 代次，进入保存掩码的排除边界、移除 pin 并分离 authority 的 handle/task epoch。任何 scalar 效果都不能跨越该单核边界。join 不删除 task、停止 GPIO 或复位 task lifetime epoch。失败的 close/join 保留责任与存储。

task 有 pin 时删除返回 BUSY。join 后，lifecycle owner 可删除另一个 task；拒绝自删。在 IRQ guard 外实际 kernel delete 之前，先设置受保护 closing marker，阻止删除期间 reopen。随后 owner 在第二个 guard 内清除 handle，保留 task epoch。产品仍负责 user quiescence、task stack 寿命、scheduler 启动、安全输出及最终 provider/platform stop。

证据及剩余退出¶

可执行测试先于生产修改，并暴露实际 authority、task、provider-context 和 startup 缺陷。经审查移除未暴露的 control counter 后，实际 task epoch 得以保留：最终模型结果是保持行为的 refactor GREEN，不是新的行为 RED。维护的 Native CMake target 执行最终全部用例。配置及锁定 port 检查保留默认与不支持 profile 的覆盖。公共 consumer 使用包含真实 reset startup 的 normal firmware graph。源码绑定证据 记录精确源码阶段、原始执行、已编译 ABI 事实、资源及单个搬移 development-SDK consumer；不宣称完整当前 SDK transport plan 已通过。

选定 ELF gate 检查完整五域范围、不可变 authority 指针、受保护对象、已编译 task/control 大小、实际 slot6/13/70、三个 user wrapper 及真实 veneer。其明确支持的 GNU Os startup 形状核对实际 reset/identity/user-initialization 调用及 DATA/BSS 边界；不认识的形状一律拒绝。这些静态 layout、opcode 和调用事实不执行 protected SVC entry/exit。未执行 runtime MPU fault、task switching、实际 PC7 output、interrupt latency 及 HIL。完整 IO-39/SOC-36 退出、其他 device、多 task/grant 及 M7 MPU 仍开放；typed interface 或 host model 不能关闭这些退出。
