官方库优先目标与当前实现¶

官方硬件库是后续 provider 工作的默认输入。已审查 HAL transport 满足完整所选模式时予以复用；否则将合适的 LL 或 SPL 原语静态绑定到所需有界机制。Nexus 保留准入、借用存储、deadline、结果发布和资源责任。直接寄存器 helper 仅作为精确 SDK 缺口、erratum、原子操作或实测预算的有理由例外。

所选 F407 UART dma-tx provider 在一个私有 owner 内使用官方 HAL 有限 TX 和分离的 LL IRQ 接收器。其他 F407 UART 模式保留既有引擎；G4、H7 和 U5 保留已审查的 LL 集成。GD32F470 编译所选官方 SPL C 单元。源码选择、模型测试、ARM 链接和物理执行仍是分别取得的证据。仅 include、原语调用或有限 TX 夹具不能建立完整 transport 或系列资格。

现有交付完善台账追加 V-A01 至 V-L08、V-P01 至 V-P06 及 V-X01 至 V-X04，保留旧记录和冻结结果。各新记录分别保留真实实现、软件和物理状态；计划没有执行证据。派生台账视图继续使用同一 renderer，不引入第二套支持或完成状态数据库。

固定时钟准入¶

已审查的软件调整值检查在冷态预检中执行。受检查的配置出现异常调整值时，启动事务会在写硬件或取得资源之前拒绝准入。芯片出厂校准值保持独立且不变；准入过程不会重新调节振荡器。这些检查不会增加正常 I/O 调用路径的工作，也不构成时钟精度实测或物理时序资格。

F103 的 HSI8 和 GD303 的 IRC8 分别要求 RCC_CR.HSITRIM 与 RCU_CTL.IRC8MADJ 的调整值为 16。H743 精确 revision V 的 HSI 准入要求 RCC_HSICFGR.HSITRIM=64；更早版本的固定名义配置保留原有的 revision 边界。U575 已选的 MSIS4 档位要求 RCC_ICSCR2.MSITRIM1=16；其独立的 I2C1 HSI16 准入检查继续要求 RCC_ICSCR3.HSITRIM=16。U575 的选择依据锁定官方 HAL/CMSIS 的档位与调整字段映射及复位定义。

F407 的 HSE8/PLL168、GD470 的 HXTAL25/PLL200 和 G474 的 HSE24/PLL170 继续使用外部主时钟。三者的内部时钟准入检查分别为 RCC_CR.HSITRIM=16、RCU_CTL.IRC16MADJ=16 和 RCC_ICSCR.HSITRIM=64。这些检查约束名义启动与回退时钟；G474 已选的 I2C1 内核也使用 HSI16。G474 的默认值 64 依据 RM0440 Rev9 第 7.4.2 节和锁定的 HAL 定义；LL 注释中的 16 已过时。

生产推广门槛¶

所选 F407 dma-tx 实现保留完整模式，包括 IRQ RX byte/event、frame/error/loss 顺序、时间戳、wake 和存储。HAL 拥有有限 TX DMA、UART TC 完成顺序和 TX abort；私有 provider 负责它们与分离的 LL 接收器及 Nexus 生命周期的集成。较早的串行有限 TX reference 仍只为其较窄合同提供评估证据，不是生产模式的资格。其他模式替换前须分别完成完整评估。

串行参考的 hal_depth IRQ guard 不是 MCU 抢占设计。生产实现必须明确允许的 HAL 嵌套、短 guard、pending-fact 处理和真实 IRQ 服务顺序。不得在可能等待的 vendor 调用周围屏蔽全部中断。abort callback 可以在 task 上下文同步执行；桥接记录有界事实，并使用实际上下文允许的通知。产品 callback 和最终结清不能任意在 vendor callback 调用栈内执行。

仅携带 Handle 的 callback 没有请求 epoch。复用 Handle 前必须证明上一次硬件、IRQ 和 callback 引用已撤离；将当前 epoch 填入迟到 callback 不能证明其关联。在 vendor 调用可能保留引用前建立 admission；admission 后的启动错误属于已接受工作，需要明确撤离。

审核每条可达 vendor 等待，包括 bootstrap/runtime 推进、毫秒量化、32 位 tick 回绕和低功耗暂停。首批 UART 工作保留既有系统时钟和 OS 启动选择。所选 HAL 模块不授权默认获取 SysTick 或更改中断策略。UART/SPI 的 uint16_t Size 参数必须匹配所选公共 size_t 合同，不能截断、隐藏分块或隐式提供 bounce 存储。

SPI 评价保留完整 CS 区间、dummy/discard、固定 DMA 地址及计数。GPIO 需要一条合并的 set/reset 命令；所选 U5 GPIO 命令现通过私有 HAL_GPIO_WriteMultipleStatePin 和已准入的 GPIO 源码闭包实现，不能用分开的 set/reset 调用代替。DMA disable 仍需实际 readback 和撤离证明，才能归还借用存储。

逐一检查完成调用栈：F4 SPI DMA 可能等待 TXE/BSY；H7/U5 的 EOT 硬件关闭流程必须先保留所选静默间隔，再禁用移位器。U575 HAL 也已包含由 Device 条件宏控制的 persistent-DMAT workaround。这些 API 的适用点不能证明回调、deadline 或借用引用已排空；应将普通 LL/SPL setter 与有理由保留的命令／快照例外分别审查。

实现边界¶

已审查的 F4 依赖是 STM32 HAL Driver v1.8.5，提交为 b6f0ed3829f3829eb358a2e7417d80bba1a42db7。其 CMSIS Device 配对来自 STM32CubeF4 v1.28.3。机器权威是官方驱动 lock，对照所选 Git 依赖和导入 SDK 字节校验。所选 API 为 stm32f407-ll-inline-eth-definitions-uart-dma-hal-tx。其 25 文件闭包保留原 LL/ETH 定义和许可证，并增加已审查 HAL 头文件及 UART、DMA、RCC C 单元。RCC 编译需要 GPIO/Flash 声明；不选入其 C 实现、PWR 或全局 stm32f4xx_hal.c。这个 lock 不声明所有 HAL 模块均受支持或已验证。

CMSIS Device 配对与共享的 Arm CMSIS-Core 来源分别维护。Core 迁移为七个维护中的 STM32/GD32 family 入口锁定官方 v6.4.0，同时保持各自的 Device/startup、HAL/LL 和供应商导入字节。内部 nexus_cmsis_core 目标提供 CPU 头，不改变公共 Nexus 类型、Arch 上下文／所有权合同或已选外设状态机。供应商版本分别记录发布版本、Core 版本宏、原始 pack 元数据和许可证身份。实际 include 闭包、固件链接和安装后 SDK 消费都需要当前源码的执行证据；使用同一 Core pin 不会把 F4 的资格转移给 G4、H7、U5 或 GD32。

此前的开发 overlay 已在 H743 family descriptor 与 SoC source-lock 投影中加入 hal_driver_h7，与既有已锁定 LL 构建输入一致。私有 capture、advanced-PWM 与 UART-FIFO 模板继续遵守各自的 specialization 合同；pin-state 提供可选 implementation 与默认宏作用域，而 CAN FD 仍是普通的、有 include guard 保护的声明。独立的 U575 SPI byte port 现在接收所选 controller 并直接调用私有 LL 函数，没有运行时转发。这些改动不重写已冻结源码审查的结论。

有界官方操作增量¶

当前开发源码对 U575 PWM 的 PSC/ARR/CNT/CCR1 使用已锁定 LL setter，对 UART RDR/TDR 使用承载字节值的字访问，并对 UART TC 单独清除、RTC 写保护密钥和 Alarm A 清除命令使用已锁定 LL 操作。既有屏障、精确 readback、IRQ／错误顺序、时钟准入、定时阶段和借用撤离仍由原 provider 负责。H743 SPI 轮询及 DMA 清理使用接收 controller 的 LL byte port；CSTART／CSUSP 的掩码处理、quiet tail、Cache 所有权及 DMA／IRQ join 保持不变。

U575 GPIO 现将四个既有命令位置交给实际 HAL GPIO C 单元：公共 write、初始化预装载、stop 和串口 TX 空闲电平。其私有 15 文件锁准入该单元及必需头文件；不会调用 HAL 初始化或 tick。已授权且不相交的掩码仍由一条 BSRR 命令处理；公共空掩码 write 仍返回成功，并避免调用 HAL 的非空掩码断言。

H743 USART3 的 IRQ-byte RDR/TDR 访问使用锁定的 LL 字操作，也包括选定 DMA 模式的 IRQ-byte 配套路径。provider 保留已保存状态的处理顺序、RX 错误／丢失、TC 完成和完整撤回。U575 看门狗的密钥、配置和刷新命令使用锁定的 LL IWDG 头，也适用于不引入 GPIO 源文件的 watchdog-only 装配。不可撤销的所有权先于激活记录；同步、精确读回、更新失败后的边界和恢复责任仍由同一 C provider 维护。

评审所选构建目标及其私有 include 图，而不只评审导出 ops 表的 C 文件。每个 H743 UART 选择都会编译共享的 uart.c，因此，其字节 IRQ 变化在 DMA／FIFO 组合中也需要评审；这并不意味着独立的数据引擎已转换。私有 I2C port 头文件将共享 V1／V2 算法绑定到所选的已锁定 LL 操作；即使冻结的文件清单形成于这些头文件之前，当前源码评审也需要包含它们。

对每个模式，分别判断三件事：所选硬件 owner、已委托给官方代码的精确常规操作，以及剩余的命令／快照例外或叶操作候选。保留 IRQ 快照、原子掩码或静默间隔，并不能成为无关手写配置的理由。源码评审和未变化的文件哈希，不能替代当前的编译器验证、模型、已安装 SDK、资源或物理证据。

GD32F470 CAN 和 Ethernet 在独立 C11 编译合同单元中核对 20 项和 25 项已复核的 SDK 寄存器偏移。每个单元先包含真实 SDK，再仅在本文件内将寄存器宏展开为整数地址。运行时 provider 保留位掩码、IRQ 检查和普通 SDK 寄存器访问。这些合同单元不生成固件代码或数据，无需编译器特定常量折叠或扫描器例外。Raw 与 enhanced Ethernet 选择同一份 MAC/DMA/VLAN/PTP 偏移合同。源码编译、链接镜像成本和物理行为仍属于分别执行的验证范围。

五个 SoC 私有的编译期 I2C port 在既有共享引擎中，将 F103/F407 receive 及 G474/H743/U575 receive/transmit 绑定到已锁定 LL 操作。它们不增加运行时转发层、vendor Handle、状态或生成的硬件算法。factory face、公共 ABI、生命周期和模式选择不变。实际 old-GREEN 基线及真实默认操作探针仍属于开发证据；最终 clean-source 门禁、完整 SDK 消费和资格尚待完成。

所选 F407 HAL UART transport¶

同一个用户编写的 dma-tx 模式选择静态私有 owner、不可变冷态配置、一个 UART_HandleTypeDef、一个 DMA_HandleTypeDef 和共享 readonly Nexus ops 表。factory 仍返回既有 Nexus face；vendor 类型和 callback 注册都不成为公共接口。私有 callback ABI 在 adapter 和所选官方 C 单元中一致设置 USE_HAL_UART_REGISTER_CALLBACKS=1。TX completion/error/transmit-abort/MSP 及 TX half-transfer callback 逐 Handle 显式绑定，不提供全局产品 callback 覆盖或运行时控制器 registry。

一个 provider 拥有 UART 的两个行为域。LL 接收器只消费一次 RX status/data，随后在 HAL_UART_IRQHandler 观察 TX 事实期间暂时屏蔽 RXNE/parity/error enable。HAL receive state 保持 idle，RX buffer/size/count 与 hdmarx 保持空，DMAR 保持清零。这样 HAL error/abort 路径不会认领 IRQ 接收器。意外的接收域或 Handle/route 身份变化会关闭准入并保留 quarantine；它不会接管或 abort 其他 DMA owner。

准入在 HAL 调用可能保留引用或同步 callback 之前建立 request 和 payload 借用。callback 锁存有界事实；只有 task service 才撤回传输指针并发布最终 settlement。DMA 完成仍不同于 UART TC，也不同于全部引用撤回。取消、timeout 和 deinitialization 失败保留 request 或冷态 lease，直到同一个 owner 证明实际 drain。stop 在释放引脚或时钟前检查外设 enable、DMA 地址/计数及 pending/active IRQ 引用。只有这次撤回之后才能复用 Handle；需要时由官方 HAL_DMA_Init 恢复可复用 idle state，不手动赋值 READY。

生产 IRQ gate 为短状态变更保存调用前 CPU mask。相关 UART/DMA IRQ 抢占 task HAL 调用时，只禁用该选定 vector，保留其硬件 pending 事实，并在保留的 HAL 调用栈退出后恢复 vector。它不会自旋，也不会让 level IRQ 在该 task 调用中无限 tail-chain。每次进入 HAL_DMA_IRQHandler 都要求 EN 回读清零，包括只有 HT 或未观察到错误的 IRQ：错误可能在 flag 快照之后到达。EN 仍为置位时，只有 HT 的事件通过官方原语确认并禁用 HTIE；不调用已注册的私有 no-op callback，也不推进传输状态。观察到错误或不一致终态事实时，撤回 DMAT 并请求 disable 一次。disable 拒绝则屏蔽该 DMA vector 并 quarantine 借用；task service 重试，并仅在 EN 清零后分派 HAL。这样所选 IRQ 路径不会执行所锁定 handler 的 SystemCoreClock/9600 等待（168 MHz 时为 17,500 次迭代）。这是有界路径设计，不是已测中断延迟或 WCET。

目标私有编译 profile 将 CMSIS exclusive-retry RMW 宏替换为一次保存 mask 的 word 更新。此 profile 要求对齐的 UART 控制 word 只有一个 CPU owner，且没有 NMI、fault/panic logger 或其他 writer。它保留调用前 mask，不修改 vendor 源码。同一 profile 使用最接近的 OVER16 BRR 舍入，以不会溢出的商/余数计算；冷态校验在 UART enable 之前拒绝零 baud 或超出字段范围的 divisor。它不授予动态时钟或任意格式支持。

只有所选 HAL UART/DMA/RCC 源单元进入 provider 私有构建。不选入 HAL_Init、HAL_InitTick 或 HAL SysTick handler。HAL_GetTick 从既有活动 TIM2 epoch 读取以 uint32_t 按 2^32 回绕的毫秒数；bootstrap 保留独立的有限轮询上限。SystemCoreClock 跟随最后确认的 16 MHz HSI 或 168 MHz PLL 观测，包括部分 startup 和 cleanup 失败。官方 RCC frequency getter 使用所选 prescaler 表，而不是虚构常量时钟。

实际 adapter/官方源码模型和时钟测试建立其已记录的软件范围。生成 factory 的执行、所选 ARM/SDK 链接、栈/周期比较及完整当前源码 gate 仍是分别验收的退出条件。没有连接设备时，不执行物理 IRQ latency、wire timing 和长期负载 HIL。不能从复用 vendor 代码或模型通过推断资源改善。

构建期 provider 合同¶

每个 constructor 从 provider 公共合同返回冻结的 Construction record。它列出 state_type、definitions、initialize、stop、retain_on_failed_init、exports 与 pin_snapshots。公共 emitter 消费这些决策，不从 family 名称重建状态类型或 failed-init 责任。initialize 是不可变 DirectCall；stop 是此类调用的 tuple。参数为显式静态 Symbol 或 Address 值、uint32 常量、boolean、NULL，或绝对 deadline 构造等嵌套直接调用。拒绝自由表达式、cast、assignment 和 function-pointer/member-call expression。definitions、exports 与 face_definitions 仍以 C 源码字符串承载声明、静态配置、存储、face 与固定转发。具体 C adapter 拥有硬件算法。实际 C 编译器确定符号和参数类型。这是窄 Python 生成合同，不是完整 C AST；这些 Python record 不向 MCU 镜像引入额外运行时 metadata 或 dispatch。

家族负责数值限制、支持模式、精确路线与构造语义；resolver 负责严格字段、不可变输入和资源冲突；CMake 负责源码选择和目标依赖。必须保留这些独立权威：生成器不得创建第二份源码构建图，配置语法正确也不能表示尚未实现的硬件已经可用。

选定 I2C V2 的不可变配置¶

选定 G474、H743 与 U575 轮询 I2C V2 provider 将私有 nx_i2c_v2_config_t 与 nx_i2c_v2_state_t 分开。生成的只读配置保存寄存器／复位地址、复位掩码、timing、有限轮询预算，以及显式选择的 BERR 和单字节 RX reload 勘误选项。零初始化的运行时存储保留配置指针和 initialized、retained、active、fault 状态。公共 face、共享 ops 和 factory 查找保持不变。该拆分不等于已经测得 Flash 或 RAM 节省。

私有 nx_i2c_v2_bind 在串行化的特权 Task owner 下执行，且要求中断未屏蔽。它校验配置，并拒绝与运行时或硬件存储重叠。已 initialized、retained 或 active 的 owner 在不修改状态的前提下拒绝重新绑定；成功绑定本身没有硬件效果。不可变配置必须与运行时 owner 同寿命；成功 stop 释放硬件所有权，但保留绑定。不得只为替换配置而重置仍在使用的 owner。

具体 G474／H743 i2c_prepare 入口先绑定，再准备引脚并初始化引擎。U575 独立的可变 clock owner 在绑定前拒绝 retained clock，并在引擎初始化前取得所选时钟。其 i2c_close 先停止引擎；只有该 stop 成功后才释放时钟。排空失败保留相关运行时与时钟责任，供显式清理或重试。

family emitter 现在提供静态配置并调用这些具体 C 入口。现有 Construction record 与生成的 Platform 仍对资源阶段、controller 启动和逆序清理的 C 调用进行编排。其他维护的外设模式采用各自 family 静态绑定与具体 C preparation；这不把所有平台生命周期迁入新的公共抽象。

精确参数与失败顺序见私有共享合同及 U575 集成。重构台账分别记录聚焦软件证据、最终链接成本比较和物理执行。

选定 UART DMA 的不可变配置¶

选定 F103 与 GD303 UART DMA 模式使用 nx_uart_v1_dma_config_t 保存寄存器／channel 地址、DMA 内存域、IRQ 撤下与 wake 校验 callback、字节 ring 或 duplex receive 存储、容量、波特率、IRQ 策略和 channel shift。所选 profile 标识存储 union 的有效成员。nx_uart_v1_dma_state_t 保留配置指针、deadline、active request 与 wake 引用、ring 游标、发布状态和生命周期标志。Duplex 内嵌自身可变 receive 扩展；字节模式不预留该扩展。配置及其引用资源与运行时 owner 同寿命。成功 stop 保留绑定，零初始化运行时仅在冷态准入期间绑定。

每个家族的具体 uart_dma_prepare 与 uart_duplex_prepare 要求串行化特权 Task，且中断未屏蔽。在 null／profile 检查后，先检查既有冷态 owner，再准备精确引脚并调用 initializer。Retained hardware、active request、wake publisher 与 duplex RX loan 阻止重新绑定；即使尚未绑定配置，也会检查候选 receive 扩展。撤下失败保留同一配置及未归还 loan，供普通 stop 或重试。共享只读 ops、公共 face 与直接 IRQ symbol 保持不变；不增加热路径 dispatch 层。

各家族冻结的 LegacyTransportProfile 向现有 emitter 提供精确接线，不使用 family-name fallback。对这些 UART 模式，所选 Construction.initialize 调用具体 C preparation；生成器提供静态配置、face 与 IRQ 转发。具体 C adapter 现在拥有 AHB DMA gate、pin resource 与保留清理。生成的 Platform 保留显式阶段顺序与 typed C 调用。Legacy I2C V1 及其他维护外设的冷态路径遵守相同的 C 硬件算法边界。

精确存储、callback 与寿命要求见 UART 私有合同。主机测试执行实际 SoC wrapper、共享 engine 与 GPIO model；生成 factory 校验和最终 ARM 资源测量仍是独立证据范围。

选定 legacy 冷态集成¶

F103 与 GD303 在各自 drivers/devices.c 保留具体 ADC、PWM 和 Flash prepare 入口。这些特权 Task 入口要求中断未屏蔽，并在替换资源绑定前拒绝相关 live、retained 或 faulted owner。精确 C adapter 拥有寄存器地址、固定引脚与 gate 关系、system-clock 状态和芯片特定冷态检查。家族生成仍校验所选 Board／模式并提供选定数值。既有共享 nx_legacy_*_close 路径保留 stop 与 drain 责任。

ADC 和 PWM owner 现在引用各精确 SoC 提供的只读硬件描述 nx_legacy_adc_config_t 与 nx_legacy_pwm_config_t。寄存器地址、gate 和固定 pad 事实移出可变 owner 存储。ADC 参考电压及 PWM tick／period／duty／inactive level 仍为选定 owner 状态，不提升为共享硬件事实。配置生命周期必须覆盖 owner，且不能与其 state 或 API 输出存储重叠。这不会把驱动变成 I2C V2 类型；Flash 保留独立私有合同。实际链接成本取决于精确选定镜像。

选定 U575 USART1 dma-tx 与 dma-chain-tx 使用静态冷态配置和具体 C prepare。C 适配器在既有 finite/chain 初始化前负责准入、绑定与引脚准备。选定 F407 SPI 轮询／DMA、成对控制器 DMA，以及 GD470 SPI0/SPI4 轮询和有限全双工 DMA，将 prepare/close 行为移入具体 C，同时保留原 Platform snapshot 槽及失败后保留的清理责任。GD470 的条件 EXTI close 也迁入 C。热路径传输引擎、公共 face 和直接 IRQ 所有权不变。

维护的 Native、F103、F407、G474、H743、U575、GD303 与 GD470 选择现在均把硬件算法保留在 C11，包括选定 GPIO、IRQ UART、ADC、PWM、EXTI、preflight、共享资源与保留清理。主机 Python 提供静态配置、存储、face 与固定 typed 调用；生成的 Platform 仍拥有显式启动和逆序清理编排。应审查实际选定的 C 路径，不从 call field 或目录推导支持。封存的冷态生命周期基线记录精确最终源码与软件证据；物理时序仍未执行。

完整 HAL transport 的接入条件¶

接受基于 Handle 的模式前，为其可能进入的每个 HAL 等待建立能够推进的时源。审查 bootstrap 时钟等待、HAL_GetTick、tick 重新初始化和中断优先级分组。不得让默认 HAL 启动静默取得 SysTick 或改变 OS 策略。公共操作使用同一个绝对单调 deadline，包含排队和准备时间。

启用硬件或调用可能同步触发回调的 API 前，先建立 request 身份与借用引用。回调桥只发布有界事实和可选唤醒提示，不执行任意产品回调。发布结清或允许重入提交前，必须检查完整 HAL 调用栈。HAL lock 不是任务互斥锁，也不能代替控制器所有权策略。

FIG-07 是既有 F407 有限 DMA 参考。DMA 完成、线上完成、HAL 内部就绪与 Nexus 结清仍是不同事实。保留公共所有权合同：abort 或 timeout 启动撤回，不归还存储。provider 最终以 release 发布 SETTLED 前，先撤回全部必要硬件、IRQ 与队列引用。排空失败保留 QUARANTINED 存储和明确恢复责任。循环 DMA 不得覆盖消费者持有的块来模拟进展。

调用方存储的生命周期诊断¶

生成的头提供 nx_platform_diagnostic_t 和可选 nx_platform_start_diagnosed / nx_platform_stop_diagnosed 入口，原 start/stop 入口继续可用。空诊断指针使用原行为；非空指针提供调用方拥有的冷路径输出，不会被保留。它不增加静态注册表、标签或默认实例 RAM。冷路径代码和栈成本仍需要纳入实际链接镜像比较。

phase 与 cleanup_phase 区分 NONE、CONTEXT、SYSTEM、RESOURCES 和 CONTROLLER。controller 阶段携带其在 resolved.json.controllers 中的零基索引，不是各 kind 的 factory ID。SIZE_MAX 表示没有 controller。调用成功清空诊断；启动失败记录主要位置，清理失败时另记录清理位置。既有主要结果、清理结果与剩余效果继续是权威；诊断不执行恢复，也不证明保留的借用已经结束。

比较与替换¶

比较官方与既有实现时，固定芯片、clock、memory、route、mode、capacity、OS、compiler、optimization 和 workload。分别记录 Flash LOAD 与 footprint、各域静态 RAM、调用方存储、预留栈与实测峰值、IRQ/service 行为和清理失败。操作次数与主机耗时不是物理 cycles、latency 或 WCET。

SPI 成本夹具使用未改变的 89485943 Source SDK 链接 0/1/2/4 个 endpoint：开发测量的 LOAD 与 footprint 均为 3,048/7,880/7,940/8,064 B，静态 SRAM 为 72/176/208/280 B，另有 2,048 B MSP，heap 为零。非零配置消费公共 controller 拓扑；四 endpoint 镜像使用三个 CS bank，因此其增量不能作为线性的单 endpoint 成本。这些链接观察不建立时序、HIL 或新源码资格。

I2C 叶操作比较保留 V1 TX 的直接访问，因为已锁定 LL helper 会增加对 DR 的读改写；V2 完整 CR2/ICR 命令也在 vendor helper 使用读改写时保留直接访问。F103/F407 的 ADDR 清除仍使用两次有序的直接读取：独立 ARM 探针测得直接实现为 6 B，LL 为 18 B，且额外使用 8 B 栈。GD470 的高频 byte/ADDR 叶操作在窄范围 SPL 调用及被调用函数比较后保留直接访问；GD303 未选入 I2C SPL C 单元。这些独立编译单元结果不建立整个 provider 的资源、栈峰值、时序或硬件资格。

只有仍需对照或存在未替代维护模式时才保留旧实现。合同与成本验收后，选定一个正常生产实现，删除无用开关和重复状态。专用 LL/寄存器路径需要已证明的语义差距或实测预算依据，不能只笼统声称厂商代码慢。

验证与交付边界¶

新增行为按 RED、GREEN、refactor 实施，并通过正常 commit/CI 门禁。主机 C 测试使用 GoogleTest/GoogleMock，工具测试使用 stdlib unittest。适配合同测试可以 mock 外部端口，然后还要单独执行真实官方代码与适配器。ARM 链接证明所选镜像与资源性质；IRQ 时序、DMA/Cache 一致性、电气行为和长期负载结论需要真实设备。

软件候选仍要求 clean source、精确依赖和配置身份、独立 SDK 消费，以及同产物的两次全新断网构建。迭代检查表或派生工作包报告均不授予这一状态。既有 release tag、附件和原始证据保持不可变。没有连接实板时，HIL 保持 not_executed，不得把纯软件迭代称为产品发布或安全资格。

所选 F407VE/ZG 和 GD470 偏移镜像已有已审查的配置、startup、向量/linker 及 ELF-to-BIN 边界；装配参考区分镜像窗口和完整物理 Flash。这不是启动认证、Flash 访问控制或运行态镜像交接资格。F407 handoff 保留 PRIMASK=1，startup 不主动解除屏蔽；偏移 FreeRTOS 链接不能建立有效 FreeRTOS handoff。

Bootloader 交接、动态变频、deep STOP、更广的 H743 DMA 和通用 U575 跨域 I/O，继续保留SoC 完善台账中各自未实现或部分实现的退出条件。官方驱动不会自动提供这些功能需要的平台合同。
