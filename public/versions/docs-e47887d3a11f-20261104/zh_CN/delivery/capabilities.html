派生能力与接入矩阵¶

本表由 tools/maintenance/capabilities.py 读取维护中的 soc.json、 routes.json、参考 Board board.json，并运行现有软件 assembly 的生产 resolver 和 binding emitter 生成。表格不是另一份配置输入；修改能力从原始事实、实现和 回归开始，随后执行 --write 更新本派生文本，--check 拒绝任何过时内容。

  • Mode 是 SoC 声明的有限模式；无 route 的模式不能据此选择连接。

  • Reviewed SoC routes 描述已维护的芯片路线，不是 PCB 连续性或电气资格。

  • Declared reference Boards 表示 Board 中存在对应 binding，不表示默认 assembly 已启用它，也不表示实板验收通过。

  • Resolver fixtures 是当前实际通过解析的 TOML 软件夹具。

  • Selected production source 从实际生成的 face 读取完整 ops 标识，匹配生产 C 中已初始化的导出定义；注释、字符串、声明和相似前缀不算定义。这是有限源码 一致性证据，不替代编译、执行或物理测量。空白列明确没有该类证据。

native (MODEL; physical=false) 行只投影当前 resolver 实际选择并生成的 Native 软件模型，不声明物理外设数量、引脚、IRQ、Board 路线或实板能力；对应路线与 Board 列因此为空。未选择的主机模型库存不进入本表。

表格不从旧候选继承新 HEAD 的软件资格，也不推断物理结果。三板实物未连接，HIL 保持 not_executed。精确模式限制及所有权合同见支持范围。

python tools/maintenance/capabilities.py --check
python tools/maintenance/capabilities.py --write

查询实际选择与验收阶段¶

全局表适合寻找已有路线；产品是否可用要回到精确装配。从固定源码或 SDK 根目录 执行以下只读查询，选择自己的 TOML。命令正常退出时输出 JSON，不更新下方矩阵：

python tools/maintenance/capabilities.py --assembly tools/configure/assemblies/qiming-baremetal-uart-dma.toml

报告保留 Board、完整料号、封装、后端、时钟、CPU、IRQ、物理 PCB 修订、内存域、 资源所有者和输入哈希。每个 controller 与 endpoint 分别提供已选择的公开合同； 额外公共 face 单列在 companion_interfaces，不伪装成 endpoint。DMA 与引脚来自 本次解析，不从同系列其他路线补齐。上例是 F407ZG 的 USART1 有限 dma-tx 选择，不能扩展为 F407 全外设或全部 UART 模式支持。

validation 分开列出以下阶段。默认查询只执行生产 resolver 和合同投影，不搜索旧 报告，也不运行编译、测试、烧录或测量。因此，下面的 not_assessed 表示本次查询 没有评估该阶段，不表示实现失败或历史上从未执行。

显式关联已封存候选¶

需要核对已有执行证据时，在同一查询追加原候选路径：

python tools/maintenance/capabilities.py --assembly tools/configure/assemblies/qiming-baremetal-uart-dma.toml --candidate /path/to/sealed/candidate.json

工具调用原候选 verifier 核对全部 payload、qualification 和链接产物，不运行新的 测试。报告同时保存 current_source 和 evidence.reference.source，不会用被引用 源码覆盖当前 checkout。evidence.relation 只在干净 commit/tree/submodules 与 精确解析配置全部相同时为 exact_source_and_configuration；此时才把原候选的 四类软件阶段投影为 passed。这是原执行的只读关联，不是本次新执行。

有效候选属于其他源码时标 historical_source，配置不同时标 configuration_mismatch；这两种情况保留当前选择的 not_assessed。原件缺失、 被修改或校验失败会拒绝查询，不能降级为已验证引用。未提供 --candidate 时 无需 Git 或证据观察。可搬移候选需先用现有 artifact 工具恢复原 closure，再提供 其中的 candidate.json；只有包摘要或下载位置不能建立通过状态。

任何软件候选都不改变 physical_hil、physical_qualified=false 或下方聚合表的 family／mode 行。硬件状态仍需要真实 station 和同一镜像的实际观察；一个精确 配置通过不等于所有 Board、backend、时钟或模式通过。
