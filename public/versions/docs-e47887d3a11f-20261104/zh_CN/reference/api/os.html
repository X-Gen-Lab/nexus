bool nx_freertos_isr_allowed(void)¶

检查当前上下文是否允许调用内核 ISR API。

备注

Native POSIX 没有物理 IRQ，返回 false。NMI、故障和内核拥有的异常会在进入 FreeRTOS 前被拒绝。Mainline 的优先级／分组必须遵守系统调用优先级上限。Baseline PRIMASK 端口接受所有可配置 IRQ，不读取 Mainline 优先级分组。Nonsecure 侧权限不排除 Secure 侧访问。

nx_result_t nx_freertos_task_discard_before_scheduler(nx_freertos_task_t *task)¶

在包装函数执行之前，丢弃一个已创建的任务。

备注

仅限一个特权启动生命周期所有者；调度器状态必须为 NOT_STARTED。内核候选任务先被挂起，以在删除前移除内核保留的 TCB 引用。bootstrap 期间不得遗留未配对的 vTaskSuspendAll：NOT_STARTED 无法揭示内核私有的挂起嵌套层数。该调用者前置条件必须在修改前满足。成功后，只有在所有外部使用者均静止时，才允许复用 TCB、栈和上下文。这不会取消或 join 已执行的任务。

参数:

  • task – [inout] 存活、由调用者拥有且未被其他调用者使用的静态任务

返回:

仅在同步内核删除及锁存器清理完成后返回 SUCCESS；控制状态不存在、不完整或已经进入执行时返回 INVALID；ISR、非特权、非规范屏蔽状态或调度器正在运行／挂起时返回 CONTEXT，且不修改状态

nx_result_t nx_wait_select(const nx_wait_port_t *port, const nx_wait_source_t *sources, size_t count, size_t start, uint64_t deadline_us, size_t *selected)¶

按调用者选定的循环优先顺序等待任一 source。

备注

仅任务上下文，遵守 nx_wait_until 的 arm/recheck 和 deadline 合同。每轮扫描从 start 回绕，至多访问 count 个谓词，不分配或保留注册。Source ready 不授予所有权，也不消费事件；调用者必须获取或尝试真实操作。显式推进下次 start 以选择公平性。调用者连接 source 通知到同一 port，维护权威谓词，并在回收状态前停止和 join publisher/waiter。没有隐式 worker、派发、订阅、自动注销或 service。除非调用者 callback 改变 selected，错误会保留它。

参数:

  • port – [in] Source publisher 使用的同一有效单 waiter port

  • sources – [in] 稳定数组，每个 ready callback 非 NULL

  • count – [in] 可读 source 条目数量，非零

  • start – [in] 首个检查索引，严格小于 count

  • deadline_us – [in] Port 时间域内的绝对单调 deadline，或 NX_DEADLINE_NEVER

  • selected – [out] 仅成功时写索引；与 port、sources、其有效 context 及其他借用元数据独立

返回:

观察到 ready 时返回 NX_SUCCESS，包括后端错误后的最终 ready；参数无效或重叠返回 INVALID，跨度不可表示返回 OVERFLOW，或返回 port 错误

struct nx_wait_port_t¶
#include <wait.h>

单等待者通知端口。

调用者拥有存储，并串行执行 arm/wait。各后端文档规定的上下文允许多个唤醒发布者。序列只是提示；谓词／请求才是权威依据。arm 与重新检查之间的唤醒次数必须少于 2^32。所有截止时间均为后端时钟域内的绝对单调微秒时间；NX_DEADLINE_NEVER 显式禁用超时。时钟必须在等待期间连续运行且不得改变时间域；应使用 nx_deadline_after 构造相对预算，避免溢出。超时不会使请求结清或释放缓冲区。销毁前，必须停止并 join 每个发布者和等待者；仅有 SETTLED 不能证明通知存储可回收。arm 快照序列；wait 必须原子地观察序列变化或已锁存唤醒，包括调用者再次检查与睡眠之间发生的唤醒。序列变化不能绕过有限截止时间：wait 在每次调用以及每次从阻塞返回后，都先检查到期，再报告提示。未到期时，非阻塞后端可以返回 BUSY。仅一个所有者可以执行 arm/wait；即使后端会拒绝第二个并发等待，其行为仍位于端口合同之外。
