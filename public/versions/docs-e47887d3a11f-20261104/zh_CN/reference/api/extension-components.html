显式 F407 熵源构造¶

对于 F407 装配，显式调用 nexus_add_stm32f407_entropy(target)，并在产品装配处链接该目标。它拥有唯一静态 RNG 源并拒绝第二个构造器。getter nx_stm32f407_entropy_instance() 返回已有只读接口；不执行启动、寄存器访问或 factory 注册。

Platform 成功启动后，使用准确验证过的 Board/profile hse_hz 和 hclk_hz 事实调用 nx_stm32f407_entropy_instance_start()。实现检查实时 PLL48/HCLK 关系，仅取得其 RNG 时钟门；不配置共享 PLL，也不启动 Platform。经过审查的时钟源选择为 8 MHz HSE 或 16 MHz HSI。产品必须将这些时钟依赖保持到 stop 完成。

在单一特权、未屏蔽中断的串行任务上下文执行 start/stop。在 nx_stm32f407_entropy_instance_stop() 前等待全部熵使用方退出，并要求 stop 成功后才撤回 Platform 时钟。撤回失败时保留同一所有者与清理责任；重试 stop，不重置或重新绑定状态。停止后的接口仍有效，数据调用返回 STATE。此显式构造器与 TOML typed-factory 选择分离；它及软件 RNG 健康检查均不能证明物理最小熵或 HIL。

拒绝时，新请求保持未借用。一旦接纳，配置失败会保留每个复制引用，直到 RTC/WUT 生产者、DMA 主设备／复位、IRQ、门控及时钟恢复均被独立确认静默。保持两个 owner、时钟、缓冲区、工作区及 RUN 屏障存活，且屏障保持关闭。保留状态的恢复期间须保持 PRIMASK=1。recover 重试同一复合链，不执行 WFI。若观察到外部 LPDMA 复位，此链将被永久隔离：静默复位值及复位解除不能证明先前主设备的最终访问。只有外部确立的系统复位才能结束该责任。受污染的时钟可以在硬件排空后以错误结束请求，但绝不能提供新的成功经过时间结果。此处不建立任何旧 TIM2 截止时间、RTOS 补偿、外设 LPBAM 计划或物理复制结果。

备注

此模式仅链接 Nexus::U575Stop2Copy。它与 Nexus::U575Stop2 拥有相同的静态 RUN 域及 WUT/recover 符号；同时链接两个备选实现会被拒绝。仍可调用仅使用 WUT 的 enter，但会拒绝每个保留中的复制借用。完全恢复前须保持 PRIMASK=1。

参数:

  • owners – [in] 精确 RUN 域中已关闭且排空的屏障。

  • copy – [in] 已初始化且不可变的 LPDMA1/channel0 face。

  • request – [inout] 已准备为 READY、位于绑定保留时间域中的复制请求。

  • escape_ticks – [in] 4096..65536 个 RTC/16 节拍，标称 2..32 s。

  • poll_limit – [in] 每阶段使用正数观察预算。

返回:

取得选定 F407 SPI2 工作模式及固定引脚的所有权。

调用方拥有外部主机，并且从初始化或提交之前开始，持续保持 CK 处于空闲 LOW、WS 处于 HIGH，直到以 acquire 语义观察到 ACTIVE。引脚读取只反映采样瞬间，不能证明电气信号持续静止。主机必须恰好传输所声明的完整帧，并在需要下一个尚未提供的数据字之前停止。再次启动时从左声道开始。已预填充时，若取消请求且 CK 仍保持空闲，DR 便无法排空；必须保留处于 QUARANTINED 的存储，直到协调提供的排空时钟允许先观察 TXE，再重新观察 BSY。这种错误排空可能产生欠载，并不保证得到有效的立体声音频或发送完整帧；错误一律报告零传输字节。超时、TC 或 NDTR0 都不能证明线上发送完成或已完成最终访问。调用方还必须按 DS8626 提供有效的工作电压、I/O 电平、负载、CK/WS/SD 时序和 DMA 补充数据裕量。ACTIVE 和引脚采样既不测量这些电气或速率条件，也不构成对它们的验证。

由一个未屏蔽中断的特权任务串行执行所有方法，并串行管理外部所有者的生命周期。所有拒绝路径都必须保留调用前的中断屏蔽状态。不允许从 NMI/HardFault 调用，也不允许其他 DMA/IRQ/引脚所有者、复位或重配时钟的写入方、调试器写入方以及并发 Platform stop 介入。借用期间一旦观察到复位或时钟配置历史丢失，请求就会被永久保留；将寄存器恢复成复位时的样子不能证明此前已经完成最终访问。主 SRAM 对 DMA 可见；CCM 不可见。芯片引脚能力既不能证明 PCB 布线，也不代表已经完成编解码器或电气 HIL 验证。实际的 F407 及封装身份由装配配置和测试夹具确定：仅凭共用的器件组标识和容量读数，既不能区分 F405 与 F407，也不能验证物理封装。

所选单镜像配置仅支持永久更新请求。此 API 不下载或校验镜像、不复位硬件、不确认试运行镜像，也不提供回滚。应用负责授权、有效候选字节、维护调度、平台生命周期和复位策略。作者 Nexus Team

函数

nx_result_t nx_mcuboot_query(nx_mcuboot_action_t *action)¶

查询上游对镜像零的计划动作。

备注

仅限 task／boot 上下文。调用方串行化访问，为整个调用提供不可变 Flash operation hook 及其有限 deadline。所有被引用的 area、region、时钟与 provider 持续存活至返回。固定上游 API 将不可读的 secondary trailer 视为空，因此 NONE 不能证明 secondary 可用或镜像有效。

参数:

  • action – 仅在成功时接收值；不保留该指针。

返回:

已知动作返回 NX_SUCCESS，NULL 返回 NX_ERROR_INVALID，上游 PANIC、未知值或报告的读取错误返回 NX_ERROR_IO。

nx_result_t nx_mcuboot_request(nx_mcuboot_request_t request)¶

使用上游公共 trailer API 请求永久更新。

备注

沿用 query 的串行化、有限 operation 与生命周期合同。返回时当前 Flash 访问已结清；超时不是中止物理脉冲。该调用不证明候选真实性、不承诺恢复旧镜像、不续期 deadline、不停止基础设施，也不复位 MCU。

参数:

  • request – PERMANENT 请求更新；TEST 无访问即拒绝。

返回:

上游完成且读回报告 PERMANENT 后返回 NX_SUCCESS；TEST 返回 NX_ERROR_UNSUPPORTED，未知请求返回 NX_ERROR_INVALID，读回其他已知动作返回 NX_ERROR_STATE，上游错误返回 NX_ERROR_IO。部分持久 trailer 修改后仍可能返回错误，包括不能悄悄提升为永久更新的 pending TEST。
