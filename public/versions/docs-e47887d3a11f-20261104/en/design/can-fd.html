CAN FD with fixed physical RAM and explicit request ownership¶

Use this contract to assemble and execute the exact STM32G474RET6 FDCAN1 software reference. It offers iso-fd-normal for external communication and iso-fd-loopback for internal silent loopback, both at nominal 500 kbit/s and data 2 Mbit/s from HSE 24 MHz. These are separately selected software modes. Neither mode establishes a populated transceiver, measured clock accuracy, external ACK, termination or physical timing qualification. HIL remains not_executed.

Select a separate static interface¶

FIG-16 describes shared current mechanisms, not a CAN bus timing diagram. Here the selected face is nx_can_fd_port_t, the compact lookup is nx_factory_can_fd, and the runtime provider owns FDCAN1 and its fixed message RAM. Generation arrows, lookup arrows and runtime calls keep their original meanings. Lookup neither reads hardware nor starts a transmission.

The normal fixture and loopback fixture use the same software Board and physical claims. The strict resolver selects one mode, validates exact rates, masks, ring capacity and IRQ policy, then publishes immutable typed IR and one generated bundle. Conflicting controller, shared FDCAN configuration, message RAM, vector and pad claims are rejected. The Board records silicon PA11/PA12 AF9 routing; its physical PCB revision, oscillator population and external PHY are unknown.

Prepare, admit and prove physical completion¶

Initialize request metadata once, then use nx_can_fd_tx_prepare to copy a whole frame and an absolute deadline in the selected monotonic domain. Preparation retains no frame pointer. Submission from the sole task executor validates the whole value, physical queue index, deadline and storage disjointness before admission. A rejected call leaves the request unborrowed and performs no transmit RAM writes or add request.

ACCEPTED borrows the complete request until acquire-observed SETTLED. The provider packs the exact DLC and payload into the selected physical element, then publishes TXBAR after a barrier. No software queue changes the hardware identifier arbitration order. Existing requests cannot become another call’s output or wake storage. Public face/table identities, private controls, peer registers, shared RAM and SCS/NVIC controls are also protected from output aliases.

FIG-06 supplies the shared ownership states. ACCEPTED and REJECTED are admission results. In this provider, source withdrawal means both TXBAR and TXBRP are clear for the slot, followed by a fresh TXBTO or TXBCF observation. An empty slot alone, a latched interrupt alone or a stale prior completion cannot release the request. A hardware add scan may keep TXBAR set while TXBRP still reads zero.

TXBTO proves successful transmission and reports the actual payload byte count. It can win a cancellation race, even when TXBCF is also set. TXBCF without TXBTO proves completed cancellation or an unsuccessful DAR attempt; an explicit cancel reports CANCELLED, and an unsuccessful ordinary attempt reports IO with zero transferred bytes. A missing external ACK does not trigger software replay. Bus retry and protocol recovery policy belong to the external product.

Cancel, timeout, bus-off and stop request physical cancellation. They never revoke the existing loan. A failed drain deadline leaves the request QUARANTINED, the slot retained and stop/recover/domain release blocked. Later physical proof may still permit settlement. The executor must continue bounded service; a wake hint does not supply execution progress.

Receive, recover and close the owner¶

An IRQ or explicit service call processes at most three transmit slots and the initial three elements in each receive FIFO. Copied receive values retain ESI as observed transmitter state. FD DLC15 means 64 B; classic DLC9..15 normalizes to 8 B with an explicit flag. The event’s acquisition time is not SOF, and a disabled hardware timestamp is never promoted to physical bus time.

The caller-sized event ring does not overwrite older records. Software loss counts and hardware-loss lower bounds remain distinct. Pending loss follows older records and precedes newly retained frames. Bus-off, error counters and last-error state are latched separately from ring fullness. Only actual enabled line0 imposes a syscall ceiling on wake binding; disabled reserved line1 does not become an additional kernel publisher. A rejected binding preserves the earlier sink.

Explicit recovery requires every transmit loan and notification publisher to drain. It reenters initialization without replay, shared reset or reassignment of the message RAM lease. The immutable mode stays normal or loopback across recovery. Bus-off recovery timing still depends on actual controller and bus progress; returning from configuration does not measure the required bus idle.

Stop closes admission, drains slots, disables peripheral sources, joins line0 and only then enters acknowledged INIT. A final PSR/ECR snapshot precedes CCE, which can destroy hardware outcome facts. Successful controller stop ends its request/ring/wake loans; any failure preserves incomplete leases for retry. Platform then releases the domain and restores outer pad/gate/system ownership. External adapter observers still need their own join before storage reuse.

Sources and software qualification¶

The authoritative API is can_fd.h, with the shared request contract. The private provider uses pinned official FDCAN definitions and direct volatile MMIO. It does not link HAL driver C, HAL_GetTick, HAL handles or MSP callbacks into this implementation. The G4 source lock preserves the exact selected headers, paired CMSIS identities and original licenses.

Reviewed hardware references are RM0440 Rev9, DS12288 Rev6 and ES0430 Rev9. RM0440 defines the fixed message RAM, queue and cancellation proof, including unsuccessful DAR attempts. Its TEST.RX bit is read-only pin state: configuration readback checks owned LBCK/TX controls and must allow a recessive RX bit. EFBI0 and the absence of mixed dedicated/FIFO transmission avoid the selected FDCAN errata conditions; they do not qualify every silicon limitation.

Common contracts, real provider register/event tests and both generated-factory selections exercise the actual C implementation. GoogleMock observes external MMIO/IRQ effects. Models cover external ACK/no-ACK, cancellation races, fixed RAM, read-only status, input/output isolation and retained shutdown. Generated tests execute actual system startup with one shared RCC/TIM2 model, then the normal TOML/factory path; they do not hand-set Platform readiness.

Actual execution and source identities belong to the delivery evidence. Host models and any separately recorded ARM links do not establish physical ACK, error injection, bus-off recovery time, oscillator envelope, throughput, IRQ latency or WCET. Normal mode still needs an inspected transceiver circuit, safe electrical connection and independent HIL evidence before physical deployment qualification.
