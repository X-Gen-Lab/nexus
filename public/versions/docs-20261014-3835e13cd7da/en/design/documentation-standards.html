Nexus 文档内容与图示标准¶

本标准用于新增和修改的平台文档。目标是让读者明确任务、条件、操作和结果， 能够沿文档完成使用、接入、维护或验收。既有页面按 实施台账逐批审查；本标准的存在不表示 正文迁移、图册、自动检查、翻译或发布已经完成。

必须/不得表示合同要求；应/不应表示默认做法，例外需有理由；可以表示允许的 选择。规范性要求必须明确主体、条件、动作和可检查的结果。责任由 Codex 承担， 独立 agent 进行内容和图示评审，不要求虚构人员账号。

2. 术语、单位和约束¶

首次出现可给中英文对应，随后同一概念使用同一词。C符号、配置键、错误码、 结构字段、CSV/JSON值和版本ID保持原样，不翻译标识符。必须区分：

术语

本文档体系中的含义

factory

返回该装配已有静态接口的typed查找

face

公共只读接口，含ops和实例context

provider

具体实现及私有状态

controller/endpoint

控制器身份与其逻辑/外部端点身份

owner/executor

资源/生命周期责任与实际执行推进责任

request/buffer

请求元数据与被借用的数据存储

DMA complete

DMA阶段完成，尚需外设和引用排空

wire complete

外设线上传输完成，尚需满足其余结束条件

SETTLED

provider最终访问后release发布；调用方acquire观察

QUARANTINED

未安全结束，借用和恢复责任仍保留

所有容量和测量写单位：B/KiB、Hz/MHz、cycles、µs/ms。Flash LOAD、Flash footprint、预留RAM和实测栈高水位分别记录。对齐、长度粒度、inclusive limit、 溢出、deadline时间域和最大配置须明确。理论上界、估计和实测值不能混写。

有效约束示例：ACCEPTED后，调用方必须保持请求和缓冲区有效，直到acquire观察 SETTLED；复用相关adapter/observer存储还需对应引用排空。无效表述示例： “注意生命周期”。后者缺少主体、结束条件和失败责任。

4. 示例与命令¶

完整例子必须来自维护fixture或固定版本外部示例，并关联实际consumer验证。 优先literalinclude；省略部分注明fragment原因。不能把示意片段称为完整教程。 普通构建不自动刷写、不执行任意Markdown命令，也不取得远程latest。

每个命令说明工作目录、工具和连接前提、输入、预期结果、检查成功方法、清理。 固件C示例遵守现有C11、80列、四空格、附着大括号、类型侧指针和反斜杠 Doxygen风格。工具及测试示例遵守对应语言规范，包括现有Python工具和C++17 GoogleTest/GoogleMock用法。文档规则不重新定义仓库代码风格。

异步例子必须说明拒绝、接受借用、执行推进、等待、取消、排空及结束后资源。 timeout/cancel不自动撤销借用；失败停止保留QUARANTINED存储。唤醒只是提示， 不能用无限等待掩盖推进条件。产品任务、私有分区和恢复政策仍属于外部工程。

每张图至少有ID、名称、用途、类型、适用范围、关系图例、正文合同和来源。 ID用于目录和迁移；公共anchor使用标准显式target/label，不能依靠front matter 自动产生引用。图源与输出登记在 图册清单。

节点名对应源码、接口或明确概念；可选项必须有文字或线型标记，不能只靠颜色。 返回箭头、异步事件、状态迁移的方向准确。图不会因美化增加不存在的CPU factory、 隐藏任务、统一池或强制OS层。

状态图中REJECTED/ACCEPTED是admission结果，不伪造为nx_request_state_t状态。 SETTLED只在全部必要引用排空后发布；取消/deadline不能直接指向“存储已释放”。 QUARANTINED到结束必须有实际恢复/排空证明，不暗示每个provider都有恢复API。 时序图必须包含相关失败分支或链接独立失败图，并标清Task/IRQ/DMA/安全域。

7. 图源、视觉和离线交付¶

首批采用可编辑Graphviz DOT和本地SVG，图源与输出成对保存。Sphinx后续可用 内置graphviz扩展；新图链及工具锁仍按DOC-25/33实施。既有Mermaid作为迁移输入， 不能另维护同一图的第二份权威源。需要时序专用工具时，以实际需求另行审查闭包。

每张图同时满足：

  • 图源可审查，图名/ID稳定；图源变更后重新生成输出。

  • 深色文字与清楚边界；颜色不是唯一含义，灰度下仍可区分。

  • 标签短且具体，复杂说明放正文；过密时拆图，不缩小到无法阅读。

  • 中文、英文、C符号完整，无缺字、重叠、裁切和模糊截图。

  • 提供alt和caption；窄屏可以放大或独立打开SVG，不把整图强制缩成小字。

  • SVG默认无脚本、动画、foreignObject、外部href/资源及DOCTYPE。

  • 图和图源随离线包交付，加载、字体说明与检查不依赖CDN。

  • Graphviz及实际字体进入文档工具闭包，缺失或差异不伪称已验证。

SVG解析和渲染成功不证明架构正确。独立审查必须逐边核对调用/依赖、状态和 失败责任。实际显示需要检查桌面、窄屏/放大和打印；未执行项保留未验证状态。
