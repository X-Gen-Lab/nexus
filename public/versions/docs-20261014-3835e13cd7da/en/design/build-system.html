Build system maintenance contract¶

Nexus uses one authored TOML assembly, a validated immutable configuration IR, static instances and typed factory, and one CMake software target graph. Ninja executes the declared graph. Products own application sources and composition.

The 48-item execution ledger preserves the requested exit conditions. Implementation, executed software verification, environment distribution and physical acceptance have distinct evidence. Historical source qualification does not qualify changed build tools.

Configuration publication is a single-writer transaction. It protects every authored and fact input before changing owned output. A rejected or interrupted attempt cannot expose the previous configuration as current. Successful identical generation preserves file content and timestamps so ordinary reconfiguration does not force unrelated compilation. A configuration digest is not a compiler or generator-source identity.

CMake owns source lists and target dependencies. The resolver emits selected facts and its configuration-code dependencies, never a parallel software build graph. ABI, optimization, diagnostics and firmware link policy have explicit target boundaries. The firmware target guarantees its declared delivery outputs and resource check. External application warnings are a consumer policy.

Developer presets and native CMake/CTest remain the normal build interface. Focused tests are development feedback. Commit gates and formal qualifications execute their complete declared suites with fresh reports. All runners preserve actual command exits, bounded concurrency, deadlines and process cleanup.

Preparation may retrieve dependencies. Formal reproducibility uses two fresh network-disabled builds with the same verified source SDK and recorded environment and toolchain bytes. Compiler caches improve development only; they cannot prove fresh-build reproducibility. Durable evidence stores retain original records, member identities and failed attempts without changing their historical status.

Behavioral fixes use actual RED then GREEN execution. Python tools use unittest; C/C++ contracts use the pinned GoogleTest/GoogleMock host framework. CMake graph and policy defects require real small consumer builds and artifact observations. Firmware stays C11 and contains no host test runtime. Normal commit hooks and independent review apply to this maintenance work.

The following support matrix records observed host tools and declared locks. The final clean-source software gates and eight exact offline candidates are recorded in the execution record. Host observations retain their own scope; source qualification uses the recorded code commit and never follows a later documentation HEAD automatically.
