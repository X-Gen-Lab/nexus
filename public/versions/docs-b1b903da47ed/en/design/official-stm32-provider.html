Official drivers and provider iteration¶

Use this contract when changing a SoC provider or integrating an official driver. Nexus keeps static assembly, typed factories and public C11 I/O contracts. Official HAL/LL code is private implementation input. This page defines the integration boundary and work-package exits; it does not qualify every external library, maintained mode, source revision or physical board.

FIG-01 remains the current responsibility diagram. Reusing official code changes the private SoC implementation, not the public dependency direction. FIG-03 in the architecture explanation shows the existing build-time generation path. Neither diagram implies a new runtime registry, HAL manager, default worker or mandatory OS layer.

Vendor-first target and current implementation¶

Official hardware libraries are the default input for further provider work. Reuse reviewed HAL transport when it satisfies the complete selected mode; otherwise bind suitable LL or SPL primitives to the required bounded mechanism. Nexus retains admission, borrowed storage, deadlines, result publication and resource responsibility. Direct register helpers remain justified exceptions for an exact SDK gap, erratum, atomic operation or demonstrated budget.

The selected F407 UART dma-tx provider uses official HAL finite TX with a disjoint LL IRQ receiver under one private owner. Other F407 UART modes retain their existing engines; G4, H7 and U5 retain their reviewed LL integrations. GD32F470 compiles selected official SPL C units. Source selection, model tests, ARM links and physical execution remain separate evidence. An include, primitive call or finite-TX fixture alone does not establish a complete transport or family qualification.

The existing delivery-completion ledger appends V-A01 through V-L08, V-P01 through V-P06 and V-X01 through V-X04 while preserving the older rows and frozen results. Each new row starts with its real implementation, software and physical status; a plan has no execution evidence. The derived ledger view uses the same renderer. No second support or completion database is introduced.

Fixed clock admission¶

The reviewed software-trim gates run in cold preflight. An unexpected adjustment in a gated profile is rejected before the startup transaction writes hardware or acquires resources. Factory calibration remains independent and unchanged; admission does not retune an oscillator. These checks add no work to the normal I/O call path and establish no measured clock accuracy or physical timing qualification.

F103 HSI8 and GD303 IRC8 require adjustment 16 in RCC_CR.HSITRIM and RCU_CTL.IRC8MADJ, respectively. H743’s exact-revision-V HSI admission requires RCC_HSICFGR.HSITRIM=64; older fixed nominal profiles retain their existing revision-specific boundary. U575’s selected MSIS4 range requires RCC_ICSCR2.MSITRIM1=16; its separate I2C1 HSI16 gate continues to require RCC_ICSCR3.HSITRIM=16. The U575 selection follows the pinned official HAL/CMSIS range-to-trim mapping and reset definitions.

F407 HSE8/PLL168, GD470 HXTAL25/PLL200 and G474 HSE24/PLL170 retain their external primary clocks. Their internal-clock admission checks are RCC_CR.HSITRIM=16, RCU_CTL.IRC16MADJ=16 and RCC_ICSCR.HSITRIM=64, respectively. They constrain the nominal bootstrap and fallback clocks; G474 also uses HSI16 for the selected I2C1 kernel. The G474 default of 64 follows RM0440 Rev9, section 7.4.2, and the pinned HAL definition; the LL comment stating 16 is stale.

Production promotion gates¶

The selected F407 dma-tx implementation preserves the complete mode, including IRQ RX bytes/events, frame/error/loss ordering, timestamps, wake and storage. HAL owns finite TX DMA, the UART TC completion sequence and transmit abort; the private provider owns their integration with the disjoint LL receiver and Nexus lifetime. The older serialized finite-TX reference remains evaluation evidence for its narrower contract, not the production mode’s qualification. Other modes require their own complete evaluation before replacement.

The serialized reference’s hal_depth IRQ guard is not an MCU preemption design. Production must establish allowed HAL nesting, short guards, pending-fact handling and real IRQ service ordering. Do not mask all interrupts around vendor calls that may wait. An abort callback can run synchronously in task context; bridges record bounded facts and use notification permitted in the actual context. Product callbacks and final settlement do not run arbitrarily inside vendor callback stacks.

A Handle-only callback does not carry a request epoch. Before Handle reuse, prove withdrawal of the previous hardware, IRQ and callback references; stamping the current epoch onto a late callback is not proof of association. Establish admission before a vendor call can retain references, and treat a startup error after admission as accepted work requiring explicit withdrawal.

Review every reachable vendor wait, including bootstrap/runtime progression, millisecond quantization, 32-bit tick wrap and low-power suspension. Initial UART work keeps the existing system-clock and OS startup choices. Selected HAL modules do not authorize default SysTick acquisition or interrupt-policy changes. UART/SPI uint16_t Size parameters must match the selected public size_t contract without truncation, hidden splitting or implicit bounce storage.

SPI evaluation preserves the whole CS interval, dummy/discard, fixed DMA addresses and counts. GPIO needs one combined set/reset command; selected U5 GPIO commands now use private HAL_GPIO_WriteMultipleStatePin with the admitted GPIO source closure. Separate set/reset calls cannot substitute. DMA disable still needs actual readback and withdrawal proof before returning borrowed storage.

Inspect each completion stack: F4 SPI DMA may wait for TXE/BSY; H7/U5 EOT hardware close must preserve the selected quiet interval before disabling the shifter. U575 HAL also contains its Device-gated persistent-DMAT workaround. These API fits do not prove callback, deadline or loan withdrawal; review ordinary LL/SPL setters separately from justified command/snapshot exceptions.

Selected F407 HAL UART transport¶

The same authored dma-tx mode selects a static private owner, immutable cold configuration, one UART_HandleTypeDef, one DMA_HandleTypeDef and a shared readonly Nexus ops table. The factory still returns the existing Nexus face; neither vendor types nor callback registration become a public interface. The private callback ABI sets USE_HAL_UART_REGISTER_CALLBACKS=1 consistently for the adapter and selected official C units. TX completion/error/transmit-abort/MSP and TX half-transfer callbacks are explicitly bound per Handle, without a global product callback override or runtime controller registry.

One provider owns both UART behavior domains. The LL receiver consumes RX status/data once, then temporarily masks RXNE/parity/error enables while HAL_UART_IRQHandler observes TX facts. HAL receive state remains idle, RX buffer/size/count and hdmarx remain empty, and DMAR stays clear. This prevents HAL error/abort paths from claiming the IRQ receiver. An unexpected receive domain or Handle/route identity change closes admission and retains quarantine; it does not adopt or abort a foreign DMA owner.

Admission establishes the request and payload borrow before a HAL call can retain them or invoke a synchronous callback. Callbacks latch bounded facts; task service alone withdraws transfer pointers and publishes final settlement. DMA completion still differs from UART TC and from full reference withdrawal. Cancel, timeout and deinitialization failures retain the request or cold lease until the same owner proves actual drain. Stop checks peripheral enables, DMA addresses/counts and pending/active IRQ references before releasing pins or clocks. A Handle is reused only after this withdrawal; official HAL_DMA_Init restores the reusable idle state where required, without assigning READY by hand.

The production IRQ gate saves the incoming CPU mask for short state changes. If a relevant UART/DMA IRQ preempts a task HAL call, it disables only that selected vector, leaves its hardware fact pending and restores the vector when the retained HAL stack exits. It does not spin or let a level IRQ tail-chain indefinitely inside that task call. Every HAL_DMA_IRQHandler entry requires EN readback clear, including an IRQ with only HT or no observed error: an error can arrive after a flag snapshot. While EN remains set, an HT-only event is acknowledged and HTIE disabled with official primitives; its registered private no-op callback is not invoked and no transfer state advances. Observed errors or inconsistent terminal facts withdraw DMAT and request disable once. Refused disable masks that DMA vector and quarantines the borrow; task service retries and dispatches HAL only after EN is clear. This excludes the pinned handler’s SystemCoreClock/9600 wait (17,500 iterations at 168 MHz) from the selected IRQ path. This is a bounded-path design, not measured interrupt latency or WCET.

The target-private compile profile replaces CMSIS exclusive-retry RMW macros with one saved-mask word update. This profile requires a single CPU owner of the aligned UART control words and no NMI, fault/panic logger or other writer. It preserves the incoming mask and leaves vendor source unchanged. The same profile uses nearest OVER16 BRR rounding with overflow-safe quotient/remainder; cold validation rejects zero baud or an out-of-field divisor before UART enable. It does not grant dynamic clock or arbitrary format support.

Only the selected HAL UART/DMA/RCC source units enter the provider’s private build. HAL_Init, HAL_InitTick and a HAL SysTick handler are not selected. HAL_GetTick reads uint32_t milliseconds modulo 2^32 from the existing live TIM2 epoch; bootstrap retains its separate finite polling limits. SystemCoreClock follows the last confirmed 16 MHz HSI or 168 MHz PLL observation, including partial startup and cleanup failures. Official RCC frequency getters use the selected prescaler tables rather than a fabricated constant clock.

The actual adapter/official-source model and clock tests establish their recorded software scope. Generated factory execution, selected ARM/SDK links, stack/cycle comparisons and the complete current-source gate remain separate exits. Physical IRQ latency, wire timing and long-load HIL are not executed without connected equipment. Do not infer a resource improvement from vendor reuse or a passing model.

Build-time provider contract¶

Each constructor returns the frozen Construction record from provider common contracts. It names state_type, definitions, initialize, stop, retain_on_failed_init, exports and pin_snapshots. The common emitter consumes these decisions rather than reconstructing state types or failed-init responsibility from a family name. initialize is an immutable DirectCall; stop is a tuple of these calls. Arguments are explicit static Symbol or Address values, uint32 constants, booleans, NULL, or nested direct calls such as absolute-deadline construction. Free-form expressions, casts, assignments and function-pointer/member-call expressions reject. definitions, exports and face_definitions remain C source strings for declarations, static configuration, storage, faces and fixed forwarding. Concrete C adapters own hardware algorithms. The real C compiler establishes symbol and parameter types. This is a narrow Python generation contract, not a complete C AST; these Python records introduce no additional runtime metadata or dispatch into the MCU image.

The family owns numerical limits, supported modes, exact routes and construction semantics. The resolver owns strict fields, immutable inputs and resource conflicts. CMake owns source selection and target dependencies. Preserve these separate authorities: generation must not create a second source build graph, and a syntactically valid configuration must not imply unimplemented hardware.

Selected immutable I2C V2 configuration¶

The selected G474, H743 and U575 polling I2C V2 providers separate the private nx_i2c_v2_config_t from nx_i2c_v2_state_t. The generated readonly configuration holds register/reset addresses, the reset mask, timing, finite polling budget and the explicitly selected BERR and one-byte RX reload quirks. Zero-initialized runtime storage keeps a configuration pointer and initialized, retained, active and fault state. Public faces, shared ops and factory lookup stay the same. This split is not a measured Flash or RAM saving.

The private nx_i2c_v2_bind runs under the serialized privileged task owner with interrupts unmasked. It validates the configuration and rejects overlap with runtime or hardware storage. An initialized, retained or active owner rejects rebinding without mutation; successful binding itself has no hardware effects. The immutable configuration must live as long as its runtime owner; successful stop releases hardware ownership but preserves the binding. Do not reset a live owner merely to replace its configuration.

Concrete G474/H743 i2c_prepare entries bind first, then prepare pins and initialize the engine. U575’s separate mutable clock owner rejects a retained clock before binding, and acquires the selected clock before engine initialization. Its i2c_close stops the engine first; it releases the clock only after that stop succeeds. Failed drain retains the relevant runtime and clock responsibility for explicit cleanup or retry.

The family emitter now supplies static configuration and calls these concrete C entries. The existing Construction record and generated Platform still order C calls for resource phases, controller starts and reverse cleanup. Other maintained peripheral modes use their own family static bindings and concrete C preparation; this does not move every platform lifecycle into a new common abstraction.

See the private shared contract and the U575 integration for exact parameters and failure ordering. The refactor ledger separates focused software evidence, final linked cost comparison and physical execution.

Conditions for full HAL transport¶

Before accepting a Handle-based mode, establish a progressing time source for every HAL wait it can reach. Review bootstrap clock waits, HAL_GetTick, tick reinitialization and interrupt-priority grouping. Do not let default HAL startup silently acquire SysTick or change OS policy. Public operations consume one absolute monotonic deadline, including queue and preparation time.

Establish request identity and borrowed references before enabling hardware or calling an API that can invoke a callback synchronously. Callback bridges publish bounded facts and optional wake hints; they do not execute arbitrary product callbacks. Check the complete HAL call stack before publishing settlement or allowing reentrant submission. A HAL lock is not a task mutex or a controller ownership policy.

FIG-07 is the existing F407 finite-DMA reference. DMA completion, wire completion, HAL internal readiness and Nexus settlement remain different facts. Preserve the public ownership contract: abort or timeout starts withdrawal; it does not return storage. Detach every required hardware, IRQ and queue reference before the provider’s final release-publication of SETTLED. Failed drain retains QUARANTINED storage and an explicit recovery obligation. Circular DMA must never overwrite a consumer-owned block to emulate progress.

Caller-owned lifecycle diagnostics¶

Generated headers expose nx_platform_diagnostic_t and the optional nx_platform_start_diagnosed / nx_platform_stop_diagnosed entries. The original start/stop entry points remain available. A null diagnostic pointer uses the original behavior; a nonnull pointer supplies caller-owned cold-path output and is never retained. It adds no static registry, labels or default instance RAM. Cold code/stack cost still belongs in the linked-image comparison.

phase and cleanup_phase distinguish NONE, CONTEXT, SYSTEM, RESOURCES and CONTROLLER. A controller phase carries its zero-based index in resolved.json.controllers; it is not a per-kind factory ID. SIZE_MAX means no controller. Successful calls clear the diagnostic. A failed start records the primary location and, if cleanup fails, a separate cleanup location. Existing primary result, cleanup result and remaining effects remain authoritative; diagnostics neither perform recovery nor establish that a retained borrow ended.

These link observations do not establish timing, HIL or new-source qualification.

The I2C leaf comparison retains direct V1 TX because the pinned LL helper adds a DR read-modify-write, and retains V2 full CR2/ICR commands where vendor helpers use read-modify-write. F103/F407 ADDR clear remains two ordered direct reads: isolated ARM probes measured 6 B direct versus 18 B LL and 8 B extra stack. GD470 hot byte/ADDR leaves retain direct operations after the narrow SPL call/callee comparison; GD303 has no selected I2C SPL C unit. These isolated translation-unit results are not whole-provider resource, stack-peak, timing or hardware qualification.

Retain an old implementation only while it provides a needed comparison or an unreplaced maintained mode. Select one normal production implementation after its contract and costs are accepted; remove unused switches and duplicate state. A dedicated LL/register path is justified by a demonstrated semantic gap or measured budget, not by a general assertion that vendor code is slow.

Validation and delivery boundary¶

New behavior follows RED, GREEN and refactor with the normal commit/CI gates. Host C tests use GoogleTest/GoogleMock; tool tests use stdlib unittest. Mock an external port when checking the adapter contract, then separately execute real official code with the adapter. ARM links establish selected image/resource properties. Real equipment is required for IRQ timing, DMA/Cache coherence, electrical behavior and long-load conclusions.

A software candidate still requires clean source, exact dependency/configuration identity, independent SDK consumption and two fresh network-disabled builds of the same artifacts. No iteration checklist or derived work-package report grants that status. Existing release tags/assets and original evidence remain immutable. Without connected boards, HIL stays not_executed; do not call a software-only iteration a product release or safety qualification.

Selected F407VE/ZG and GD470 offset images now have reviewed configuration, startup, vector/linker and ELF-to-BIN boundaries; the assembly reference distinguishes their image window from complete physical Flash. This is not boot authentication, Flash access control or running-image handoff qualification. The F407 handoff retains PRIMASK=1 and startup does not unmask it; an offset FreeRTOS link cannot establish a valid FreeRTOS handoff.

Bootloader handoff, dynamic reclocking, deep STOP, broader H743 DMA and generic U575 cross-domain I/O retain their separate unimplemented or partial exits in the SoC refinement ledger. Official drivers do not automatically supply the platform contracts for these features.
