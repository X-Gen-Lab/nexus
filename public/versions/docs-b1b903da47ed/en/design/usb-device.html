USB FS device packet ownership and integration boundaries¶

The public interface is nexus/io/usb_device.h. The current slice provides internal-PHY full-speed device PIO mechanisms for Native, STM32F407 and GD32F470, with actual SDK bindings. Its maintained scope covers EP0 control, explicitly selected EP1–EP3 bulk IN/OUT and interrupt IN, SETUP/reset/suspend/resume facts, STALL, SET_ADDRESS, cancellation and exit. One DCD request remains one packet no larger than MPS. A separate optional activation face explicitly controls nonzero endpoint active state and interrupt masks. The external Chapter 9 owner supplies SET_CONFIGURATION, configured readiness and rollback; packet mechanisms alone do not prove complete enumeration or physical reset recovery. Optional Nexus::USBControl composes EP0 multipacket DATA, necessary ZLP and STATUS; the separate Nexus::USBDescriptors validates external descriptor structure. Neither creates tasks or allocates memory. External projects supply class dispatch, descriptor bytes and lookup, VID/PID, strings, configuration and recovery policy. Optional Nexus::USBACM composes only the CDC ACM control subset below; it provides no data pump or complete CDC/HID class stack, nor Host, HS, DMA, ISO or remote wake support.

Objects, resources and clocks¶

Controller and endpoint retain separate identities; public faces contain only read-only ops and context. Assembly owns one controller, exact endpoint array, exact event ring and an explicit 48 MHz clock owner. Instances share read-only tables without global mutable registries, maximum endpoint pools, hidden workers or mandatory OS. Unselected instances create no state, and MCU hot paths use direct volatile MMIO. Model builds replace only external MMIO/NVIC leaves; MCUs carry no model-function tables or runtime-simulation branches.

Both SoCs use USBFS base 0x50000000, four IN / four OUT directions, a 320-word FIFO and IRQ 67. Bindings validate actual offsets, strides, capacity and W1C/read-only bits against locked SDKs. EP0 MPS is fixed at 64 bytes; bulk MPS may only be 8/16/32/64. Interrupt mode selects only EP1–EP3 IN with MPS 1–64 B, including non-power-of-two lengths such as 10 B; interrupt OUT and ISO are not integrated. RX FIFO requires at least 64 words and each selected IN FIFO at least 16 words. Partition validation rejects overlap or totals exceeding 320 words. Invalid direction, type, MPS, FIFO or duplicate-identity plans are rejected before clock validate/retain or MMIO.

These existing DCD sizes exclude the optional ROM profile, EP0 adapter and caller-provided outer request; the added components’ Flash/RAM costs require separate confirmation using an ARM ELF built from the same source and the actual ABI. Private endpoints replace the former single-byte bulk with uint8_t transfer, adding no interval, scheduling or queue fields. The selector remains one byte; host sizeof or historical probes do not substitute for ARM cost measurements of the new image.

Selected ROM profile and descriptors¶

The read-only profile in nexus/io/usb_profile.h binds existing controller/endpoint faces and the selected direction, type, MPS, FIFO, 48 MHz, internal PHY, FS device and PIO facts. The generator emits the profile, exact endpoint array and nx_factory_usb_profile getter only when USB is selected and factory.capabilities = true. With false, it emits none of these objects or the getter; ordinary USB faces, method tables, provider contexts and existing generic capability types do not grow as a result. The getter neither initializes hardware nor discovers new endpoints. Assembly adds the value "interrupt" to the existing transfer field; immutable IR and public profile fields remain unchanged. Public NX_USB_PROFILE_INTERRUPT has enum value 2, whereas USB wire/register EPTYP is 3. The provider explicitly maps the types rather than casting between them.

nx_usb_profile_validate checks selected facts read-only; it cannot prove actual clocks, PCB, VBUS or enumeration. External descriptors reach nx_usb_descriptor_validate through nx_usb_descriptor_view_t: device, configuration and string views must be complete. Validation checks lengths/totals, EP0 MPS, unique interfaces, alternate zero, and the correspondence of bulk/interrupt IN endpoint direction, number, type and MPS with the selected profile. An interrupt descriptor’s bInterval must be a linear count of 1–255 full-speed 1 ms frames; zero is invalid. External descriptor bytes alone own it: it is not copied into TOML, IR, profiles or provider state. DCD neither schedules host polls nor promises actual intervals; existing bulk interval handling remains unchanged. A selected-type mismatch, a described endpoint absent from the selected profile or an MPS mismatch returns INVALID. Interrupt OUT, ISO, nonzero control and alternate settings remain UNSUPPORTED; invalid reserved fields remain INVALID. Class-specific subordinate records are bounds-checked without decoding class semantics.

Descriptor validation scans the full supplied length without reading hardware, copying descriptors or retaining them; passing establishes structural validity only. Descriptor selection, request handling and class content remain external policy. Once sent, descriptor/reply bytes must remain valid and unchanged until the outer request’s SETTLED is observed with acquire semantics.

The profile, endpoint array, face/ops, adapter, request and view/snapshot metadata must have the natural alignment of their C types, and address ranges must not wrap; invalid alignment is rejected before typed access. Descriptor bytes require only byte alignment. Numeric checks do not establish accessibility of arbitrary addresses or opaque private contexts; callers must still supply valid readable/writable storage and keep it valid.

Packet completion and control epochs¶

Prepare never accesses payloads; rejected admission retains no new references. ACCEPTED borrows requests and payloads until acquire-observed SETTLED. Requests, payloads, outputs, counts, immutable clock ops and wake targets are checked against controller/endpoint/ring/clock state and existing loans for overlap. Rejected state/read_events output aliases preserve outputs.

Each finite IN data/ZLP writes (1U << 19) | length to the length register (PKTCNT=1), keeping MCNT/reserved high bits zero; interrupt mode adds no odd/even-frame commands. Every selected IN direction uses a dedicated Tx FIFO. The entire packet of at most 64 B is loaded synchronously, leaving no software refill work; the TX-empty mask stays zero and no TXFE refill worker is created. Writing IN FIFO is not completion. SUCCESS requires XFRC, cleared EP enable, restored FIFO free capacity and successful observed-W1C-completion clear readback. OUT requires both packet data and XFRC; short packets complete normally. Oversized packets consume every FIFO word, copy at most caller capacity, then report OVERFLOW and drain, never writing outside caller buffers.

IN TXFE is read-only and contributes neither W1C clearing nor zero-value completion proof. ITTXFE means a retryable host IN token arrived while FIFO was empty; OUT STUP is normal SETUP phase. Neither incorrectly terminates packets. IN control timeout and OUT FIFO overrun use real direction-specific event bits. SETUP/core owns EP0 DATA PID: bits 29:28/16 are reserved on EP0, so software uses DATA0 commands only on nonzero bulk/interrupt endpoints. Reset/clear-halt must check DATA0 readback; failure retains the reset admission barrier or halt instead of admitting a new packet loan early.

SETUP strictly decodes eight little-endian bytes and generates monotonically increasing epochs. New SETUP/reset makes old control loans drain; changing an epoch cannot revoke a borrow. Reset and queued SETUP in one snapshot have no proven order, so previously queued SETUP is discarded. After old loans drain and FIFOs are flushed, reset must also explicitly mask and clear active state on the selected nonzero directions of both families. Only successful readback clears reset_pending. Failure retains the reset barrier and clock; service or full stop continues recovery. New admission still requires the endpoint to be active in hardware. SET_ADDRESS validates every field of the current standard SETUP, stages the address and writes DCFG only after actual XFRC of the corresponding status-IN. Address readback failure closes the controller.

STM32F407 bus reset clears USBAEP on nonzero endpoints; the model preserves this hardware fact. Automatic EPACT clearing on GD has not been verified. After loans drain, the common production path clears nonzero active state and masks those directions on both families. This is a uniform platform postcondition, not an assertion of automatic GD hardware behavior. The GD regression must leave hardware active and prove that common code actually clears it. Completed reset still requires explicit enable with the new current epoch; reset, clear-halt and submit never activate endpoints automatically. Submitting to an inactive nonzero endpoint returns STATE, leaves the prepared request READY and creates no new request/buffer borrow or FIFO write. EP0 control retains its existing contract; DATA0 recovery, a reset event or a controller that is not closing does not prove an external configuration has been committed.

The event ring retains value facts without overwriting old events when full; exact software-loss markers follow existing queue contents. Latest SETUP/epoch/closing state does not depend on ring space. Timestamps are IRQ acquisition times, not USB bus sampling times; unordered old SETUP in reset batches is not counted as newly received control.

Explicit nonzero endpoint activation¶

The separate nexus/io/usb_activation.h provides nx_usb_activation_port_t: a two-pointer face containing shared read-only ops and the existing controller context, with one synchronous nx_usb_activation_set(port, epoch, endpoint_address, active) operation. Generated nx_factory_usb_activation(nx_usb_device_id_t) returns a static borrowed face for the selected controller, or NULL for an invalid or unsupported identity. Lookup neither initializes hardware nor retains the clock. Generation is independent of factory.capabilities, needs no ROM profile and changes no existing USB ops, profile or face layout, or factory ABI epoch 1. The mechanism adds no mutable controller/endpoint state, queue, worker, instance pool, dynamic allocation, TOML field or IR type. The two-pointer layout describes the face shape; retained read-only cost, unreferenced GC and complete-image cost require separate evidence from the corresponding ARM ELF.

The operation addresses one already selected EP1–EP3 direction. Both EP0 addresses and reserved or unselected addresses are rejected; OUT still supports only existing bulk mode. The caller must be the same serialized privileged Task with incoming IRQ masks clear. The controller must be started, retain its clock and have no closing/reset barrier. The epoch argument must equal the latest authoritative software control/reset epoch; cold epoch 0 is valid. Invalid identities and already-known stale software epochs reject before MMIO. After software checks pass, an observed raw USBRST also returns STATE before writes. A physical SETUP/reset not yet acquired may still arrive later; the IRQ guard is not a wire-atomic transaction. External callers must discard cached epochs after stop/restart.

The target direction must have no request loan, disable work, EPENA, unacknowledged defined event or unfinished SETUP cleanup. IN also requires its dedicated FIFO fully free and no flush; OUT requires the shared RX status FIFO empty. Otherwise the operation returns BUSY without implicitly cancelling requests, consuming another direction’s RX or releasing its storage. INVALID/CONTEXT/STATE/BUSY preflight rejection performs no hardware writes and creates no new loan. Activation itself never borrows a request or payload and cannot replace an existing packet’s cancel/drain/acquire SETTLED.

Cold start activates and unmasks only the two EP0 directions. Other selected directions retain immutable geometry but remain inactive/SNAK. Enabling an inactive direction first applies its selected MPS and wire type, and the FIFO selector for IN only, establishes DATA0, clears STALL and sets active/SNAK. It leaves EPENA clear and writes neither TSIZ nor the payload FIFO. It proves stable control fields, DATA0 and NAK, then handles only new target IN NAK-effective/token-empty hints (0x50) arising after the command and proves their W1C clear. Any other new event fails the operation with partial IO/closing. Defined events already present on entry still return BUSY and are not cleared during preflight rejection. It then unmasks the target EP_MASK bit and reads back the complete expected mask. OUT never writes reserved TxFIFO fields. Active state, transfer enable and IRQ masking are independent conditions; a mask or active bit alone does not mean a packet was admitted.

Before deactivation, the external owner must actually cancel/drain and acquire SETTLED for the target packet. The operation first masks the target direction and proves other mask bits unchanged, then sets SNAK, clears active and reads back the result. Each call changes only its direction, preserving other endpoints and both EP0 bits; physical vector/priority routing stays fixed. It neither flushes shared RX, resets the controller, stops the clock nor starts a transfer. Explicit Task operations wait for control/W1C readback within the existing finite poll budget, issuing each command once. The added reset-progress deactivation step makes one observation and relies on later service to continue; it does not introduce this Task wait loop into IRQ execution.

Idempotent calls require the same no-loan/no-pending preflight. Enable on an already active direction first validates immutable geometry, does not replay control-register configuration and only repairs the target mask if needed. Repeated enable must not reset DATA1 to DATA0, clear a real HALT or send a packet. Disable on an already inactive direction does not reprogram geometry; it only proves the target mask is off and events are clear. Only explicit disable followed by enable establishes fresh DATA0 and clears halt after successful readback; disable preserves PID. Corrupt immutable geometry on an active direction returns IO/closing without concealing the fault by rewriting control registers.

Failed readback after a control or mask write returns IO and retains the existing closing barrier. IO may already have partial hardware effects; it is not a no-operation rejection. Best-effort mask/inactive rollback affects only the target. If EPENA is unexpectedly observed set, writing zero cannot pretend disable has completed. Retrying activation cannot clear closing. The external owner must continue progressing other loans and perform explicit full stop. Stop may still return BUSY, retaining the clock and caller storage until existing disable/flush/IRQ-join proofs complete.

The external Chapter 9/configuration owner chooses directions for the configuration or alternate setting, cancels/drains/disables old directions, stages new directions and then submits STATUS IN for that request. This matches the before-status sequence in the ST manual and reference Zephyr; it does not impose activation only after ACK. The external owner publishes configured readiness only after actual corresponding STATUS completion and while the current transaction conditions still hold, and must gate ordinary nonzero packet admission beforehand. Several setter calls are not a configuration transaction. On a later failure, superseding SETUP or failed status, the owner must undo successful staging or explicitly stop. Platform rollback cannot revoke an ACK already observed by the host. Deconfiguration also requires actual drain/deactivation before the external deadline/rejection policy decides whether to accept; the DCD does not decode configuration values.

Activation adds an explicit control call to existing FIG-16 without a new lifecycle owner or execution thread. It supplies no Chapter 9/class stack, CDC notification, multiple-configuration/alternate policy, continuous transfer, DMA, ISO, interrupt OUT, HS/Host/OTG or electrical integration. Software mechanisms do not prove physical enumeration/reset timing, full IO-35 exit, a clean candidate or HIL.

Optional EP0 packetizer and outer borrow¶

nexus/components/usb_control.h uses a caller-provided, zero-initialized nx_usb_control_t containing only two fixed packet request slots; callers also provide the outer nx_usb_control_request_t and payload. The profile/faces must remain valid for the entire lifetime of the bound adapter. The application has exclusive use of EP0 packets; external owners still manage event-ring consumption, class dispatch and controller recovery/stop. The face→provider edge in the existing FIG-16 I/O assembly and execution diagram represents packet-layer calls; the application executor explicitly advances the EP0 component, which adds no lifecycle owner.

prepare is also restricted to Task context; all other adapter APIs additionally require execution by the same serialized privileged Task with incoming IRQ masks clear. A second Task, ISR or callback must not reenter. initialize does not start hardware; prepare does not borrow the payload. nx_usb_control_begin admits against the current authoritative SETUP epoch, establishes the outer borrow only on success, and does not itself submit a packet. IN sends min(length, wLength); OUT capacity must cover wLength. Requests, control storage and payload must meet the alignment and nonoverlap contracts in the public header. Each nx_usb_control_step makes at most one DCD service call, reads authoritative state at most once, and performs at most one packet submission/cancellation or STALL action. It checks only the two fixed packet slots, does not loop through a multipacket transaction within one step, and creates no worker; callers remain responsible for advancing it during suspend, cancel or shutdown.

nx_usb_control_out_view provides a const inspection view only in DATA_READY for the same epoch with no provider packet references. The outer borrow continues; the view expires at the next adapter call by the same owner and must not be modified, freed or passed across Tasks. External policy inspects the contents and then calls nx_usb_control_approve: true permits STATUS IN at the next step, while false requests STALL for the old transaction. Approval must occur within the original absolute monotonic deadline; a rejection decision for an old transaction is not accepted once software has observed a new epoch.

The rejection path uses the selected ROM profile’s setup_decision, a by-value nx_usb_setup_decision_port_t two-pointer face formed from shared read-only ops and the existing instance context. Within one IRQ critical section, nx_usb_setup_reject checks the expected published software SETUP epoch, pending/closing state, and the absence of active provider packets in both EP0 directions; it then issues the STALL command and verifies readback. No fields are added to the existing generic USB method table or provider context. A decision for an old epoch cannot STALL a newly observed software transaction. This is a serialization contract for observed software epochs, not a physical atomic transaction on the USB bus. SETUP packets not yet collected by the IRQ, host retries and actual wire timing still require hardware verification; rejection, epoch changes or leaving the critical section do not revoke the outer request’s borrow.

Address policy explicitly calls nx_usb_device_address and checks authoritative device state after step refreshes it. nx_usb_control_snapshot only copies the most recently acquired state; it neither replaces a refresh nor returns the borrow. Device address, closing and external configuration readiness cannot be inferred from outer SUCCESS.

A new SETUP/reset epoch, cancel, timeout or device stop never revokes an old borrow. The adapter first acquires/folds completed packets and then observes a new epoch; old packets must actually drain before it can finally publish outer SETTLED. Descriptor bytes, the outer request, adapter context, profile and its endpoint faces must remain valid throughout this interval; completion of one outer request does not join independent observers on the caller’s behalf.

If an OUT0 packet enters QUARANTINED, the adapter exposes NEEDS_DEVICE_STOP and retains the outer borrow. Only the external controller owner can authorize nx_usb_device_stop; the adapter does not automatically stop a shared controller or substitute reset or reinitialization for drain. After the owner performs an actual full stop, it must continue stepping to acquire the packet’s terminal state and finish the old outer request; storage remains retained without the required proof.

Optional CDC ACM control subset¶

nexus/components/usb_acm.h uses caller-zero-initialized, naturally aligned nx_usb_acm_t storage containing one existing EP0 packetizer, one outer request and seven wire bytes. The caller explicitly supplies the communication interface number, initial line coding and control intent; no instance pool, task, data pump, UART binding or new controller/endpoint face is created. Providers still share readonly ops; without a reference to Nexus::USBACM, no class instance or archive code is retained. The external dispatcher exclusively schedules EP0 use and handles standard requests and other interfaces/classes first. Class-specific descriptors, capability declarations, configuration readiness and application authorization remain external responsibilities; the generic descriptor helper does not validate ACM class semantics. An external project advertising a class capability must provide all its required request/notification contracts; this control subset alone does not establish complete CDC compliance.

Only SET_LINE_CODING, GET_LINE_CODING, SET_CONTROL_LINE_STATE and SEND_BREAK are supported. bmRequestType must be OUT 0x21, or IN 0xa1 for GET. The complete wIndex must equal the selected interface number. Line coding requires zero wValue and wLength of exactly 7; control-line and break requests require zero wLength, and control-line permits only the two DTR/RTS bits. Unknown requests or malformed fields are explicitly stalled through the existing software-epoch guarded rejection. If guarded rejection returns an error such as BUSY/STATE/IO, rejection cannot be reported as completed. External dispatch must not misroute other valid class requests to this narrow subset.

SET_LINE_CODING first receives seven staged bytes into DATA_READY; nx_usb_acm_pending copies values only for external inspection. Shared line-coding format checks accept only nonzero rate, stop bits 0..2, parity 0..4 and data bits 5/6/7/8/16; actual UART capabilities and product policy may be narrower. Short DATA or malformed fields cannot be approved, but may still be explicitly rejected. Control-line/break requests do not admit STATUS before approval. Every mutation requires explicit nx_usb_acm_approve from the same serialized privileged Task. True permits subsequent STATUS only; it neither changes committed state nor applies physical lines early. Approval remains within the original absolute monotonic deadline.

Only after the matching outer acquire SUCCESS, meaning a real STATUS ACK, does the component commit approved software intent and update committed_epoch. New SETUP/reset/cancel drains under the existing packetizer rules without revoking borrows; a terminal outcome without outer SUCCESS does not commit. Successful cancellation only requests drain: if the matching STATUS still receives a real ACK before endpoint withdrawal, outer acquire SUCCESS still commits the approved original epoch intent. An already acquired STATUS ACK is not revoked by later SETUP/reset, closing or a failed state read; an immediately following GET returns the newly committed line coding. Whether reset restores initial class state is separate external owner policy. Each nx_usb_acm_step advances the existing packetizer at most once, preserving the per-step bounds of one service, one state read and one packet action. The external executor must continue progress and retain all storage during cancellation, timeout, suspend and shutdown. OUT0 quarantine still requires the external controller owner to authorize real complete stop; the component does not stop it automatically.

After each step and before dispatching the next request, the external owner reads the snapshot and uses a new committed_epoch to apply UART parameters, DTR/RTS or break, with separate responsibility for application failures and recovery. The snapshot is not an event queue, and software commit does not prove peripheral application. SEND_BREAK records only 0 (stop), 0xffff (indefinite) or a finite millisecond intent; it creates no timer, performs no automatic clearing and does not prove physical break. The control subset provides no bulk data movement, serial-state notification, complete CDC enumeration, other classes or physical qualification.

Cancellation, failure and complete stop¶

Task entries require one serialized privileged executor outside Handler mode with clear incoming IRQ masks. IRQs save/restore masks, consume at most eight RX status items, 128 payload words and eight selected directions per call. Cold/hot paths are separate: cold reset/flush has finite poll budgets; IRQ flush issues one command and readback, never cold polling in IRQ. Timeout uses independent monotonic deadlines; USB suspend/unplug still needs external executor service, not SOF or hidden timers.

IN drain requests SNAK, observes actual NAK, then requests disable. EN clear, EPDISD, FIFO flush and W1C clear must all hold. Nonzero OUT first confirms global OUT NAK, then disables and drains RX. Drain timeout retains QUARANTINED and never revokes buffer loans.

Control OUT0 EPD is permanently zero and SETUP may bypass NAK. Cancellation cannot be completed by modeling a nonexistent disable acknowledgement. Without actual completion proof, individual OUT0 cancellation remains DRAINING then QUARANTINED; users may select full device stop. Full stop reads back soft disconnect, global OUT NAK and DMAEN=0, consumes RX FIFO, disables global/endpoint/NVIC sources and joins all notification publishers, flushes FIFO, then rechecks disconnect/NAK/FIFO/IRQ state before releasing OUT0 PIO loans and finally publishing SETTLED. OUT0 EP enable may still be one because hardware owns only internal FIFO and withdrawn PIO executors no longer own caller buffers; next cold core reset reestablishes hardware state. Missing proof at any step returns BUSY with caller storage and clock consumer retained.

After wake-target capture, publisher counts still retain that borrow; stop/detach returns BUSY until notify returns. Wake must support both service/cancel task context and true IRQ context. Binding reads actual priority/grouping to validate syscall ceilings without changing global grouping.
