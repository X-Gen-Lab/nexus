Next iterations and team execution¶

Stage one: turn software candidates into physical evidence¶

The highest priority is connecting the three actual launch Boards, recording PCB/crystal/power/wiring, and establishing probe, serial and waveform/power-cut stations. G474/H743/U575 source-reference configurations require separate actual-board checks. H743 additionally needs power-mode observation; U575 requires option-byte/start-state confirmation before running an image. Check safe initial outputs and clock first, then UART true TC, cancellation, RX loss, watchdog reset, Flash power cuts and EXTI/PWM/ADC. Qualify each mode only on actually executed target tuples. Keep trial outputs disconnected from product loads; station contracts govern field actions.

Use the same candidate ELF to measure cycles, IRQ latency, maximum service interval, stack high-water, loss and sustained load. Source/assembly inference helps locate causes but is not a measured timing result. Budget or provider changes require regenerated source/config/artifact evidence.

Stage two: add capabilities according to measurements¶

F407/F470 already have bounded UART/SPI DMA, continuous UART RX/bidirectional DMA, bounded/continuous ADC trigger blocks, I2C IRQ/DMA, Classic CAN, USB FS PIO and Ethernet/capture/complementary-PWM exact software fixtures. First refine these existing modes with actual throughput, IRQ latency, inter-block gap, line-drain and overload measurements. Continuous modes cannot promise losslessness under arbitrary IRQ latency or consumer speed. I2C remains 100 kHz, 7-bit, 1–256 bytes per message, at most eight messages and exact routes; 10-bit or longer transactions are separate extensions.

F103/GD303 add finite UART channel-DMA, normal RX blocks, IRQ-message I2C and physical Flash/single-shot ADC/fixed PWM; GD303 also maintains EXTI. Finite RX depends on owner service to rearm, so gaps, backpressure and loss require measurement; priority-zero I2C cannot notify a kernel. The GD303 hardware timer cascade also needs physical carry and Flash-stall observations; host models cannot establish bridge propagation delay.

G474 adds ADC1 bulb shots/TIM6 normal-DMA blocks, polling I2C1 and ECC Flash; first-conversion discard, warmup, the exact 2.5–50 kHz trigger range and actual sampling aperture require measurement. H743 maintains finite UART RX DMA-IDLE, optional initialized D2 SRAM1 and seven finite peripheral classes. Cache-on DMA still requires exclusively owned complete lines; RX has service/rearm gaps and Flash requires Cache off. U575 TZEN0 has finite SPI/I2C/ADC/PWM/EXTI/Flash fixtures; VDDA/ASV, VDDIO2 and actual bus electrical behavior need separate acceptance. The independent TZEN1 reference only adds cooperative jobs of up to eight copied PC7 commands, retaining state in private Secure storage and no NS address across calls. It supplies no general asynchronous borrow, RTOS, dual-world factory or cross-domain DMA. Chip facts authorize neither additional modes/routes nor physical qualification. Each extension first fixes owner, buffer, cancel/drain, ISR, deadline, alignment/cache and stop contracts. Then use GoogleTest/GoogleMock for an actual RED→GREEN production-provider vertical slice, followed by generated factory, ARM ELF, SDK and physical-boundary verification. Unselected modes retain no resources; growing generic-object costs are not imposed on every product.

This iteration records source implementation, targeted developer execution and final integrated software qualification separately. Final acceptance must bind exact frozen source/configuration/tool/artifact identities; new documentation, source merges and historical counts do not replace actual execution. ECC Flash program_flags, fresh-erase provenance and per-pulse completion evidence also belong in the product caller contract. Physical equipment is absent, so physical items remain not_executed; they are not promoted to safety certification or production release.

Reuse existing narrow ports and static assembly first; allow explicitly versioned breaking changes when contracts cannot express hardware facts. Flash authentication, upgrades, manufacturing keys and industrial security policy belong to external products/independent mechanisms. Existing storage CRC or watchdog feed cannot establish their completion.
