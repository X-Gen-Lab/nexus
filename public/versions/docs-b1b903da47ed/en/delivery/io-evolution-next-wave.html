Completion and failure¶

U575 DMA transfer completion does not imply USART wire completion. The selected mode retains DMAT across requests and cancellation, in accordance with the reviewed U5 erratum. Final settlement requires fresh channel withdrawal/reset proof, independent USART TC and reference drain. Failed drain retains the request in QUARANTINED; a timeout does not revoke its source-buffer loan.

G474 CAN FD separates pending TX add/request bits from fresh per-element sent or cancellation outcomes. Receive queue capacity does not hide the latched protocol state. G474 PWM/ADC joins timer, ADC, DMA and IRQ references and latches late faults before publishing its final request state. Products must continue service and preserve storage whenever withdrawal fails. See the public API and finite PWM/ADC contract for the selected call contexts and physical reference assumptions.

Build and dependency delivery¶

Private official inputs add exactly two U5 LL headers (dma, usart) and three G4 FDCAN-definition headers, including their transitive definitions. Pins, licenses and CMSIS pairing remain checked. The selected closure does not link HAL handles, a vendor tick, vendor IRQ callbacks or a second transfer owner.

The source SDK now requires the new public/private I/O modules, coupled configuration code and explicit family payload. verify_consumers --parallel N accepts a strict positive job count for every consumer build. Omitting it preserves the previous 4-job base/2-job modern defaults. Its Python regression checks all 13 consumer roots and 16 image targets with external subprocess test doubles; it does not constitute execution of a new real SDK consumer package.
