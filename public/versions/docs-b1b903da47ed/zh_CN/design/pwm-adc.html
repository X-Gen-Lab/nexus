由同一硬件 owner 管理的有限 PWM 与 ADC 窗口¶

本合同说明如何通过 nx_pwm_adc_t 选择并执行有限的定时器触发采样窗口。当前实现仅覆盖下述精确 STM32G474RET6 finite-regular-dma 软件参考：DMA 填充有限原始采样数组时保持一帧 PWM 占空比不变，随后先撤离各个源，再归还请求。产品控制算法、功率级策略和经实物检查的 PCB 接线仍由外部工程负责。HIL 为 not_executed。

选择一个联合接口¶

FIG-16 描述当前共用机制，不是经过测量的 PWM/ADC 时序图。 在本装配中，生成的接口为 nx_pwm_adc_t，provider 统一拥有 TIM1/ADC1；请求、占空比数组和采样数组由应用提供。箭头仍分别表示生成、查找和调用。factory 查找不会预转换 ADC、启动 PWM 或调度工作。

正常输入为维护中的 TOML 夹具。其纯软件 Board 包提供芯片引脚和供电假设，不建立已安装模拟电路的事实。严格解析器选择一个 Construction、紧凑的 NX_PWM_ADC_ID_WINDOW 和 nx_factory_pwm_adc，在发布原子 bundle 前拒绝 TIM1、ADC/common、比较器、DMA、向量和引脚的资源冲突。普通 PWM-group 与 ADC 接口不会再独立暴露该装配的硬件。

准备、准入与显式推进¶

  1. 取得生成的不可变接口，并显式启动 Platform。启动只准备冷态 owner，不启动请求或 PWM 输出。

  2. 首次使用时初始化请求，然后准备独立采样数组、完整的三通道占空比帧及有限的绝对单调 deadline。准备操作复制帧元数据，不建立借用，也不访问采样内容。

  3. 由唯一的特权、未屏蔽中断的任务执行者提交。拒绝不遗留新效果或引用。NX_SUCCESS 表示 ACCEPTED，包括装载失败后可能已通过真实排空结束的请求。

  4. 接受后必须保留请求与占空比存储，应用不得读写采样存储。IRQ 只锁存有界事实，同一任务通过 service 推进完成或撤离。没有隐式任务代为推进。

  5. 在读取结果和样本前，以 acquire 观察 NX_REQUEST_SETTLED。再次准备同一存储以发起显式请求前，还要单独等待 adapter/observer 引用退出。普通成功完成不会自行重新装载。

准备操作拒绝请求、帧、占空比与采样范围之间的重叠、未对齐或地址回绕，且不修改已初始化的请求。provider 还会在准入前拒绝与保留状态、事实、存储域描述符及已知 MMIO 控制区域重叠的别名。已知控制区域中的请求描述符会在读取字段前被拒绝。

每个已接受窗口在 TIM1 停止时装入一致帧，并在安静触发路由下使预装载生效。启用 ADC 后先丢弃两次软件转换，再启用普通 DMA 和外部常规组触发。两次预转换都不会进入用户 DMA 存储。有限预转换序列使用至多 100 us 的 deadline 预算及第二层轮询次数上界。后续每个显式窗口都会重新启用 ADC 并执行两次预转换；空闲时不会让 BULB 采样器持续启用。

整个窗口的 deadline 是观察规则：缺少可信完成时间戳时，若首次观察 TC 已到达或超过 deadline，就报告 TIMEOUT。若在 deadline 前已经观察到 TC，之后仍可继续完成必要撤离。这不建立物理执行时间上界。超时和取消均保留原借用，直至真实源排空成功。

发布结果前证明撤离完成¶

FIG-06 提供共用请求状态合同。 ACCEPTED 与 REJECTED 是准入结果，不是额外的请求状态。在本 provider 中，DRAINING/QUARANTINED 与 SETTLED 背后的源撤离证明包括以下每一步。

  1. 撤离主输出、通道与定时器中断源。先证明 CEN0，再选择基于 enable 的安静触发路由；拒绝清除 CEN 时不得产生新的 TRGO2 上升沿。

  2. 请求停止 ADC，观察 ADSTART/ADSTP 撤离，再禁用 ADC 并观察 ADEN/ADDIS 撤离。service 使用有界进度轮询，不把长时间等待放在中断屏蔽区内。

  3. 禁用 DMA 并证明其状态，撤除两个硬件地址及计数，随后撤除 DMAMUX 路由。取消或错误后，剩余计数快照不能证明有效样本前缀。

  4. 应答中断源前，保留每个已捕获的 TE/OVR/break 事实。只清除观察到的自有 DMA 标志，再次检查故障。排空中迟到的标志不得被转成采样成功。

  5. 禁用并等待两个向量退出，包括 pending 与 active 发布者。在最终短元数据保护区内再次采样故障，撤除 active 请求引用，再以 release 发布 SETTLED，作为 provider 对请求的最后一次访问。

单凭 DMA TC 无法证明输出、触发或 ADC 已撤离。有限 DMA 可在终止 IRQ 迟到时避免反复覆写用户缓冲区，但不会停止 TIM1。COMP break 撤除 MOE，却不会停止 CEN、TRGO2、ADC 或 DMA。这些独立事实不能相互替代。

普通成功结果精确报告请求的样本数。任何错误或取消均报告零个保证有效的样本。在失败撤离的重试期间，首个错误、取消或超时原因保持权威；DMA 完成不得覆盖物理故障。未完成的停止使请求保持 QUARANTINED，私有恢复状态继续存活；后续成功重试才可结束请求。锁存故障要求冷态恢复，不会自动重启输出。

公共 stop 关闭后续准入并尝试源排空。成功不归还引脚、时钟或私有存储。Platform close 还要等待两个向量退出、关闭下属硬件状态、恢复原逻辑优先级，最后才恢复比较器、引脚和时钟。close 失败时，同一 owner 必须保留每个未完成的外层租约并继续重试。不得把已停止身份当作已撤销的指针。

来源与软件证据¶

公共权威合同为联合请求 API和核心请求生命周期。私有 provider复用选定的官方 ADC/DMAMUX 原语与下属冷态辅助函数，不会替换既有 TIM6 流的定时器指针，也不会暴露两个硬件 owner。

已审阅的硬件来源为 RM0440 Rev9、DS12288 Rev6 和 ES0430 Rev9。官方驱动的原始身份、配对 CMSIS 与许可证保留在精确源码锁中。ADC 预转换、有限 DMA 和特定标志应答处理了选定的勘误条件，不表示每一项芯片限制或物理电路均已通过验收。

外部寄存器/事件测试执行真实 provider 代码，覆盖别名拒绝、预转换、DMA 迟完成、保守 deadline、独立撤离拒写、最终故障快照和迟到 IRQ 后的存储复用。生成 factory 测试执行正常 TOML bundle、冷态时钟/引脚/比较器构造、两次预转换采样，以及清理失败保留和优先级恢复。GoogleMock 观察外部效果，不替换 provider 方法。

这些实际主机执行只建立记录的软件范围。正常 fixture-io-evolution-g474-pwm-adc ARM 装配也已链接并通过资源预算和保留检查：一个选定接口、一个具体方法表和五个方法。该软件链接不建立 clean 发布候选、可复现性或物理 HIL 资格；各项均需要绑定精确产物和源码的独立证据。本有限软件参考不建立已检查 PCB、模拟精度、波形测量、中断延迟或连续/同时/注入组采样资格。
