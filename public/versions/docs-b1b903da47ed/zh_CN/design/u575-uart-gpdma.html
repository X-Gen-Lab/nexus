STM32U575 USART1 有限 GPDMA TX¶

当精确 STM32U575ZIT6Q 的 TZEN0 装配需要通过 USART1 发送有限字节，同时保留独立的 IRQ 字节接收时，选择此模式。实现使用一个静态 UART 所有者、调用方持有的请求和 TX 缓冲区，以及锁定的官方 LL 寄存器操作。产品任务、等待策略、协议组帧和恢复策略仍由外部工程负责。物理 HIL 为 not_executed。

选择精确装配¶

FIG-16 展示当前共享的构造和运行时所有权，不表示 U575 DMA 时序或硬件资格。 此选型生成 nx_uart_port_t 接口，共享方法表为 nx_stm32u575_uart_gpdma_ops，私有所有者包含一个 UART 前缀和按选型保留的 GPDMA 元数据。箭头仍分别表示生成、查找和调用。不存在第二个 UART 接口或隐藏 DMA worker 共同拥有同一控制器。普通 IRQ 字节 UART 的状态和方法表不增加字段。

通过既有 UART 接口执行¶

  1. 由特权任务所有者调用平台启动。检查主要错误、清理错误及剩余效果。部分构造失败仍可能保留所有权；重试停止期间，必须保持其存储和冷态租约有效。

  2. 通过 nx_factory_uart(NX_UART_ID_CONSOLE) 取得静态接口。查找只返回身份，可以在启动前执行；硬件操作要求平台已成功启动。

  3. 对新请求调用一次 nx_request_initialize，随后通过 nx_uart_tx_prepare 准备请求。deadline 是有效 nx_time_now_us 时间域内的绝对时间。借用期间必须保持整个数据区不可变。

  4. 通过 nx_uart_port_submit 提交。拒绝不会保留请求、数据或新增硬件效果。NX_SUCCESS 表示 ACCEPTED，也包括后续硬件启动失败；同一所有者必须完成其排空。显式适配器也可通过 nx_uart_port_start_admitted 传入自己已经持有的 QUEUED 借用。

  5. 同一任务调用 nx_uart_port_service 推进 deadline 观察与排空。IRQ 只锁存有界的物理事实，并可发出唤醒提示。等待适配器是可选项；使用内核通知前，必须验证两个 IRQ 策略。唤醒提示不能替代请求状态。

  6. 读取结果或复用请求及数据前，必须通过 acquire 观察到 SETTLED。适配器观察者也必须退出后才能复用其存储。DMA TX 期间仍可进行普通 RX 读取。

查找、启动、提交和 IRQ 分派均不创建调度器、worker、动态分配或运行时名称注册表。一个特权任务串行执行控制操作；跨任务取消使用既有的外部 slot/epoch 适配器，不共享可变请求指针。

区分 DMA、线上与引用完成¶

FIG-06 描述当前共享的请求合同，不承诺超时能够停止硬件。 可选的 QUEUED 路径属于显式适配器。此 provider 在取消和 deadline 观察后仍保留同一请求及源数据，直到证明硬件和引用已经撤离。

观察结果

provider 动作与释放条件

DMA TCF

锁存块完成事实，继续保留请求和源数据。依赖 USART 线上状态前，必须证明引擎已禁用、空闲且 FIFO 无剩余数据。

取消、deadline 或 DMA 错误

保留首个终止原因，开始有界排空，并保持既有的最早排空期限。超时不撤销缓冲区借用。

活动通道撤离

请求 SUSP，观察新的硬件 SUSPF 和 IDLEF，发出合法 RESET，并读回已禁用及空闲状态。向 EN 写零不会禁用 GPDMA。

挂起 IRQ

撤销 SUSPIE 并确认读回，保留后续复位证明所需的实际 SUSPF。缓存的标志不能授权复位。

独立的 USART TC

最后一个停止位已完成；发布完成前仍须撤离各源、IRQ 和发布者。

全部必要排空条件成立

先清除活动引用，再通过 release 发布 SETTLED，作为 provider 对请求的最后一次访问。

排空期限届满仍缺少证明

继续借用 QUARANTINED 存储，并保留所有者继续恢复的责任。

当引擎已证明禁用、空闲且为空时，普通块完成不要求每个请求都复位。取消活动通道需要上述挂起和复位顺序。新的 EN 前先排空旧完成和挂起标志；错误保持锁存，旧 TCF 不能启动下一请求的线上排空预算。标志确认期间到达的 DMA 错误不能使失败请求变为成功。

任务 service 撤销 DMA/USART TX 中断源并检查读回，确认 DMA 向量已禁用、无 pending、无 active，同时检查活动 UART IRQ 及已捕获的唤醒发布者。只有 DMA 已不能继续装载 TDR 字节后，才独立观察 USART TC。IRQ 字节 RX 与 TX DMA 保持独立。错误或中止的请求将保证有效的传输字节数报告为零；成功请求报告全部提交字节数。

恢复期间保持 USART 请求门控¶

ES0499 Rev12 第2.21.2节描述了清除再设置 DMAT 后可能丢失后续 DMA 请求的问题。此模式采用文档中的持续门控规避措施：首次启用 UE 前建立 DMAT=1，并在成功、取消、错误、通道复位及重新装载期间保持。逐请求恢复不会循环关闭再开启接收器的 UE。

整体停止先关闭准入，并保持 DMAT，直到未完成请求、中断源、两个向量和唤醒发布者均已退出，且观察到 UE=0、TEACK=0 和 REACK=0。之后才可清除 DMAT 并撤销本次新增的 GPDMA 时钟。部分初始化在第一次写入前记录效果，并保留未证明完成的清理责任。对冷态或已成功停止的所有者重复停止不会访问硬件，包括同一控制器已由后继实例启动之后。

如果 service 或 stop 无法证明撤离，必须保持请求、数据、环、唤醒目标及选定冷态所有者有效。通过同一所有者继续有界 service/stop。产品决定如何处理永久无响应的外设；平台不会虚构成功释放，也不会自动恢复协议流量。

构建与评估证据¶

在仓库根目录准备好锁定工具和依赖后，运行：

python tools/dev/dev.py configure --preset fixture-io-evolution-u575-uart-gpdma
python tools/dev/dev.py build --preset fixture-io-evolution-u575-uart-gpdma

维护的输入为上述 TOML。成功后在该 preset 的 bin 目录生成 io_evolution_fixture.elf、.bin、.map、.resources.json 和 provider-retention.json。检查资源验证成功，且保留了一个选定 UART 接口及其真实 GPDMA 方法表。这些命令只构建软件，不烧写开发板或执行物理 HIL。应用 TX 执行需要上述显式任务流程；链接冒烟夹具只建立其声明的链接范围。

当前开发证据包括40个真实 provider 的 GoogleTest/GoogleMock 用例、8个正常 TOML/生成工厂用例，以及通过资源和 provider 保留检查的正常 ARM 配置与构建。记录的模型用例全部通过，无跳过。模型执行建立所测软件行为，ARM 产物建立链接和资源证据。两者均不建立 clean-source 完整门禁候选资格，也不建立实测周期、振荡器精度、电气行为或实物勘误资格。物理 HIL 为 not_executed。

源码使用已锁定的官方 LL DMA 和 USART 头文件完成选定寄存器操作，不增加厂商 HAL 句柄、HAL tick、厂商 IRQ 回调、链表描述符或第二个传输所有者。USART2 DMA、RX DMA、连续流、自主或低功耗 DMA 及 TrustZone broker 均不在此实现范围内。通用 Cortex-M33 架构和芯片的其他 DMA 能力不会扩大此精确 provider 的范围。
