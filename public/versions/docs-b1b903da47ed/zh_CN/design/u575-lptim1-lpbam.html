U575 跨 Stop2 的 LPTIM1 单组 LPBAM¶

本参考适用于 STM32U575ZIT6Q TZEN0 baremetal：一组固定 SRAM4 tuple 通过 LPDMA1 channel0 更新 LPTIM1 CCR1、RCR 和 ARR，同一 concrete Stop2 owner 负责睡眠与最终归还。通用 LPBAM 以及原 IO-32、SOC-35 退出仍开放。Board 输出路线未知；物理 HIL 为 not_executed。

ES0499 第 2.17.3 节指出，修改 DIER 中的中断位会清除对应状态标志。因此成功必须在撤源改写 DIER 之前锁存新鲜的内核写入确认。软件模型保守地允许任意 DIER 写入清除全部三个 write-OK 标志；这是防御性测试边界，不是硅片测量结果。

链接 Nexus::U575Stop2Lptim1，它引入 Nexus::U575LpdmaLptim1 和保留时间组件。WUT-only、SRAM4-copy 与 LPTIM1 是同一静态 Stop2 owner 和 RUN ClockDomain 的互斥编译期模式。默认镜像不选入任何新目标。该参考不引入堆、worker、队列、动态 MMIO 计划、运行时注册表或新 factory；vendor types 保持私有。

准备精确 owner¶

选用维护的 assembly。仍须满足其选定 SRAM4/LPDMA1 reset startup 和外部准备的 LSE RTC 来源合同。在每次 join 完成前，必须保持 0x28000000..0x28003fff 的 16 KiB nonsecure SRAM4 供电与保留，并保持 SRAM4EN、LPDMA1EN 有效。运行时恢复不得通过修改掉电字段来补救已丢失的 SRAM4。

既有 保留时钟与 Stop2 profile 要求 TZEN0、未交换 Flash、有效 MSIS4/MSIK4、各总线频率相同、真实 Range4 和 caches off。所有 LPDMA channel/vector 初始必须静默，其他 channel 不得运行。整个 LPTIM1 控制器必须独占且初始处于 reset/cold 状态，访问门控关闭、kernel mux 为 reset 值。外部 timer writer、IRQ user 或 reset 不得共享它。RUN LPTIM2 必须已禁用并 join。

以 receiver API 和 Stop2 API 为声明权威。由一个 privileged Thread 串行调用；复制的 face 保留相同物理身份。ISR 或并发 writer 不得控制这些对象。所有 owner、clock 和 face 都须保持有效，直至 stop 与 join 完成。

启动、借用与执行¶

  1. 使用普通保留时间初始化器，设置 wake_owner=nx_stm32u575_stop2_identity()，再初始化 Stop2 和 receiver。不使用 AlarmA-copy 初始化器。Receiver 初始化无副作用；显式公开 start 在未屏蔽的 privileged Thread 中准备访问。

  2. Start 获取 LPTIM1EN、LPTIM1SEL=LSE 和仅在需要时新增的 LSESYSEN，并观察 LSESYSRDY，保持 oscillator/calendar 来源不变。它不写 timer register。部分失败保留账本和物理预留；必须保持存储有效，并调用公开 stop，直到恢复成功。产品无需私有 RCC 准备写入。

  3. 初始化 request base，取得一次成功的 retained sample，然后以 tuple、workspace 和保留时间域中的绝对 deadline 或 NEVER 准备元数据。Prepare 不借用或访问 tuple/workspace；须保持 tuple 内容不变。值准入检查发生在 ACCEPTED 之前。拒绝不改变 request 的任何字节，也不保留新引用；旧 TIM2 deadline 从不转换。

  4. 关闭并排空精确 RUN barrier，禁用/join LPTIM2 并停止 Platform。以 privileged MSP Thread、CONTROL0、PRIMASK1 和 BASEPRI/FAULTMASK0 进入；恢复期间保持掩码及 RUN 准入关闭。使用 4096..65536 个 RTC/16 escape ticks，以及正数的每阶段 poll_limit。即使后续设置失败，ACCEPTED 仍借用 request、tuple 和完整 workspace，直至 acquire 观察到 SETTLED 且外部 observer join 完成。

观察到 CR.ENABLE 后，新的成功 retained sample 作为有界等待的起点；至少再等待两个 256 Hz RTC tick，并检查 request deadline。即使第一个 tick 间隔任意短，仍包含一个完整的 128 LSE cycle 间隔，超过两个 counter cycle。轮询次数本身不能证明经过时间。PRELOAD1、一次 CC1E 设置以及初始 CCR1=0/RCR=0/ARR=1023 写入要求新的 CMP1OK/REPOK/ARROK；这些初始标志随后必须被清除并确认清除，才能启动 DMA。

首个 32 位 CCR1 写入等待 request13 lptim1_ue_dma，使用 BREQ1、SWREQ0 和保留位 DREQ0。两个生成的软件请求 LLI 依次写 RCR，最后写 ARR，目的地址固定且不连续，也不递增。ARR 的 APB 写入应答清除 UE；末链为零，完成发生在最后一个 LLI。WUT 独立提供逃逸唤醒；不配置 AlarmA register 或 GPIO。成功表示寄存器写入已同步，不代表播放完整 PWM 周期。

证明成功、隔离与 join¶

成功须在 UEDE0 或任何 DIER 撤源写入可能清除标志之前，锁存有限 DMA 完成与新鲜 CMP1OK/REPOK/ARROK。DIER 写入后标志安静不是该证明。每次准入及完成的自有隔离都会在既有 16 B 账本内清除保存的证明。错误或部分取消无需为未发出的写入取得 write-OK；master 隔离和自有 reset 可以错误终止此类请求。

若尚无 DMA 终态或既有失败，公开 service 返回 BUSY 并保持 UEDE 启用，使待发生的硬件请求仍可推进。pending IRQ 只是提示。若具体 Stop2 清理不能证明完成，会保留借用并记录错误，供显式恢复使用。

有限 DMA 完成后，有界的新鲜 write-OK 证明若不完整，会锁存 NX_ERROR_IO 并返回 BUSY，本次调用仍保留生产源和借用。下一次公开 service 或具体 recover 即使始终没有这些标志，也会沿错误排空路径推进。这表示未能证明内核接收，不是从轮询次数推断 deadline 已到。

WUT、deadline、cancel 和恢复错误须在撤源前进入首次失败账本。该决定与 DIER 写入之间到达的 TC 可以增加已观察的传输前缀，但不能将终态错误升级为成功。公开 service 从不发布 SETTLED；同一具体 Stop2 owner 必须完成最终引用撤除。

在有效访问配置下，先撤回 UEDE 并观察新鲜 DIEROK，再进行下一次 DIER 写入；对于仍启用的 DMA 通道须取得 suspend/SUSPF/idle，对已完成通道须观察 idle。证明 full-word RESET 与完整 CCR 为零。在通过 RCC reset 独占的 LPTIM1 前，清除通道地址、链接、标志和 IRQ 引用。绝不清 CR.ENABLE：ES0499 第 2.17.1 节要求使用 reset 关闭。保留无关门控、mux 字段及 RTC/LSE 来源；自有 reset 不得擦除任何外部控制器状态。

访问 profile 未知时，不允许 RTC/LPTIM/DMA MMIO，并保留效果与存储。Concrete Stop2 recovery 重试时不执行 WFI。只有 DMA 最终访问已被证明之后，自有 reset 失败才可重试；活动借用期间观察到外部 DMA 或 LPTIM reset，会将借用永久隔离，直至实际外部系统 reset。撤销 reset 或静默 reset 默认值不能归还该借用。

Cancel/deadline 从不撤销存储借用。只有 peripheral、DMA、IRQ、借用 gate、RTC/WUT、power 和 clock 都恢复后，Stop2 才移除引用，并以 release 发布 SETTLED，作为其最后一次 request 访问。公开 start 的 claim 保留到 joined public stop 归还它们，即使 stop 是在借用期间请求的。所有效果排空后才可重新开放 RUN 并重启 Platform；旧 Core TIM2 deadline 仍然无效。

来源与验证边界¶

生产 receiver 与具体 Stop2 通过 typed compile-time profile 共享不变量；两个公共 request/ops 类型保持独立。维护的公共 C11 consumer 是源码集成参考。完整安装版 SDK consumer plan 由维护的 transport policy 定义；历史 v7/v8 结果不授予新增选择资格。完整集成 gate、搬移 SDK、离线复现与候选验收均须有各自证据。

有针对性的真实生产 C GoogleTest 模型在 debug 和 Os 下各通过 24 项，覆盖保守 DIER 清旗、早期 service、确认缺失、部分取消、晚到 TC 和证明复用。既有 memory-copy receiver31 与 coupled17 项保持通过。选择性严格 C11 Cortex-M33 开发重链接重新编译 receiver 和 Stop2 单元，复用固定的 startup、公共 consumer 与未变依赖库。这些检查不建立完整 SDK 或候选资格。

RM0456 Rev7 来源为第 18.3.3 节/Table148（request13）、18.3.4 节/Table149（BREQ）、18.8.11 节（保留位 DREQ）、58.4.11/13 节（write-OK/enable 延迟）、58.4.20–21 节（CCR1→RCR→ARR/UEDE）、58.5 节（Stop2 前禁用 LPTIM2）、58.7.8 节（DIEROK）和 11.8.48–49 节（LSE mux/system gate）。ES0499 Rev12 第 2.17.1–3 节规定 reset、repeat/APB 约束和 DIER flag；RCR0 与 LSE≤PCLK 排除奇数 repeat profile。物理波形、保留、驻留、精度、唤醒与功耗检查仍为 not_executed；不提升任何原 IO-32/SOC-35 退出状态。
