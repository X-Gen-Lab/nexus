主流 MCU 接入与平台反馈¶

使用本页扩展精确的 STM32 或 GD32 料号，同时维护通用平台合同。本轮新增 STM32F103RBT6 和 GD32F303RCT6 参考接入，并扩展 G474、H743 和 U575 的选定模式。源码实现与已通过的软件候选分别记录。在已连接设备实际执行站点计划之前，所有适用的物理结果均保持 not_executed。

CAN、USB、Ethernet、DAC 与存储/协议服务属于独立能力，九类表不包含或授予这些能力资格。不支持的控制器、路线、传输模式和后端必须在解析阶段失败。不得从 DMA 回退到 polling，也不得替换其他控制器或引脚。派生能力矩阵与既有 SoC 台账继续作为实际权威。

可选 Ethernet 合同也分别维护。原有 eth face 使用连续未标记帧和四字 descriptor。独立 eth_frames 选择在精确 F407/F470 RMII 参考上使用八字 descriptor、SG frame loan、单个带内 VLAN C-tag 和 MAC 硬件事件时间戳；两者不能同时占用同一个 MAC。两个合同都不包含协议栈或网络时钟同步，软件装配也不为 PHY/PCB 接线建立资格。

H743 SPI4 DMA 选择 DEV_ID 0x450、REV_ID 0x2003（V）、固定 HSI64/默认 trim、Cache off/on 和裸机。正常有限全双工请求借用所选已初始化 AXI SRAM 中互不重叠的 TX/RX span。Cache off 接纳 1..65535 bytes；Cache on 要求独占完整 32-byte lines，地址对齐，长度为对齐的 32..65504 bytes。DMA1 Stream2/3 与可选 USART3 Stream0 TX 或 Stream1 RX 资源独立。该模式不开放 PLL384、FreeRTOS、16-bit、固定 dummy/discard 或多段 SPI DMA。见 H743 provider 合同。

独立 H743 rx-dma-continuous 模式使用 USART3、DMA1 Stream1/request45、DBM/CIRC 及至少三个等长、调用者拥有的 AXI SRAM 缓冲区。它选择 V 修订、固定 HSI64、裸机和 Cache off/on。task service 在 BRR/TIM2 推导的保守时限之前替换 inactive bank，并在 IRQ 外执行 Cache 维护。替换过晚或不确定、Cache 失败或没有 FREE 缓冲区时，停止生产并显式报告 loss；借用保持到实际排空。IDLE 关闭本次 producer 并发布排空后的 prefix；调用者须显式重新初始化 stream 再启动。TX 仍是有限 IRQ，不构成 DMA duplex。Cache-on 缓冲区独占完整对齐的 32-byte lines。该模式接纳 32..65535-byte Cache-off 缓冲区或 32..65504-byte Cache-on 缓冲区，不建立实测吞吐、时限或物理资格。

U575 USART1 dma-tx 选择 TZEN0、MSIS4、8N1、Cache off，并通过 GPDMA1 channel0/request25 处理非安全 SRAM1 中的有限 payload；IRQ-byte RX 保持独立。GPDMA 合同保留 ES0499 持续 DMAT、独立 UART 线上 TC 及完整 source/IRQ/publisher 排空。独立 irq-fifo-bytes 选择有显式阈值和每次 IRQ RX/TX 字节预算，不与 DMA 组合。这些选择不增加 USART2 DMA/FIFO、RX DMA、LPDMA、TrustZone transport 或自主低功耗执行。

独立 U575 dma-chain-tx 模式使用同一 USART1/GPDMA channel 及独立 IRQ-byte RX。一次请求借用连续地址的 SRAM1 payload，最多三块，每块最多 65535 bytes，并使用最多两个 packed 12-byte 私有节点。整个 24-byte 节点数组按 32 bytes 对齐，位于同一 CLBAR 窗口。196605-byte 协议上限还要求真实可达且无别名的 RAM；它不为调用者保留整块 SRAM。payload 和节点保持 live，直到 fetch/channel/IRQ 排空且独立 UART TC 已观察。该有限选择不开放 scatter-gather 或循环链。

独立无引脚 U575 LPTIM2 irq-counter16-oneshot 参考选择 TZEN0、MSIS4、裸机与 PCLK1/4，提供名义 1 MHz RUN counter。请求接受 2..65536 ticks；ARR 必须大于 reset CCR0，因此拒绝一个 tick。IRQ68 priority5 从不调用 OS。它不拥有外部引脚或 DMA，不承诺 Stop、backup 或 VBAT 连续性。PCB 与硅片修订仍未观察；软件模型与链接检查不测量物理时序。

精确模式边界¶

G474 的 RE 封装包含 52 个 GPIO 焊盘，不能视为六个完整的十六引脚端口。固定 HSE 配置保留 PF0/PF1；PG10 因 NRST 选项保持不变而继续保留。GPIO 清单与 Board 连接器路线分别维护。SPI1/2 使用八位传输、模式 0..3、明确的低有效 CS，每次有限调用最多传输 256 字节。170 MHz 配置将请求 SCK 限制为 42.5 MHz：二分频会超过数据手册上限。G474 还将 TIM3 CH1 PA6 AF2 与 TIM4 CH1 PB6 AF2 实现为独立、独占整个控制器的 PWM 所有者：固定向上计数、有效高电平 base，整数时钟分频 1..65536，period 为 1..65535，暂存 duty 为 0..period。Capture、互补输出、break、IRQ、DMA 及共享 timer channel 均不在本次增量内。

这些 PWM 限制描述计数器算术范围，不表示无条件的引脚频率。SPI/PWM 使用 OSPEEDR=11。DS12288 Table56 在 30 pF 下，将引脚翻转限制为 VDD 1.62..2.7 V 时 50 MHz、2.7..3.6 V 时 120 MHz；因此 period 为二时的逻辑 85 MHz 波形有适用条件。当前配置不建立 GPIO 供电、负载或脉宽适用性；这些条件必须由 Board 验证。

Polling SPI 仅在证明移位器排空且 CS 无效后返回。若准入后的 reset 或 CS 撤回不能证明这一状态，执行者保留调用者缓冲及控制器/CS 所有者，屏蔽中断并调用平台故障观察者。观察者返回后继续停驻；外部产品恢复不得返回已释放的存储。空闲 stop/recovery 失败仍保留各自可重试的私有租约。

H743 USART3 使用 PD8/PD9 AF7，以及 DMA1 Stream1 上普通模式的有限 RX DMA 块，DMAMUX1 channel 1 request 45。所有者负责处理完成并重新装载下一个块；块之间可能出现空隙。这不是循环或连续接收器。仅准入选定且已初始化的 AXI/SRAM1 域。Cache 关闭时，块包含 1..65535 字节。Cache 开启时，块必须独占完整的 32-byte Cache 行，地址和长度均须对齐，最大长度为 65504 字节。必须先撤离访问源、观察稳定的剩余计数并完成后置 Cache 失效操作，才能发布。消费者仍持有借用，或分离失败时，必须继续保留 DMA 流、Cache 及平台依赖。

U575 新增 USART2 PA2/PA3 AF7 以及适用于该封装的 GPIO 路由。PG[15:2] 要求 VDDIO2 供电已经建立，并观察到 PWR 时钟／IO2SV 配置；平台不会使能未知的外部电源轨。IO2SV 是配置观察结果，不是电源轨电压测量。TZEN0 仍是通用平台配置。独立的 TZEN1 参考配置还接受至多包含八条 PC7 命令的协作式 GPIO 作业，命令会复制到一个 Secure 槽位中。SERVICE 每次最多推进一条命令，POLL 读取锁存状态，CANCEL 保留此前已产生的效果，CONSUME 仅释放已进入终态的作业。票据永不回绕；调用结束后不保留任何 NS 地址。这既不提供用户缓冲区借用，也不提供通用异步或跨安全域传输支持。

F103 独立启动准入检查 CPU 可读的工厂 Flash 密度，不依赖仅调试模式可读的设备组或修订值。ES096 Rev15 第 2.2.2 节指出，正常软件读取 DBGMCU 返回零，因此设备组和修订仍未观察。配置中的 STM32F103RBT6 料号声明及封装仍需独立接入证据。参见 F103 来源边界。

F103 使用 USART2 PA2/PA3 和 PA0/PA1 EXTI 事件。F103 SPI1 和 GD303 SPI0 使用默认的 PA5/PA6/PA7，以及显式指定、低电平有效的 PA4 CS；标称频率为 31.25 kHz..4 MHz，字长为八位，支持模式 0..3，每次有限调用最多传输 256 字节。它们的 SPI 装配不能同时选择 PA5 GPIO/LED 绑定。F103 TIM2 为 16-bit，标称频率为 1 MHz；其溢出服务间隔和中断屏蔽时长均须小于 65.536 ms。GD303 将 TIMER1 更新 TRGO 级联到 TIMER4 ITI0，并扩展高位溢出，服务间隔须小于 2^32 个标称微秒。这使低位计数在所述 800 ms Flash 擦除上限期间发生的回绕仍可保留；定时器桥接的进位传播仍需物理观察。两个配置都不建立经过校准的实际时间，也不证明同 bank 取指停顿后的 FreeRTOS tick 追赶。

模式资源、采集与物理 Flash¶

F103 USART2 的 TX 使用 DMA1 channel7，有限 RX 使用 channel6；GD303 USART0 使用 DMA0 channel3/channel4。仅 TX 的构造采用紧凑的 TX 状态与显式的 IRQ 字节环形缓冲区；只有双工构造才增加调用者提供的 RX 块。两者仅准入已声明、长度为 1..65535 字节的 SRAM 区间。在传输线 TC 和访问源撤离之前，内存 TC 不会使 TX 结清。有限 RX 仅在通道／DMAR 撤离且计数稳定后发布；所有者服务重新装载空闲块，因此空隙和可见丢失仍属于合同的一部分。替换块不可用绝不授权覆盖消费者借用的存储。它们的 PB6/PB7 I2C 使用优先级为零的 IRQ 处理，并拒绝内核通知；总线电压与上拉由外部负责。共享的旧式引擎仍是唯一的协议所有者。

G474 ADC1 选择单端 12-bit bulb 采样，SYSCLK/128 = 1.328125 MHz，采样代码为 code0。软件触发的单次采样丢弃首次转换，并保留显式的预热与间隔保护。TIM6 触发的有限普通模式 DMA 块仅接受能整除 1 MHz 触发时基的 2.5–50 kHz 采样率。bulb 采样孔径取决于前一次 EOC 和下一次触发，而非仅由 SMPR 决定。IRQ 停止触发；服务先观察到 DMA/ADC 已撤离且 ADEN 已清零，再发布，随后由后续服务重新装载。准入的 SRAM1/2 域排除 CCM 别名，即便芯片可通过其 0x20018000 别名执行 DMA。32 KiB CCM 只计入一次。勘误和采样孔径界限见确切的 G474 合同。

H743 的可选 D2 SRAM1 具有显式预算、时钟门控准入和启动时 DATA/BSS 初始化；NOINIT 仍由调用者拥有。DMA 在借用前重新检查 AXI/SRAM1 已初始化及其时钟状态。H743 ADC1 在 PA3/INP15 上提供 16-bit 原始单次采样，并采用与芯片修订版本匹配的 boost 配置和完整线性度校准；U575 ADC4 在满足外部 VDDA/ASV 准入条件后，提供 PC0/channel1 12-bit 单次采样。F103/GD303 在 4 MHz 下使用 PA0/channel0 12-bit 单次采样，并采用型号专属的预热与校准。这些格式和已声明的参考电压不代表经测量的模拟精度。它们确切选定的 PWM/EXTI 路由和引脚冲突仍由支持范围及相邻的 SoC 合同规定。

物理 Flash 暴露确切型号的完整空间，而不是产品分区。在要求提供的场景中，编写配置时指定的 supply_mv 是必需的软件假设，绝不是电压测量。nx_flash_geometry_t.program_flags 可设置 NX_FLASH_PROGRAM_REQUIRES_FRESH_ERASE：每个单元都须经过一次成功擦除，且此后未承受任何编程脉冲。全 FF 的读回结果不能证明隐藏的 ECC 历史；失败或中断的脉冲会消耗该单元的编程资格，直至下一次成功擦除。提供者不保留隐式历史位图。标志为零不免除提供者自身的编程规则，全 FF 的输入单元也不会触发脉冲。

每次物理脉冲前，先清除残留的错误／完成状态并观察清除结果，再要求在实际忙状态／写缓冲排空后出现新的完成状态。G474、U575 和 F407 的 EOP 锁存受 EOPIE 控制；GD470 的结束标志使用 ENDIE。在临时置位选定的脉冲中断位期间，它们的轮询所有者独占租用处于禁用、非活动状态的 FLASH IRQ；NVIC 始终不使能该向量。清理时撤除脉冲模式和使能位、锁定控制器，并在保留优先级的同时确认挂起状态已经清除。按各自的寄存器合同，旧式 F103/GD303 和 H743 的完成标志无条件锁存；不能据此推断它们也具有中断使能前置条件。H743 等待 BSY/QW/WBNE 排空，并要求 Cache off；U575 在 TZEN0/SWAP0 下等待 BSY/WDW 排空。

超时会阻止后续脉冲，但无法中止已经启动的脉冲。同 bank 的取指／IRQ 执行可能停顿；若控制器永久保持忙状态，就始终不能按“已完成”归还调用者存储。产品代码负责可写且擦除对齐的区域、电压、watchdog、执行位置和掉电恢复。通用 Flash 适配器不会虚构擦除历史。维护中的双 bank 存储算法在保存前擦除非活动 bank，分别写入不同的完整头部／载荷单元，并最后编程一个独立的提交单元；保存失败后，必须先重新打开／恢复，后续保存才能再次擦除该目标。

看门狗激活不可逆，启动命令之后的编程失败也不例外。准备失败会保留未成功撤回的 LSI 或 debug 租约，供 stop 重试。已编程的标称时长与物理最短、最长时长分别记录。GD303 与 F470 数据手册提供内部 RC 标称频率，没有受审的最小/最大包络：编程成功返回 success，边界为零；已启用状态查询报告不支持边界，同时保留 enabled、irreversible 和实际 debug 事实。U575 拒绝预分频 LSI，标称最小时长为 375 微秒，确保 RLR 至少为二。其他芯片的边界均保留各自数据手册的适用条件。

官方来源与版本配对¶

厂商文档建立芯片事实。库提供选定操作；示例可帮助识别执行顺序，但不建立通用平台合同。必须保留原始声明与许可证清单，锁定精确字节或 Git 提交，并将所选源码闭包纳入 Source SDK。官方 PDF URL 可能变化；后续下载必须匹配已记录摘要，或重新审查。

接入必须完善共享平台¶

每个新料号首先识别精确差异：寄存器代际、时钟/复位域、中断拓扑、DMA 路线、缓存可达性、封装引脚、勘误和不可逆效果。将这些事实写入 SoC 描述与受审路线。PCB 电气事实保留在 Board 数据，产品策略保留在外部仓库。一个编译宏不能代替这些审查。

只有硬件和所有权假设成立时才复用既有 provider。在两个具体接入证明语义与失败顺序相同之后，再抽取通用机制。优先使用编译期 helper，或带私有硬件端口的共享生产算法；避免仅转发的运行时层、系列名称条件链及重复生成常量的描述符。接受泛化前，必须测量代码、RAM 和栈。

新增旧式 GPIO 接入应反馈完善封装验证、原子置位/复位、先输出后模式的顺序及 remap 冲突处理。对应 UART 应反馈完善时钟舍入、活动设备拒绝、IRQ mask 恢复、错误/数据读取顺序和晚到中断隔离。F103 TIM2 为 16 位，与 F407 的 32 位 TIM2 不同：overflow 扩展必须有明确的最大 service 间隔，不能静默沿用更长的回绕假设。

本轮将反馈用于 timer 准入和清理：观察 timer gate 后重新检查保留的 slave、channel 和 trigger 状态；将仅 gate 租约与已准入 timer 分开；发出预分频更新时选择安静的 trigger 源。reset、trigger 恢复或 gate 撤回遭拒时，保留对应清理责任。看门狗审查同样反馈完善基于状态的安全观察、保守的混合 shadow 更新边界和可重试准备清理，不假设不同厂商拥有相同 RC 或 reload 语义。

必须审查库的实际行为，包括隐藏副作用：GD32F4 的组合函数 fwdgt_config 在编程前启动不可逆计数器，将其视为可逆准备是不成立的。同样，新增 M3 映像使用 soft-float，既有 M4F 映像使用 hard-float。资源、保留、候选与复现工具从唯一的 resolved CPU 合同取得 ABI，并继续验证 ELF flags、链接配置和输入字节；绝不根据制品推断 ABI 来使其通过。

官方 LL helper 是受审操作，不自动意味着执行有界。例如，F1 的 ATOMIC_* USART setter 可能包含 exclusive-store 重试循环。必要时在 provider 既有的保存/恢复 mask 区域中使用有界寄存器操作；安全的 LL 数据/标志操作仍保持私有。勘误审查必须考虑选定模式与芯片修订，包括 GD32F30x USART DMA 使能顺序、timer capture DMA/shadow 相互作用和 ADC 时钟约束。

验收顺序与后续接入¶

每项接入采用相同顺序：来源/许可证审查；失败的配置与真实 provider 测试；最小实现；测试通过；严格资源/模式拒绝；ARM 映像/资源检查；搬移后的 SDK 消费；clean-source 候选资格。保留真实 RED 失败与 GREEN 命令。GoogleTest/GoogleMock 仅用于主机，固件保持 C11 且默认无动态分配。资格合同规定证据要求，而不是本页的文件或检查数量。

凡选定模式可能到达的路径，均需执行部分启动失败、重试、逆序清理、实例隔离、接受后的取消、晚到 IRQ 和排空失败。排空失败保留 QUARANTINED 存储；超时从不撤销借用。只有所需引用脱离后，以 acquire 观察到 SETTLED，才结束 provider 访问。调用者仍需排空自己的 observer 和控制引用。

物理站点独立观察芯片/修订、Board/焊桥、时钟、映像、复位和 I/O 行为。性能结论要求相同映像、时钟、工作量和仪器。主机测试耗时与操作计数不等于 MCU cycles、IRQ latency、电气正确性或安全资格。没有设备连接时，依赖硬件的退出条件保持待执行。

后续主流候选包括 STM32F072RBT6、STM32F303RET6、STM32G071RBT6、STM32L476RGT6 和 GD32E230F8P6。这些是建议的接入目标，不是已支持料号。实施前需确认官方封装/存储事实、源码许可证、工具链/ABI、有限外设集合及独立来源的 Board。其他 GD32F4xx 和 STM32F4 料号同样需要明确的变体事实与路线；SDK 头或相同内核均不授予支持。

Bootloader 接管、运行时变频、deep STOP、通用跨域 DMA 与更广的 U575 异步 transport 仍遵循 SoC 完善台账中的独立退出条件。本轮不会因增加一个 MCU 系列或链接官方库而关闭这些任务。
