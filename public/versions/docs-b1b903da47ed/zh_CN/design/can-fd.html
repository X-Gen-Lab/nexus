CAN FD：固定物理 RAM 与明确的请求所有权¶

本合同用于装配和执行精确的 STM32G474RET6 FDCAN1 软件参考。iso-fd-normal 用于外部通信，iso-fd-loopback 用于内部静默环回；二者均使用 HSE 24 MHz，标称阶段 500 kbit/s、数据阶段 2 Mbit/s。这是分别选择的两个软件模式，均不能证明已安装收发器、实测时钟精度、外部 ACK、终端电阻或物理时序资格。HIL 仍为 not_executed。

选择独立的静态接口¶

FIG-16 描述共享的当前机制，不是 CAN 总线时序图。 在此选择中，接口面为 nx_can_fd_port_t，紧凑查找为 nx_factory_can_fd，运行期 provider 拥有 FDCAN1 及其固定消息 RAM。生成箭头、查找箭头和运行调用保留原有含义。查找既不读取硬件，也不启动发送。

以同一个软件 Board 和物理资源声明为基础，正常模式夹具和环回夹具分别选择模式。严格解析器校验精确速率、掩码、环容量和 IRQ 策略，再发布不可变 typed IR 与一份生成 bundle。控制器、共享 FDCAN 配置、消息 RAM、向量和焊盘的冲突声明都会被拒绝。Board 记录硅片 PA11/PA12 AF9 路线；实际 PCB 修订、晶振安装及外部 PHY 均未知。

准备、准入与物理完成证明¶

先初始化请求元数据，再用 nx_can_fd_tx_prepare 复制完整帧及选定单调时间域中的绝对 deadline。准备阶段不保留帧指针。唯一任务执行者提交时，在准入前校验完整值、物理队列索引、deadline 和存储互不重叠。被拒绝的调用不会借用请求，也不会写发送 RAM 或发出 add request。

ACCEPTED 借用整个请求，直到调用方以 acquire 观察 SETTLED。provider 把精确 DLC 和 payload 打包到选定物理元素，执行屏障后发布 TXBAR。软件队列不会改变硬件标识符仲裁顺序。已借用请求不能成为另一次调用的输出或唤醒存储。公共接口面／方法表身份、私有控制、peer 寄存器、共享 RAM 和 SCS/NVIC 控制也受输出别名保护。

FIG-06 给出共享所有权状态。 ACCEPTED 与 REJECTED 是准入结果。在此 provider 中，源撤离要求对应槽的 TXBAR 和 TXBRP 都已清零，随后重新观察 TXBTO 或 TXBCF。单独的空槽、已锁存中断或上一次陈旧完成都不能释放请求。硬件 add scan 期间，TXBRP 仍为零时 TXBAR 也可能保持置位。

TXBTO 证明成功发送，并报告实际 payload 字节数。即使 TXBCF 同时置位，真实发送也可以赢得取消竞争。没有 TXBTO 的 TXBCF 证明取消完成或一次失败的 DAR 尝试；显式取消报告 CANCELLED，普通发送尝试失败报告 IO，已传输字节为零。缺失外部 ACK 不会触发软件重发。总线重试与协议恢复策略属于外部产品。

取消、超时、bus-off 与 stop 都请求物理取消，绝不撤销已有借用。排空 deadline 失败会使请求保持 QUARANTINED、槽继续保留，并阻止 stop/recover/domain 释放。后续物理证明仍可能允许结束请求。执行者必须继续有界 service；唤醒提示不提供执行推进。

接收、恢复与关闭所有者¶

一次 IRQ 或显式 service 最多处理三个发送槽，以及每个接收 FIFO 最初的三个元素。复制后的接收值保留 ESI，表示观测到的发送者状态。FD DLC15 表示 64 B；经典 DLC9..15 规范为 8 B，并附显式标志。事件采集时间不是 SOF，已禁用的硬件时间戳也不会被解释为物理总线时间。

调用方定容的事件环不会覆盖旧记录。软件丢失计数与硬件丢失下界分开保留；待发布丢失边界排在旧记录之后、新保留帧之前。bus-off、错误计数和 last-error 状态独立锁存，不依赖事件环是否已满。只有实际启用的 line0 对唤醒绑定施加系统调用优先级下限；已预留但禁用的 line1 不会成为另一个内核发布者。被拒绝的绑定保留原 sink。

显式恢复要求所有发送借用和通知发布者都已排空。它重新进入初始化，不重发、不复位共享域，也不重新分配消息 RAM 租约。不可变模式在恢复后仍保持 normal 或 loopback。bus-off 恢复时序依赖真实控制器和总线推进；配置返回不代表已测量所需总线空闲时间。

stop 先关闭准入，排空槽，禁用外设源并等待 line0 退出，然后才进入已应答的 INIT。最终 PSR/ECR 快照先于 CCE，因为 CCE 可能破坏硬件完成事实。控制器 stop 成功才结束其请求／环／唤醒借用；任何失败都保留未完成租约以便重试。之后 Platform 释放 domain，并恢复外层焊盘／时钟门／系统所有权。存储复用前，外部 adapter 观察者仍须单独退出。

来源与软件资格¶

权威 API 为 can_fd.h，并遵循共享的请求合同。私有 provider复用固定版本官方 FDCAN 定义，直接访问 volatile MMIO；本实现不链接 HAL 驱动 C、HAL_GetTick、HAL handle 或 MSP 回调。G4 来源锁保留精确选定头文件、配套 CMSIS 身份及原始许可。

已审硬件参考为 RM0440 Rev9、DS12288 Rev6 和 ES0430 Rev9。RM0440 定义固定消息 RAM、队列及取消证明，包括失败的 DAR 尝试。TEST.RX 位是只读引脚状态：配置读回仅检查拥有的 LBCK/TX 控制，必须允许 RX 为隐性电平。EFBI0 和不混用 dedicated/FIFO 发送规避了选定 FDCAN 勘误条件，不能据此宣称所有硅片限制均已验证。

公共合同测试、真实 provider 寄存器／事件测试及两个生成 factory 选择执行实际 C 实现。GoogleMock 观察外部 MMIO/IRQ 效果。模型覆盖外部 ACK／无 ACK、取消竞争、固定 RAM、只读状态、输入输出隔离及失败停止后的保留。生成测试使用同一个 RCC/TIM2 模型执行真实系统启动，再走正常 TOML/factory 路径，不手工设置 Platform 就绪状态。

实际执行与来源身份以交付证据为准。主机模型及任何单独记录的 ARM 链接都不能建立物理 ACK、错误注入、bus-off 恢复时间、晶振范围、吞吐、IRQ 延迟或 WCET 资格。正常模式在取得物理部署资格前，仍需已检查的收发器电路、安全电气连接及独立 HIL 证据。
