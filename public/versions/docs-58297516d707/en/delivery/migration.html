External-project migration¶

This iteration retains the overall factory and polymorphic-interface model while rebuilding configuration and static instance generation. Compared with the original factory, instances have exact independent state, shared read-only operation tables and explicit lifecycle. Compared with the previous direct typed binding, callers can now obtain interfaces by typed IDs and replace providers. First pin the new platform source version, then update callers and tests completely. Persistent formats and recovery for previously deployed products need separate contracts.

External projects supply explicit NEXUS_ASSEMBLY_FILE, link Nexus::Platform, and use nexus_add_firmware() for startup/system/linker/resource gates. Applications include only public Nexus headers and generated nexus_factory.h/nexus_bindings.h; they do not inspect private provider storage or SDK register types. SPI/I2C controllers and child-device endpoints are obtained separately; a controller factory must not return an alias of the first child. Invalid IDs return NULL. Factory lookup neither initializes nor allocates memory.

Maintained assemblies use TOML schema 2. Schema-1 JSON reading is only for explicit migration and tool-derived input, not a parallel authored copy of TOML configuration. Cold startup still explicitly calls nx_platform_start() and shutdown calls nx_platform_stop(). BUSY/QUARANTINED retain state and all borrowed storage. Faces may be retained before start. Successful stop preserves face identity while the provider rejects operations.

Request migration must update ownership too: prepare does not mean accepted, and cancel does not mean settled. After acceptance, retain request and payload until acquire-observed SETTLED permits reuse. Shared-owner control handles retain stable slot+epoch; an old request pointer cannot cancel a new operation. Producers submit and wait; the sole executor continuously services requests. Stop closes admission before drain/join, and notification storage cannot be reclaimed before publishers exit.

OS storage uses real per-object stack/TCB/depth. Task-entry return does not mean underlying deletion; storage is reclaimed only after successful join. Timeout retains handle, stack and TCB. Persistent instances own external workspace. After mutating-I/O failure, reopen to confirm generation; an error cannot prove that commit did not occur.

Migration acceptance proceeds through strict-input negative paths, Native/model behavior, independent source-SDK consumption, six base ARM ELFs, exact budgets, offline double-build and candidate sealing; HIL follows on the actual PCB/wiring. External nexus-examples is an independent example repository. Platform CI does not add product applications to default platform targets.
