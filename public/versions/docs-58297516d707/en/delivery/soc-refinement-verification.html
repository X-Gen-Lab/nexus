Interpreting the ledger¶

implemented records a mechanism in source. contract_implemented and documentation_updated record narrower contract/documentation work. qualification_record_authority delegates acceptance to the actual external record for the exact source/configuration/artifact tuple; it is not a source file’s self-reported pass. final_source_pending means that execution is still required for the completed source scope.

selected_profiles_observed records actual static cost measurements only for the profiles named above and in the index. tooling_software_validated qualifies the HIL software contracts; the corresponding physical test remains unexecuted. The partial-reference implementation states preserve their limited GPIO/UART scope even after host, ARM or installed-SDK checks pass.

SOC-05 records versioned datasheet, manual and errata provenance. Actual silicon revision and full per-mode errata applicability remain unqualified. SOC-23 and SOC-27 require observed actual ELF costs; an observer’s unit tests alone do not complete measurement. A changed capacity, backend, Board route or memory layout must be reported as a distinct selection rather than a like-for-like saving.

SOC-28, SOC-30 and SOC-31 contain only the exact H743/U575 GPIO/UART/time reference subset. SOC-29 and SOC-32–36 retain explicit missing features. Their original exit conditions remain unchanged. A rejected unsupported mode is not a completed mode implementation. SOC-37–55 contain executable software preparation, admission, capture and validation tools; every physical exit remains open until real station records are captured and validated.

No result here establishes MCU cycles, interrupt latency, Flash power-loss behavior, cache/DMA coherence, TrustZone isolation, product safety, certification or a product release. Exact support remains defined by the support matrix and SoC contracts.
