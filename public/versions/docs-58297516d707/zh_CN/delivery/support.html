Linux/POSIX 行为模型、实际线程与持久化文件故障模型

裸机和锁定 FreeRTOS 均为显式选择的薄适配。启动只建立平台时钟／接口，不创建 scheduler、产品任务或工作流。FreeRTOS POSIX host 运行验证软件生命周期，不能 替代对应 MCU 的 IRQ ceiling、FPU context 与 stack high-water 实板验证。

H743 使用官方 Cortex-M7 启动与有界 LDO 电源入口，在 ACTVOSRDY 前禁止 RAM 写入；从 HSI64、Cache off 的可信冷状态建立所选固定时钟与 Cache 配置。Cache 关闭位本身不能证明外来 dirty 数据已经清理；要求可信复位或此前成功完成自有 clean/disable。U575 默认 Platform 使用官方 Cortex-M33 启动并维护 TZEN=0 单地址状态；独立 TZEN=1 参考有自己的入口和安全归属 owner。启动后读取 option register 不能使不匹配的启动变成合法状态。两者都不修改 option bytes，不自动 接管 bootloader、DMA 或既有 clock/IRQ owner。原始 CMSIS Device H7/U5 源码、 许可和版本固定在 source lock。 精确入口见 H743 与 U575。

ThreadX 是额外显式后端，锁定官方 Eclipse ThreadX 6.5.2.202603 release。当前 配置维护三块 F407/F470 Board 的 Cortex-M4 GNU port，以及 Native Linux GNU。 独立 CPU runtime 维护 M4 integer、M4F hard/softfp，BASEPRI 或 PRIMASK 政策； 其他 Cortex-M ThreadX port 明确拒绝。生产 graph、真实 Linux 内核 task/queue/join 与三板 ARM 链接分别验证，Linux 自身 pthread 栈与内部 host 分配不是 MCU 成本。 ThreadX 不实现本项目 FreeRTOS 的 MPU、split-security 或 tickless 模式。详见 ThreadX 接入。平台启动不进入任何内核，产品显式进入内核； 仍运行的 scheduler 不允许普通 I/O shutdown 关闭其 clock/Tick。

CPU 软件层另支持 M0／M0+／M3／M4／M7／M23／M33／M55／M85，统一严格事实 解析器选择 Core/Arch、原子操作和裸机/FreeRTOS runtime。M0/M0+ RMW 使用 bounded saved-PRIMASK；可选 cache/MPU/SAU 有真实 CPU 算法，FPU/MVE 与安全 状态决定精确 kernel port 和 ABI。CPU-only runtime 自身不生成 SoC/Board/factory； 上述 H743/U575 纵切片分别拥有独立装配与验收。编译、寄存器模型与真实 FP/MVE/cache/MPU/安全世界验收分别记录； cache.h 的范围维护与仅 M7 维护的冷 Cache 启停分别提供；CMSE 范围权限观察 本身不建立用户内存 pin、复制或 transport。 可选 restricted MPU task 和 split Secure/NonSecure runtime 已有独立软件实现； 窄 delay/tick SVC、Secure context lease 与调用者静态存储分别验证。默认仍为 privileged single-world；MPU+split 明确拒绝，未新增实板 HIL。范围和配置例子见 Cortex-M 软件支持 与 Arch 契约。

已审查的软件 Board 配置支持 STM32F407 I2C1/I2C2 与 GD32F470 I2C0/I2C1 的 IRQ/DMA 装配及 typed factory；双控制器夹具已有独立实例隔离与真实 SDK 链接证据。 参考 Board 只开放明确声明的 binding；其他硅片路线与实际接线需单独审查。详见 多控制器所有权。

SPI DMA 要求非空、不重叠的 TX／RX 实际访问跨度；固定地址方向只访问调用者的一字节。 不分配 scratch 或隐式复制池。实际 memory domain 与读写权限由 provider 再次校验；STM CCM、GD TCM 均不能作为 DMA 缓冲。DMA TC 表示内存传输事实，UART TC／SPI idle 表示线上事实；两者排空证明 都满足后才发布 SETTLED。取消、超时或 EN 拒绝关闭保留借用，进入 QUARANTINED。

UART 的 irq-blocks 保留独立 IRQ 接收实现；rx-dma-idle 使用有限 DMA 与 IDLE， rx-dma-continuous 使用硬件双缓冲，另有显式 dma-duplex 和 dma-duplex-continuous。块由调用者提供，消费者 acquire 后保持不可变，直到匹配 epoch 的 release。连续模式必须预留两个硬件目标及替换块；替换地址读回、目标银行 和新错误检查成立后才能发布旧块。没有替换块就停止，不覆写消费者借用。 仅接收模式使用独立只读方法表，不保留 TX DMA 方法与对应链接代码；当前共享 接收状态布局仍包含 TX DMA 基类字段，不能宣称冷态字段开销为零。RTS/CTS 并不代替 容量和排空合同；RS485 的 DE 引脚、极性及 setup/hold 时间由外部工程明确提供， 到达真实 UART TC 后才开始 hold 并撤销 DE。详见 UART DMA 与 RS485。

ADC 的 trigger-dma 使用普通有限 DMA；每块停止触发、转换与内存写入，再发布完整块。 调用者必须显式 service，完成上电稳定／GD 校准后重新触发下一块。无空闲 loan 时 保持暂停，不覆写、不伪造暂停期间的精确丢样数。该模式有块间间隙，不承诺连续 无间隙采样。trigger-dma-continuous 则显式选择硬件双缓冲及预投递块，地址替换 成功后发布完整块；至少需要三个调用者 slot。频率需满足精确 timer divider 和 整段 scan 转换时间；GD 连续模式显式选择 SDK 对应的 sample-time code，有限模式 保持原有 15-cycle sample。可选 observer 的时间戳是软件发布观测时间，不是采样 孔径时间。单个锁存 TC/CT 事实无法计算未观测的多轮丢样。stop 在持有 loan 时返回 BUSY。

I2C 中断及 DMA 共享经过两家 SDK 布局与位定义检查的 V1 寄存器算法，MCU 热路径 直接访问寄存器。DMA TC 不代表线上完成；最后字节、BTF、STOP/MSL、DMA EN 和 IRQ 发布者必须排空后才 SETTLED。bus-clear 独立要求静止外设、独占开漏 GPIO 和 有界等待，最多九个完成的恢复脉冲；STOP 或释放失败保留 lease，可继续清理。 平台没有为未经审查的 Board 自动切换引脚。详见 I2C 总线恢复。

这些是 SoC 实现能力。参考 Board 默认 binding、软件测试夹具路线、现场测量结果 各自独立。STM32 默认参考 Board 未声明可资格化的 SPI CS，资源矩阵只测 empty/GPIO/UART；软件 fixture 的 SPI 不能继承为参考板 SPI 支持。GD32 默认 Board 的 SPI4 PF6/7/8/9 有公开来源，外接 NOR 具体料号仍未知。

明确边界¶

连续模式不能承诺任意 IRQ 延迟与消费者速度下无丢失。I2C 超出 256-byte 的 read、 动态 clock、deep sleep/STOP、安全启动／升级及上述未维护模式明确不提供。 FreeRTOS 可选 lowpower_port="timebase" 只在固定 F407/GD470 profile 使用浅 Sleep； 要求 SysTick、tickless、single privileged、无 MPU。默认 custom 不新增 sleep 机制；CPU-only runtime 缺少 SoC timebase 时拒绝该选择。实际相位、clock 连续性、 wake latency 与功耗保持物理未执行，见浅睡眠。 Unsupported 配置明确拒绝，不通过成功 stub 声称支持。

Flash pulse 不能被 deadline 撤销；BUSY 未清不能释放责任。产品负责 Flash 执行 停顿、电压、watchdog 窗口、掉电、认证、布局与持久化格式迁移。公共通用 storage 的 CRC/commit 机制不等于安全升级协议。

GD32 Flash 的重新上锁读回失败会保留静态 provider 并拒绝继续操作，需要受控 复位；普通 stop 不能恢复此状态。tests/google/gd32_flash_fault_test.cpp 专项模型 验证故障后拒绝读取／写入／重新取得控制器，不构成实板资格。 生命周期与扫描诊断的解释见安全审查。

硬件未接入，全部 MCU 目标的 clock、reset、GPIO safe output、UART TC/abort/RX、SPI/I2C 电气、Flash 掉电、watchdog reset、EXTI 波形、PWM 与 ADC 精度均未执行。当前 支持声明不能替代物理 HIL 或产品 release promotion。
