测量资源并准备硬件验收¶

使用本指南区分链接后的软件成本与物理 MCU 行为。平台提供测量与 HIL 工具；产品选择工作负载、电气限制、安全输出和发行策略。真实设备执行已审查范围之前，任何 Board 都没有实板资格。

先准备固定源码与递归依赖，再为精确选择的装配准备锁定工具链。

测量精确镜像¶

记录干净源码、装配／resolved 摘要、依赖、编译器和标志。在变更前后构建同一负载。核对实际 ELF／BIN／map 与资源报告，不使用对象数量估算。分别记录 Flash LOAD、Flash 占用范围、各物理 RAM 预留、MSP、任务栈／TCB、队列和 I/O 缓冲区。栈容量不是实测栈高水位。

构建合同维护资源检查。使用维护中的 tools/measurement/ 门禁；执行预算说明范围。速度结论必须包含单位、时钟、输入规模、负载、采样方法和不确定度。DWT 32 位快照需要有界回绕间隔；主机到达时间戳不能证明 MCU cycles 或 IRQ 延迟。

FIG-09 是精确 H743 参考。启用缓存的 TX 要求拥有完整 32 字节缓存行，并可达 AXI SRAM；DMA 完成、线上完成和借用结束分别判断。它不授权 RX DMA 或 TCM 放置。

在不操作设备的情况下准备¶

先配置并构建所选维护装配。以下仓库根目录命令使用梁山派裸机参考的实际输出：

python tools/dev/dev.py configure --preset gd32-liangshan-baremetal
python tools/dev/dev.py build --preset gd32-liangshan-baremetal --parallel 4
python tools/hil/prepare.py     --fixture tools/hil/fixtures/gd32f470_liangshan.json     --resolved build/gd32-liangshan-baremetal/generated/resolved.json     --report /tmp/nexus-hil-preparation.json
python tools/hil/measure.py plan     --fixture tools/hil/fixtures/gd32f470_liangshan.json     --resolved build/gd32-liangshan-baremetal/generated/resolved.json     --report /tmp/nexus-hil-measurement-plan.json

锁定 ARM 编译器必须位于 PATH。检查报告中的型号、引脚、选择模式和 not_executed 项。准备流程不打开串口、不刷写，也不操作电源设备。数值限制和仪器在审查前保持未绑定。G474／H743／U575 软件参考夹具会明确拒绝物理工位准入；未来实板夹具需要独立审查的工具集成。

只执行真实且经过审查的工位¶

将实际观察的 PCB／型号／UID、探针、稳定串口路径、接线和供电绑定到精确 ELF、resolved 配置与资源报告。锁定采集工具、操作配方、仪器和数值上下限。遵守维护中的 HIL 采集合同：识别、刷写、验证、复位、串口和清理。失败保留原始日志；清理失败继续隔离保留工位，并要求实物检查。

采集完成只表示执行过，尚未取得资格。分别验证实际基本功能检查、测量和 OS 记录。不得合成物理跟踪记录或将软件模型当作 HIL。资格只覆盖已记录观察，不证明未观察的 WCET、电气安全或产品发行。
