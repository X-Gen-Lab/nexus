Nexus documentation content and diagram standards¶

These standards govern new/changed platform documentation so readers understand tasks, conditions, actions and results for use, integration, maintenance or acceptance. Review existing pages in batches using the implementation ledger. These standards do not establish completion of content migration, diagrams, automation, translation or publication.

Must/must not express requirements; should/should not express defaults with justified exceptions; may expresses permitted choices. Normative rules must identify actors, conditions, actions and checkable outcomes. Codex owns responsibility; independent agents review content/diagrams without invented human accounts.

2. 术语、单位和约束¶

Introduce bilingual terms where useful, then use one term per concept. C symbols, configuration keys, error codes, fields and machine identity values in CSV/JSON stay unchanged, including states, IDs, digests, paths, versions and configuration values. Translation must not overwrite authoritative CSV/JSON bytes. Human-facing tasks, explanations and exit conditions may have translations or derived displays while preserving original authority and evidence identities. Distinguish:

Term

Meaning in these docs

factory

Typed lookup returning existing static interfaces of this assembly.

face

Public read-only interface containing ops and instance context.

provider

Concrete implementation and private state.

controller/endpoint

Controller identity versus logical/external endpoint identity.

owner/executor

Resource/lifecycle responsibility versus actual execution/progression responsibility.

request/buffer

Request metadata versus borrowed data storage.

DMA complete

DMA phase complete; peripheral/reference drain remains.

wire complete

Peripheral wire transfer complete; other final conditions remain.

SETTLED

The provider drains required references, then release-publishes SETTLED as its final request access; the caller observes with acquire semantics.

QUARANTINED

Not safely ended; borrowing/recovery responsibility remains.

State capacity/measurement units: B/KiB, Hz/MHz, cycles and µs/ms. Record Flash LOAD, Flash footprint, reserved RAM and measured stack high-water separately. Define alignment, length granularity, inclusive limits, overflow, deadline domains and maximum configurations. Do not mix theoretical bounds, estimates and measurements.

Valid rule: after ACCEPTED, callers retain requests/buffers until acquire-observed SETTLED; reuse of adapter/observer storage also requires drained references. Invalid wording: “mind the lifecycle”, which omits actors, final conditions and failure responsibility.

4. 示例与命令¶

Complete examples must come from maintained fixtures or pinned external examples and be associated with actual consumer validation. Prefer literalinclude and explain fragments. Illustrations are not complete tutorials. Ordinary builds do not automatically flash devices, execute arbitrary Markdown commands or fetch remote latest.

Every command states working directory, tools/connections, inputs, expected results, success checks and cleanup. Firmware C examples retain C11, 80 columns, four spaces, attached braces, type-side pointers and backslash Doxygen. Tool/test examples retain language conventions, including Python and C++17 GoogleTest/GoogleMock. Docs do not redefine code style.

Async examples must explain rejection, accepted borrowing, progression, waits, cancel, drain and final resources. Timeout/cancel does not revoke borrows; failed stops retain QUARANTINED storage. Wakeups are hints, and infinite waits cannot conceal progression conditions. Tasks, private partitions and recovery stay external.

Runtime diagrams must show that after factory lookup, ordinary I/O calls faces/providers directly; Arch is compile-target-selected; applications own scheduling/progression. Static structure does not determine initialization order or represent every runtime call.

REJECTED/ACCEPTED are admission outcomes, not invented nx_request_state_t enum states. Publish SETTLED only after required reference drain; cancel/deadlines never point directly to reclaimed storage. Ending QUARANTINED needs actual recovery/drain proof without implying every provider has recovery APIs. Sequence diagrams must include failure branches or link separate failure diagrams, with Task/IRQ/DMA/security domains marked.

Diagrams do not replace preconditions/contracts. Conflicts suspend affected delivery claims until sources are corrected; changing diagrams/tutorials alone must not hide contract conflicts.

7. 图源、视觉和离线交付¶

Initially use editable Graphviz DOT and local SVG pairs. Sphinx may later use its graphviz extension; new chains/locks follow DOC-25/33. Existing Mermaid is migration input, not another authority for the same diagram. Specialized sequence tools need independently reviewed closures justified by real demand.

Every diagram satisfies:

  • Reviewable source and stable names/IDs; regenerate after source changes.

  • Dark text/clear boundaries; colors are not sole meaning and grayscale remains distinguishable.

  • Short specific labels with detailed prose; split dense diagrams rather than shrinking unreadably.

  • Complete Chinese/English/C symbols without missing glyphs, overlap, clipping or blurry screenshots.

  • Alt text/captions; narrow screens allow zoom/standalone SVG rather than forcing tiny text.

  • SVG defaults exclude scripts, animation, foreignObject, external href/resources and DOCTYPE.

  • Offline packages include diagrams/sources; loading, font notes and checks need no CDN.

  • Graphviz/actual fonts belong to tool closure; missing/different tools never claim validation.

Successful SVG parsing/rendering does not prove architecture correctness. Independent review must check every call/dependency, state and failure edge. Actual display checks desktop, narrow/zoom and print; unexecuted checks remain unverified.
