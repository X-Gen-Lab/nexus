解释台账¶

implemented 记录源码中的机制。contract_implemented 和 documentation_updated 记录范围更窄的契约／文档工作。qualification_record_authority 将验收交给精确 source／configuration／artifact tuple 的外部实际记录，不是源码文件自报 passed。final_source_pending 表示完成的源码范围仍需执行。

selected_profiles_observed 只记录以上及索引命名 profile 的真实静态成本。tooling_software_validated 资格化 HIL 软件契约，相应物理测试仍未执行。部分参考实现即使通过主机、ARM 或安装 SDK 检查，也保留有限 GPIO／UART 范围。

SOC-05 记录版本化 datasheet、manual、errata 来源，实际硅片修订及每个模式完整 errata 适用性仍未资格化。SOC-23／SOC-27 要求实际 ELF 成本观察，observer 单元测试不能完成测量。容量、后端、Board route 或内存布局变化应作为不同选择报告，不能描述为同配置节省。

SOC-28、SOC-30、SOC-31 仅包含精确 H743／U575 GPIO／UART／time 参考子集。SOC-29、SOC-32–36 保留明确缺失功能，原始退出条件不变。拒绝不支持模式不是该模式实现完成。SOC-37–55 包含可执行的软件准备、准入、采集、校验工具；真实 station 记录采集并校验前，所有物理退出保持开放。

这里没有结果建立 MCU cycles、中断延迟、Flash 掉电、cache／DMA 一致性、TrustZone 隔离、产品安全、认证或产品发布。精确支持由支持矩阵及 SoC 合同定义。
