# STM32G474RE HSE24 software reference

This package describes a source-reviewed STM32G474RET6 reference using the
NUCLEO-G474RE / MB1367 C04/C05 documentation. The name identifies a software
profile. Physical PCB revision, fitting, bridges and all HIL remain unknown.

The fixed clock profile is `hse24-pll170`: X3 24 MHz, PLLM6/N85/R2, HCLK and
APB1/APB2 170 MHz. [UM2505 Rev7 section7.5.1 page22](https://www.st.com/resource/en/user_manual/um2505-stm32g4-nucleo64-boards-mb1367-stmicroelectronics.pdf)
specifies X3 as the default, with SB25/SB26 on, SB24/SB28/SB27 off and C56/C59
6.8 pF. The alternate 8 MHz ST-LINK MCO bridge profile is unsupported here.

`led0` authorizes PA5 / LD2, active high with inactive zero and SB6 on.
`uart1` selects LPUART1 PA2 TX / PA3 RX, AF12. The reviewed VCP choice requires
SB17/SB23 on and SB18/SB22/SB13/SB19 off. These facts describe the manual, not
an inspected Board. Products must confirm their PCB and electrical path before
commissioning.

Only GPIOA PA5 and `irq-bytes` LPUART1 are configured. UART reception uses an
explicit generated byte ring and priority5. No event/block RX, DMA, Flash
programming, FDCAN or other peripheral mode is advertised. TIM2 and its IRQ28
are reserved for the platform's independent monotonic clock; LPUART1 uses IRQ91.
The exact CPU/Flash/RAM contracts are in the [G474 design](../../docs/design/stm32g474.md).

Generated cold assembly leases only selected GPIO fields. It snapshots those
fields after acquiring the observed GPIOA gate and before changing pin modes.
All providers join before the fields are restored and only newly acquired gates
are withdrawn, with readback. Failed restoration retains the platform lifecycle
for explicit cleanup retry; no factory lookup acquires or initializes hardware.
